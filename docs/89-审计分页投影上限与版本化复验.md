## 变更前观察与验证设计

只读检查实际原生 PostgreSQL 测试库，原分页计划为 Limit → Sort → Seq Scan；详情大小判断和 JSON 转文本投影位于排序、分页之下。跳过的记录或排序候选可能先计算详情，最终最多返回 51 条不能证明计算范围也最多 51 条。现有 16 KiB 脱敏投影保护返回体，尚未保护分页前的转换工作量。

先在真实 PostgreSQL 中使用临时函数计数实际投影次数，覆盖首页、后续页、末页及越界空页。临时函数只包裹真实 octet_length，使用本连接的自定义配置记录次数；测试结束删除函数，连接、事件及 monkeypatch 均清理。不能用时间断言、放宽超时或更改生产统计来使测试通过。

## 修复约束

- 先按相同筛选、created_at/id 倒序、50 条页宽和 51 条前瞻选出本页，使用 PostgreSQL MATERIALIZED CTE 明确计算边界，再对这至多 51 条执行详情大小检查和脱敏投影。
- SQL 中继续执行 16 KiB 上限，不将超大详情取回 Python。空页不执行详情投影；不得改变完整计数、has_more、字段、角色、筛选、当前名称解析或审计保留规则。
- 保留 REPEATABLE READ READ ONLY、一致快照、5 秒语句与 1 秒锁预算；不加锁、不自动重试、不增加数据库迁移或 HTTP 端点。
