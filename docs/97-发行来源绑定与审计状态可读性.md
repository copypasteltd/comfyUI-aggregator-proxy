# 97 · 发行来源绑定与审计状态可读性

日期：2026-10-26（Asia/Taipei）。修复第 96 增量已记录的 **REL-96-01** 与 **UI-96-01**，关联完整待办 50、74、76。本文先记录实现约束，运行结果随后以新的版本化证据追加；第 96 原报告与归档保持不变。

## 1. 发行来源约束

新构建必须在本项目 Git checkout 中执行，把实际 HEAD 的完整 40 位 commit 写入已有 `release-manifest.source_revision`。构建前与结束前核对来源：应用及 CI 输入须已提交，候选所选输入必须在 HEAD 中以普通文件存在，实际文件字节须匹配提交中的 Git blob；构建期间源文件集合、摘要与 HEAD 不得变化。未提交、未跟踪、被 Git 忽略却参与打包、外部链接或来源未知时拒绝出包，不以 null 或调用者自报版本继续。

文档与证据可以在构建后追加；`app/.local` 的固定工具、已核对 Provider 和编译产物沿用各自摘要与校验，不能以 commit 字段替代这些验证。保持显式准备 Admin 生产构建的使用顺序。历史 v1 归档的 null 字段继续被独立安装器接受，新构建规则不破坏旧候选读取。

本项对应 DEV-01/02/05/19/25/26/30/31；不改变公开 API、运行契约、数据库 head、Workflow 批准或安装提权规则。不自动安装 SCM、不改变生产配置。

## 2. 审计界面约束

审计保留卡片继续复用原始 04 · 青柠 CSS、字体和现有主题令牌，定制只写在独立页面适配中。标题、状态与正文在 1360、390、320px 都须完整可读；检查未启用、最长合法保留天数、读取失败与旧快照场景，不用省略号隐藏策略状态。原冻结保留接口与权限逻辑不变。

先保留修复前真实 DOM 的布局证据，再用实际构建的页面验证文本边界、页面溢出、键盘焦点及 reduced-motion；明确 UI 夹具与真实 API 检查的层级。更新截图、MP4/GIF 和双语入口。所有本次浏览器 context/browser 均在 finally 关闭，临时数据与进程只清理本次拥有的资源。

New builds must embed the actual committed source revision, verify selected file bytes against Git blobs and reject changes during packaging. Legacy manifests with a null revision remain readable.
