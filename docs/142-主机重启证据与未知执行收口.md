## 证据及授权边界

ComfyUI 队列/历史为空、单独重启 Worker、客户端超时或租约到期，都不能证明旧执行已停止。只有本地 Windows 节点在重启前持久保存检查点，并在之后观察到同一主机的开机运行计数严格下降，且 ComfyUI 的成功查询确认原关联不存在，才允许关闭原尝试。API 仍需校验节点、原 boot/fence、关联、prompt、物理 GPU、冻结渠道、检查点摘要及一次性资源记账。

Windows 的 [GetTickCount64](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-gettickcount64) 返回系统启动后经过的毫秒，不受系统时间调整影响。本协议要求当前值至少比持久检查点小 1,000 毫秒；这为实际计数精度留出余量。计数增加、相等、证据缺失或无法取得时均拒绝停止确认。若重启前检查点过早、重启后的计数尚不能证明下降，则保持待核对，不推测重启。

检查点仅由已认证 Worker 对其当前受控执行提交。原生节点先核验 local 渠道的 TCP 连接两端属于同一主机，并绑定实际 GPU UUID；HTTP-only 渠道不能使用主机重启证明。Windows 安装身份仅传摘要，不传注册表原值、路径或凭证。该功能不执行主机重启，也不增加 Admin/业务 Key 的强制关闭能力；重启仍属于独立的设备操作授权。

## 协议与持久记录

沿用 `/internal/v1/reconciliations`，新增可选的 `host_checkpoint` 和 `host_restart`。注册回执通过 `recovery_protocols` 显式声明支持 `windows-host-uptime-reset-v1`；未声明时新 Worker 使用旧协议，不向旧控制面发送新字段。

| 阶段 | Worker 行为 | 控制面行为 |
| --- | --- | --- |
| 建立检查点 | 成功查得原关联 absent，原生核验本机连接，持久保存安装身份摘要、GPU、渠道摘要、随机标识和 uptime | 校验原尝试；保存不可静默覆盖的检查点及绑定摘要，返回检查点摘要；继续保留占用 |
| 原启动内再次核对 | 重用原检查点，不更新基准计数；普通 Worker 重启不算主机重启 | 相同请求幂等返回；不同检查点拒绝，不凭 absent 释放 GPU |
| 主机重启后 | 原检查点仍在；同一安装/物理 GPU，当前 uptime 严格下降，成功查询原关联 absent | 校验全部身份及摘要后终结旧尝试、一次性释放生成/未完成预留，保留日用量和审计 |
| 找到原 prompt / 稳定产物 | 使用既有 found / local_outputs 恢复原尝试 | 增加 fencing 并恢复原执行；清除过时检查点，不提交第二次生成 |

PostgreSQL 在 attempts 增加独立的 `recovery_checkpoint`；不把检查点伪装为生成完成或稳定产物。SQLite journal 增加专用检查点记录；领取身份变化时旧检查点失效。检查点与停止确认都必须可重放，丢失响应先回读/重放原意图，不生成新检查点绕过冲突。

停止确认将任务置为 `failed`，错误码为 `execution_host_restarted`；若已有取消意图，则置为 `cancelled`。不自动排入重试，也不计作缺模型、OOM 或坏输出。后续业务调用或验证使用新的持久意图；保留原失败及全部源 Workflow。旧 lease/旧回执、其他节点或已替代尝试不能改变新占用。

## 必须验证与发布顺序

本增量必须验证：检查点跨进程持久化、不可覆盖、原尝试绑定；同次启动/修改时钟不释放；不同主机/GPU/渠道、错误摘要、旧 fence、已恢复尝试、HTTP-only 和查询失败拒绝；真实 PostgreSQL 下并发重放只释放一次；取消语义、日用量和冻结输入保持；新旧控制面协商及旧协议恢复继续可用。

先完成原生组件和事务验证，再备份并向前迁移控制面，最后排空升级 3080 Worker；保留 ComfyUI、原 journal、原任务和检查点。线上先证明同次启动继续拒绝停止确认，才讨论设备重启。实际重启、自动收口和后续五个三维/174 个 4090 型号的调用验证分别留证；全部日上限继续不限，所有开发继续使用原生进程。
