# 画布原提交只读核对

当首次生成请求已经写入数据库、但浏览器没有拿到响应时，画布保留原请求与幂等键。恢复操作通过 `POST /v1/jobs/lookup` 查询原提交，找到后恢复原任务 ID。该接口不创建、重放、重新上传、重新计费或调度任务。POST 仅用于避免将原始请求放进 URL；数据库事务使用 `REPEATABLE READ READ ONLY`。

接口复用 `JobCreate` 请求体，以原业务 Key、原 `Idempotency-Key` 和首次提交使用的可选 `X-Expected-Release-Digest` 调用，只要求 `jobs:read`。原租户、项目、逻辑 Key 必须匹配。先比较规范化后的完整原请求（包含字段是否存在、素材 ID 和 `client_request_id`），再用任务保存的 `execution.asset_hashes` 检查原幂等记录和任务指纹。不会读取当前模型发布配置，也不要求原素材仍可上传或可下载。旧任务若缺少可验证的冻结信息，返回 `submission_unverifiable`，不猜测。

成功响应为 `generation.submission_lookup`：`found` 携带原任务；`not_observed` 携带 `job: null`。后者只说明本次快照未观察到已提交映射，不能证明从未执行，也不能允许补发。原请求或发布摘要不匹配返回 `submission_mismatch`。响应不回显提示词或输入；产物列表仍要求 `artifacts:read`。现有鉴权、Key 撤销、CIDR 与 RPM 限制保持生效。

服务在 `/v1/access-policy` 响应头公开 `X-Studio-Submission-Lookup: 1` 并通过任意源 CORS 暴露。旧服务没有该能力时，画布保留未知记录并明确提示，不回退到生成 POST。只有从未发送的 `prepared` 本机任务可以首次提交；未知、发送中或从备份恢复且无 ID 的任务必须明确选择只读核对。导入本身不触发查询。

本扩展兼容既有 0.4.0 业务协议，不增加数据库迁移，不改变 Windows Worker，不引入新的限额、超时、重试或并发预算。机器可读契约见 [studio-submission-lookup.json](contracts/studio-submission-lookup.json)。本轮原生数据库、浏览器、线上部署及回归结果将追加在本页；实现完成不等于全系统验收完成。
