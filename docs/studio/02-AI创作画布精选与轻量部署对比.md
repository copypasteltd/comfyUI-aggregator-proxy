# AI 创作画布精选与轻量部署对比

调研日期：**2026-10-29（Asia/Taipei）**。根据“AI 创作画布、简单易用、轻量部署”的要求，从本轮 28 个针对性候选中精选 **12 个**，按 Star 降序排列。

**首选比较：basketikun/infinite-canvas、Node Banana、Toonflow；需要轻量服务端任务与素材保存时加入 FlyReq。**

**01 / 02 已补充深度核对**：[48 项全面横向对比与页面图](03-Toonflow与无限画布全面横向对比.md) · [离线页面对比](03-页面对比.html)。补充范围包括移动端、音频、3D 预演、WebDAV、视频任务恢复与长任务边界。其余候选仍为静态调研。

本轮选择的是有真实生成接口路径的创作应用。普通白板、流程图 SDK、单纯聊天分支画布不列入；没有将底层 SDK 当成已完成的 AI 创作产品。

“上手”根据界面操作说明、模型配置和工作流步骤判断；“轻量”按部署时必须维护的服务和数据组件判断。没有安装候选应用、调用付费模型、运行 Docker / WSL，也没有做内存 / 吞吐量实测。调用外部 API 时，模型算力在现有 ComfyUI / 外部服务上，不能把这种部署与本机加载模型的硬件需求混同。

- **极轻**：主应用可静态部署，生成请求由浏览器连接已有 API。
- **轻**：一个应用服务配合本地文件或 SQLite，无需另部署数据库集群。
- **轻至中 / 中**：含额外运行时、同步后端、对象存储配置或媒体处理工具；也可能因为桌面 / Agent 功能增加组件。

## 如何选择

| 优先级 | 方案 | 选择理由 |
|---:|---|---|
| 1 | [无限画布（basketikun）](https://github.com/basketikun/infinite-canvas) | 基础画布为静态前端，OpenAI 兼容与自定义图片 / 视频脚本能复用现有后端；适合先做简单、轻量 Web 创作入口。 |
| 2 | [Node Banana](https://github.com/shrimbly/node-banana) | 已有图片、视频、音频、3D 和本机 / 远程 ComfyUI；以单 Node 服务和文件保存为基础，适合多模态节点创作。 |
| 3 | [Toonflow](https://github.com/HBAI-Ltd/Toonflow-app) | 想少做产品开发、直接开始项目 / 分镜 / 资产创作时值得优先试用；服务器模式有 Bun 原生安装路径。 |
| 4 | [FlyReq Image Studio](https://github.com/doudou770/flyreq-image-studio) | 若需要服务端保存素材和任务，Node + SQLite 的结构比多服务运营平台简单。 |

## 最贴近现有生成服务的接入逻辑

若目标是给现有 ComfyUI 聚合服务增加创作界面，优先用 **basketikun/infinite-canvas 作为前端候选**：构建静态页面，配置 Base URL / API Key，把图片、视频和音频任务结果组织到画布里。它的自定义调用脚本为处理异步任务提供了改造入口，但仍需核对现有平台的上传、提交任务、查询任务、下载结果与模型目录字段。当前没有完成这一接入，也不能把“OpenAI 兼容”理解为视频、音频、3D 全部无修改可用。

**Node Banana** 已在设置中区分 Comfy Cloud、本机 ComfyUI、远程 ComfyUI，并支持导入工作流。若直接使用设备的 ComfyUI 服务，它比纯 API 图片画布覆盖更广；若统一走已有聚合代理，仍要映射代理鉴权、模型、上传和异步任务协议。

**Toonflow** 面向项目、角色、分镜等完整创作过程，适合希望尽快获得现成业务界面的人。其原生服务器安装路径为 Bun 构建并启动 Web / Server，当前公开版的统一用户访问管理不能按已有聚合后台能力直接推定。

## 每个候选的适用边界

| 编号 | 项目 | 值得考虑的情况 | 边界与待验证项 |
|---:|---|---|---|
| 01 | Toonflow | 项目工作区、叙事创作工具和 Android 横屏应用优先比较 | 已有音频节点、Android ARM64 客户端和 3D 预演；长任务可靠性、平台权限和聚合接口仍需适配。 |
| 02 | 无限画布（basketikun） | 最符合轻量 Web 画布和现有 API 复用方向 | 默认 IndexedDB，已有可选 WebDAV 和内置视频任务 ID 恢复；窄屏画布和自定义异步接口仍需适配。 |
| 03 | Node Banana | 多模态 + 现有远程 ComfyUI 最值得比较 | 节点式操作需要少量学习；支持本机 / 远程 ComfyUI不等于已兼容聚合代理的任务协议。 |
| 04 | 无限画布（tigerowo） | 需要服务器端保存与同步时再考虑 | 在 basketikun / HuFakai 生态基础上增加后端，组件与配置多于纯前端版。 |
| 05 | T8 Penguin Canvas | 偏好丰富节点或现成桌面客户端时考虑 | 功能和配置项较多；当前源码开发脚本通过 Electron 启动后端，不能只按旧说明推定任意 Node 环境即用。 |
| 06 | Director’s Console | 直接调多台 ComfyUI 的分镜创作很相关 | 需配置项目目录、工作流与渲染节点；聚合 API 和独立音频 / 3D 节点不能直接假定已适配。 |
| 07 | TwitCanva | 适合借鉴可视化视频创作 | 不同模型供应商的密钥 / 字段需要分别配置；复用现有代理通常需要整理接口适配。 |
| 08 | FlyReq Image Studio | 想要轻后端、持久任务与素材管理时优先 | better-sqlite3 有原生模块安装要求；已有代理的异步响应仍需逐项验证。 |
| 09 | PoloX AI | 适合偏好自然语言创作的人 | 当前主要走 WaveSpeed，接自有代理需改适配；网页检查、拼接等功能会增加浏览器 / 媒体处理负担。 |
| 10 | AI Omnigen Canvas | 个人 BYOK 试用的轻量备选 | 没有独立数据库 / 代理配置不代表已经提供静态导出；浏览器 ffmpeg.wasm 视频处理内存未实测。 |
| 11 | StoryFlow AI Canvas | 只先验证图片创作界面时可考虑 | 规模小，偏早期；以 Gemini 图像路径为主，完整视频 / 音频创作和代理接入需要扩展。 |
| 12 | Caraca | 轻后端节点画布的早期备选 | Star 和社区体量很小；当前依赖 fal.ai / OpenRouter，成熟度与自有 API 兼容性尚未实测。 |

## 重点源码核对

- basketikun：当前 [web/package.json](https://github.com/basketikun/infinite-canvas/blob/main/web/package.json) 使用 Vite 构建；[Dockerfile](https://github.com/basketikun/infinite-canvas/blob/main/Dockerfile) 最终仅以 Nginx 服务 `web/dist`。这里只读取构建文件，未运行容器。仓库部分部署文字仍提到 Next.js，以当前构建入口核对静态架构。
- Node Banana：[package.json](https://github.com/shrimbly/node-banana/blob/master/package.json) 的生产入口为 `node server.js --production`，README 明确工作流与媒体保存在本地，支持本机 / 远程 ComfyUI。
- FlyReq：[backend/package.json](https://github.com/doudou770/flyreq-image-studio/blob/master/backend/package.json) 为 `node server.js`，使用 `better-sqlite3`；README 提供非容器生产部署步骤。
- PoloX：[package.json](https://github.com/saihhold-zhao/polox_ai/blob/main/package.json) 声明 Nuxt 与 Node 运行时；SQLite 是本地数据层，Chromium 用于特定网页检查技能，FFmpeg 用于拼接 / 抽帧等功能。
- T8：当前 [package.json](https://github.com/T8mars/T8-penguin-canvas/blob/main/package.json) 的开发后端经 Electron 启动；旧部署段的“纯 Node”表述不能替代当前依赖核对。
