设计冻结：2026-10-25。关联待办 12、29、50、62，DEV-02/06/23/25/26/29/31/32。先冻结诊断边界，再实现和验证；历史异常与本轮注入分开，不以隔离复验通过宣称根因已解决。

## 1. 已有证据与缺口

- 82 的并发原生协议失败保留在 `confirmed-retry-native-concurrent-lock-failure.json`。所属 API 日志显示网关鉴权的 `rate_states SELECT ... FOR UPDATE` 遇到锁等待超时；当时没有阻塞事务链，不能推断是哪一个调用持锁或直接提高超时。
- 85 首轮完整 CI 的管理员审计查询返回 503。原生 PostgreSQL 日志在 2026-10-25 13:28:38.015 +08:00 记录审计分页投影触发 statement timeout；可确认语句预算被触发，尚不能证明为何该次查询超时。SQLSTATE 57014 也可能代表人工取消，不能仅凭该码将所有异常命名为超时。
- 现有审计路径丢弃数据库错误类别；未处理 DBAPIError 虽然客户收到通用 500，仍会向 ASGI 服务器传播并形成包含 SQL/驱动文本的堆栈。日志边界需要修正。

## 2. HTTP 诊断契约

沿用现有 HTTP 状态、错误码、请求 ID、权限与限额。审计不可用仍返回脱敏的 503；其他未处理 DBAPIError 仍返回既有通用 500；IntegrityError 的既有 409 不变。不新增客户可见诊断字段或数据库查询入口，不自动重试数据库事务、网关生成或 GPU 工作。

在已有有界 `http_request` JSON 事件中按需加入一次 `database_failure`。形状冻结于 [机器契约](./contracts/database-failure.schema.json)：固定操作组 `gateway_auth`、`audit_snapshot`、`http_request`；固定 SQLSTATE 白名单及对应原因；严格布尔 `connection_invalidated`。未知 SQLSTATE 只记 null/other。每个请求保留第一个已分类的失败，防止外层通用处理覆盖来源。

禁止记录异常文本/类型自报名、SQL、参数、表/约束名、DSN、文件路径、客户端提供的请求 ID、提示词、凭证和驱动 detail/hint/context。不新增指标标签。ContextVar 使用本次请求拥有的可变捕获槽，使同步线程池可回传最小诊断；finally 必须重置上下文，嵌套请求、并发请求和取消不能互相污染。仍经原 1024 项非阻塞日志队列输出，日志丢弃不改变业务结果。

DBAPIError 使用显式类型异常处理器消费，阻止框架重新向 Uvicorn 抛出数据库堆栈。非数据库异常继续遵守原处理与观测边界；不把任意异常当成数据库失败。审计保持只读一致快照、5 秒语句和 1 秒锁预算，网关鉴权保持现有 5 秒锁预算和事务边界。

## 3. 原生并发观测

原生协议驱动增加只读观测器，仅连接本项目回环 `127.0.0.1:55438`，只接受本次随机创建且后缀一致的控制面/上游测试库。读取 pg_stat_activity/pg_blocking_pids 的状态、等待类别、事务/语句年龄和阻塞关系；绝不读取 query 文本、参数、客户对象或凭证。

采样间隔至少 100 ms；每次最多 128 个后端、最多 256 个后端别名和 128 个去重观测；SQL 1 秒、锁等待 100 ms。只有阻塞或达到 500 ms 的活动语句/1000 ms 的事务进入观测；反复出现的同一关系仅更新次数及最大年龄。导出使用本轮 backend-N 别名和固定状态桶，不输出实际 PID、数据库名、application_name、地址或未知 wait_event 文本。达到上限明确计数，不默默扩大内存。

观测失败保留固定失败码与采样事实；测试驱动不得把缺失观测当作无阻塞。只有测试夹具故意跨 HTTP 持有已知锁，生产事务不引入该行为。finally 停止线程并关闭只属于本次观测的连接，再停止所属服务、清理本次测试库/凭证。禁止 Docker/WSL/VM，不干预开发预览和用户进程；本轮无 UI 行为变更，不以新截图替代数据库验证。

## 6. 并发任务查询的一致快照补充

完整重叠窗口再次出现任务 GET 的 502。控制面对应请求返回 200，数据库仅记录两次预期注入故障，尚不能将本次 502 归因于历史鉴权行锁超时。源码显示任务详情先读取 Job，再以第二条语句读取 Artifact；READ COMMITTED 下完成事务可在两次读取之间提交，形成旧的非终态与新产物组合。Provider 会按既有安全契约拒绝此组合；此处先登记待验证机制，不将推测写成已确认的原始故障根因。

冻结修复边界：任务详情的状态、revision、终态时间和授权产物列表必须来自同一个只读一致快照。事务开始后、第一条数据读取前设置 REPEATABLE READ READ ONLY，保留现有连接、语句及锁预算；不增加行锁、自动重试或跨 HTTP 持锁。业务和网关读取复用同一仓库，现有主体范围、jobs:read、artifacts:read 与敏感字段检查保持；列表不新增产物查询。响应字段、状态机、Worker、Go 严格校验和数据库 schema 不变，无数据迁移。

验证先在真实 PostgreSQL 的 Job 读取与产物读取之间，使用独立事务完成实际上传验证和唯一发布，要求单次响应保持旧完整快照，下一次查询返回成功与唯一产物。修复前保留可重复失败，修复后检查 revision、唯一用量及无权限字段不外泄；再执行原生 Provider、完整并发窗口、完整 CI 与精确候选安装。该修复只关闭已证明的读取竞争，不据此关闭历史鉴权行锁、审计慢查询或真实设备验收。

## 8. 包含路由的安全模板解析补充

复核发现当前锁定 FastAPI 将 include_router 保留为延迟包含节点，直接遍历 app.routes 的 path 漏掉这些已注册业务/网关模板；同一路由被不同前缀包含时，scope.route 又指向原始路由，不能单靠其 path 得到有效完整模板。[框架探测记录](./evidence/2026-10-25/database-diagnostics-route-before.json) 已证明实际 200 请求被记成 unmatched，并验证了隐藏路由和两个前缀的匹配上下文。

冻结修复：构建中间件时使用锁定框架的 iter_route_contexts 保存服务端注册的有效模板及原始路由归属；请求结束时只在该原始路由的已注册上下文内匹配有效路径。不得将客户端原始 path/query、参数值或自报 route 加入允许集合。包含前缀、嵌套、同一 Router 多前缀和 include_in_schema=False 都要覆盖；不依赖 OpenAPI 暴露全部内部路由。未知路径继续输出固定 unmatched，指标标签及队列/字节/超时预算不变，不读取或缓冲响应正文。直接注册路由和原有静态/未匹配回退保持。

先保留真实 ASGI 栈的失败回归，再修复；验证含嵌套/多前缀/隐藏路由、挂载 root_path、未知路径和正文/凭证不入日志。重新执行相关检查、完整 CI、原生协议及精确候选安装。此项完善日志归属，不改变业务授权、生成状态或 GPU 行为。
