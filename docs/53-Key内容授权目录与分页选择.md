# 53 · Key 内容授权目录与分页选择

日期：2026-10-24（Asia/Taipei）。本增量本地实现与协议验证完成，完整首版仍未验收。

## 1. 目标与权限边界

修复 Key 内容共享项目依赖旧会话 100 项、创建者依赖当前 Key 列表页的问题。项目与创建者分别分页搜索、批量解析已选名称；不以缓存、当前页或名称代替真实归属校验。保留既有内容策略 owner_only、project_shared、shared_creator_keys 和每类最多 1,000 个唯一 ID；不得缩小历史可配置范围。

共享内容继续按同一租户、所选项目、指定创建者的交集授权，当前逻辑 Key 自己的内容按既有规则保留。查询目录不会授予权限、消费生成额度、修改配置版本或写管理幂等记录。目录使用独立 Admin 会话及 keys:manage；业务 Key、Worker、网关服务身份均不能调用。

目录包含停用项目以及停用、到期、归档的本地/网关逻辑 Key，以管理仍存在的历史内容，明确显示其状态。这不恢复凭证、生成能力、已删除或到期的产物，也不改变每次内容读取的当前授权。响应只含名称、公开 ID、可信归属、状态及本地/网关来源分类；不含秘密值、verifier、凭证标识、策略、外部客户引用、内网地址或下载 URL。

## 2. 查询契约与资源上限

新增 POST /admin/api/v1/key-policy/options/query，要求 CSRF，属于只读查询，不要求 Idempotency-Key 或 If-Match。使用 JSON body 承载最多 1,000 个项目过滤和 1,000 个名称解析 ID，避免长查询串，并保留原授权容量。

请求 mode 为 browse/resolve，kind 为 project/creator_key，tenant_id 必需。browse 按 page=1～10,000、每页最多 50 条，q 最多 128 字符、NFC/去首尾空白且不含控制字符；不接受解析 ID。resolve 要求 1～1,000 个唯一 ids，只接受 page=1、空 q，不受 50 条目录页限制。project 不接受 project_ids；creator_key 必须始终与 project_ids 取交集，空项目集合返回空目录，禁止退回整个租户。

未知或范围外的解析 ID 统一列为 unresolved_ids，不返回其名称或是否存在。项目过滤中其他租户的 ID 不能扩大结果。浏览使用按名称/ID 的稳定排序，ID 搜索为完整公开 ID，名称搜索按字面转义 %/_。响应含 page、has_more、observed_at、选项 data 和 unresolved_ids。

查询在原生 PostgreSQL 的只读一致快照中完成，有 5 秒语句/1 秒锁超时；SQL 数量不随选中数量增长。批量 Key 策略验证最多按模型、Workflow、渠道、共享项目、创建者五类各执行一次查询，保留原错误码和全部服务端归属检查。无需数据库结构迁移，沿用 e94a0c637b20/42 张表。

机器契约见 [key-policy-options-query.schema.json](./contracts/key-policy-options-query.schema.json)。新增 DTO、运行时 schema、fixture、OpenAPI、生成前端类型和路由目录同步更新。

## 3. 页面与交互

沿用 Admin 的深蓝、青色操作、灰白表单与橙色待处理状态，不增加装饰或后台轮询。内容授权区明确说明：指定项目共享包含所选项目全部创建者；指定创建者共享取项目与创建者交集。多选器按名称/ID 搜索并翻页，选项显示所属项目、完整公开 ID 和生命周期标签；已选标签折叠，缓存最多保留已选 1,000 项及当前 50 条。

目录与已选名称解析分别可取消；关闭选择器取消无用搜索，关闭抽屉/切页/卸载取消全部读取和防抖计时。解析失败或归属失效时保留原 ID 并标记，禁止默默删除、回退为全部创建者或自动放宽授权。保存前明确要求处理无效选择，服务端仍重查全部范围。

新建 Key 切换至其他租户时清空共享范围、回到仅自身内容，并持续提示重新选择；编辑既有 Key 的租户/项目保持不可移动。移除共享项目后，该项目创建者的旧选择保留为待处理，管理员可恢复项目或移除创建者。仅改变本 Key 所属项目且仍在同一租户内，不擅自删除合法内容授权。

打开含非空授权的表单时，父表单必须先标为“未核对”；选择器在 active 改变时重新报告有效性，即使有效性仍为 false。禁止用通用的 valid=true 初始化覆盖子组件的失败结果。关闭再打开、解析失败、点击保存、重试成功必须作为连续操作验证；只在第一次打开时检查失败状态不够。
