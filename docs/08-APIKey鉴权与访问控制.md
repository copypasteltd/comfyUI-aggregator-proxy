# 08 · API Key 鉴权与访问控制

状态：开发设计基线 v0.4；2026-10-22 用户明确要求首版支持由 Admin 管理的多 API Key、独立访问限制与后续内容管理，并确认 Key 用于对外生成及内容 API。本文是需求与设计，尚未生成真实密钥或实现鉴权服务。

## 1. 首版目标

Admin 增加“API Key 管理”页面，管理员可以创建多个 Key，分别设置用途、权限、可访问内容和资源限制，并进行编辑、停用、恢复、轮换、撤销和记录查询。Key 用于对外生成及内容 API 的 Bearer 鉴权；Admin 登录与管理 API 沿用独立账号/管理会话，业务 Key 不授予后台管理权限。

首版内容管理对象是已有任务、输入素材和生成产物：支持按项目、创建 Key、模型/Workflow、标签与时间筛选，按权限查询、下载、取消或删除；内容发布站点、编辑器等独立 CMS 功能不由本需求隐式承诺。

## 2. Key 类型与身份边界

| 类型 | 使用入口 | 可授予能力 | 边界 |
| --- | --- | --- | --- |
| 业务访问 Key `service` | `/v1` 的 Bearer 鉴权 | 模型发现、素材上传/访问、生成、任务查询/取消、产物下载/删除 | 只能访问明确授权的项目和内容，不因拥有业务 Key 获得 Admin 权限 |
| Admin 管理会话 | `/admin`、`/admin/api/v1` | 按管理角色管理 Key、渠道、Workflow、模型、队列及授权内容 | 由独立管理账号登录建立；业务 Key 不能换取管理会话 |
| Sub2API 客户 Key | Sub2API 的客户入口 | 网关自身授权的客户操作 | 凭证仍由 Sub2API 验证，项目只接收经认证的身份映射与限制，不导入其明文 Key |
| Worker 凭证 | `/internal/v1` | 自身节点心跳、租约、受控管理动作与结果回报 | 不可调用客户接口或管理接口 |

管理员可为不同脚本、应用、客户或内容系统分别创建业务 Key。每个 Key 记录凭证签发来源、所属租户和默认项目，不能通过访问另一个路径自动提升权限。只有具备管理角色授权的 Admin 会话可创建其他 Key 或修改策略；业务 Key 不能修改自身权限。

Admin 账号通过 HTTPS 登录换取短时 HttpOnly/Secure Cookie 会话，写操作校验 CSRF。Key 管理页面只在创建/轮换成功时显示一次新秘密值；页面不把长期 Key 放入 URL、localStorage 或日志。后台账号权限和业务 Key 策略分别管理，轮换业务 Key 不改变管理员账号身份。

首次管理员通过原生部署的初始化流程建立，保留受控账号登录/恢复路径，随后在 Admin 创建业务 Key。业务接口、内容文件路径和管理接口不得因尚无 Key 而自动匿名放行。业务 Key、管理会话、网关服务身份和 Worker 身份分别校验，不按任意客户端声明选择可信身份类型。

## 3. API Key 管理页面

| 分组 | 管理员可设置或查看 |
| --- | --- |
| 身份 | 名称、说明、用途标签、签发来源、所属租户/默认项目、创建人 |
| 凭证 | 稳定 key_id、展示前缀/指纹、凭证版本、创建/轮换时间；完整新 Key 仅创建/轮换时显示一次 |
| 状态 | enabled/disabled/revoked、有效开始/截止时间；到期独立展示，已撤销不可恢复 |
| 操作权限 | 按操作选择 scopes；可使用只读内容、图片生成、视频生成、素材上传等预设后细化 |
| 能力范围 | 可用公开模型、可选的 Workflow/发布版本范围、允许渠道集合、生成规格上限 |
| 内容范围 | 指定项目、仅本 Key 创建内容，或管理员明确授予的项目共享/指定 Key 内容范围；敏感提示词/原图单独授权 |
| 调用限制 | 请求频率/突发、每日新任务数、未完成任务上限、同时生成上限，以及图片张数/视频秒数的资源额度 |
| 访问来源 | 可选 IP/CIDR 白名单；实际来源只信任已配置代理链，客户伪造转发头不能绕过 |
| 文件访问 | authenticated_proxy 或显式允许的 signed_url；按 Key 限制下载、删除与保留期内的内容访问 |
| 使用记录 | 最后使用时间/来源 IP、调用/拒绝数、任务结果、资源用量与剩余额度，按 Key/项目/时间查询 |

创建页面默认最小权限、显式选择项目和能力；未配置权限/模型/渠道范围不解释为全部允许。不限额、全部已授权资源等宽范围选项必须显式选择，仍受平台/租户上限约束。无效或空交集策略应在保存时提示，不能悄悄改成放行。

列表支持按名称、key_id、项目、用途和状态筛选；提供权限摘要、用量入口和一键停用。删除是撤销后的逻辑归档，历史任务和审计保留关联。

## 4. 操作权限与内容隔离

| 权限组 | 示例 scopes | 首版检查位置 |
| --- | --- | --- |
| 发现能力 | `models:read`、`capabilities:read` | 列表与详情只返回可授权范围，不暴露内部依赖路径 |
| 生成与任务 | `jobs:create`、`images:create`、`videos:create`、`jobs:read`、`jobs:cancel` | 入口类型、模型/解析后的发布版本、规格、内容归属与资源额度均校验 |
| 素材与产物 | `assets:upload`、`assets:read`、`artifacts:read`、`content:download`、`content:delete` | 列表、单条、预览、HEAD/Range 下载、删除与签名刷新均校验 |
| 业务内容目录 | `content:read`、`content:download`、`content:delete`、`content:sensitive` | 仅用于 `/v1/content` 及其详情/下载/删除；绑定指定项目/创建 Key 范围，不获得 Admin 权限 |
| Admin 管理权限 | 管理角色中的内容查看/删除、Key 管理/用量查看、渠道/Workflow/模型管理 | 仅通过管理会话；授权不得超过管理员自身可授予范围，后台详情和 SSE 同样过滤 |

有效权限为平台规则、租户/项目规则、当前身份/角色和 Key 策略的交集。模型别名解析后再次检查具体 Workflow/版本；渠道限制传入调度硬过滤，客户端不能通过原生 jobs、图片/视频兼容入口或指定路径绕过。

`content:sensitive` 是额外披露权限：完整提示词、输入原图及被标记敏感字段在已有读取/下载权限之外还需该scope，管理端对应独立管理权限。它不代替assets:read、content:download等操作，也不授予修改权限。仅把已授权素材交给内部Worker用于生成，不等于向客户披露原图；仍校验素材归属和任务输入授权。job详情可返回安全状态；附带产物元数据另查artifacts:read，签名/文件/内联结果另查content:download。

所有生成入口先归一化能力，再同时检查 `jobs:create` 和相应 `images:create` 或 `videos:create`，不能利用原生 jobs 绕过图片/视频限制。限制到特定 Workflow/版本的 Key，不因公开别名切换自动获得其他版本。模型/渠道范围约束新任务准入与冻结路由，内容访问另按当前操作与内容授权检查；模型下架不抹除历史内容。

jobs、assets、artifacts 记录可信的 tenant_id、project_id、owner_key_id，并保留实际凭证版本与鉴权来源。业务准入使用 Key 的默认项目，或经可信网关映射确认的项目；两个独立 Key 即使属于同一管理员或同一项目，默认也不能互查内容。只有管理员显式授予同租户内的项目共享或指定创建 Key 范围才可访问；租户边界不能靠 Key 策略越过。标签用于管理检索，不单独决定授权，调用者不能靠改标签或填写 project_id 改变归属。

列表、聚合计数、分页游标、搜索、预览、错误、下载和实时事件均按相同范围过滤。无资源权限时不泄露其他项目/Key 的任务存在性；将未授权资产 ID 填入新任务也必须在 GPU 执行前拒绝。

首版增加业务内容目录 `/v1/content` 和管理内容目录 `/admin/api/v1/content`，按既有任务/素材/产物索引聚合，不能用这些目录获得原端点没有授予的操作。前者使用业务 Key，后者使用管理会话。内容条目使用稳定 ID 和 kind/source_id 关联已有资产/产物，详情、下载和删除继续校验源对象归属与生命周期，不接受原始磁盘路径。公开接口不返回内网渠道地址、完整工作流或模型磁盘位置。

## 5. Key 生命周期与存储

key_id 表示稳定的逻辑访问主体；credential_id/版本表示可轮换的秘密值。系统生成高熵随机凭证，服务端保存不可还原的校验摘要和展示前缀，不能通过查看详情取回完整 Key。开发方案固定为：随机秘密部分至少32字节CSPRNG，公开credential定位符与secret分开编码；只以公开定位符查找记录，使用带版本服务端pepper的HMAC-SHA-256校验，并以恒定时间函数比较固定长度摘要。记录pepper_version；轮换保留必要旧校验密钥或显式轮换凭证，不能误使全部合法Key失效。不把明文Key当数据库检索字段，不复用此方案存储低熵管理员密码。

管理员密码采用成熟Argon2id库与可升级参数，管理员session使用独立高熵不透明令牌、服务端只存摘要；参数和库的精确版本在WP-02经过原生验证后锁定。渠道凭证需要给Worker实际使用，因此采用加密secret store而非不可逆哈希；只存引用和受保护密文。不能将客户Key、管理员密码、会话和渠道秘密四种存储方式混为一套。

轮换为同一 key_id 生成新秘密，可配置短暂重叠窗口或立即撤销旧凭证。默认旧凭证立即失效；新凭证延续同一权限、内容归属、限额计数和幂等范围，不能靠轮换重置每日额度。新增独立 key_id 的跨 Key 内容访问需要另行授权。

停用可恢复；撤销不可恢复且禁止签发/使用该 Key 下的凭证。到期/停用/撤销和权限收紧成功提交后，后续鉴权请求使用最新权威策略版本；缓存不得继续按旧许可放行。已接收的长等待请求在返回受保护内容前重新校验；Admin 会话按其管理账号当前角色复核，与业务 Key 生命周期分开。

Key 限制的身份校验和额度记录无法可靠读取时拒绝新授权操作，不能降级为匿名或无限额；任务执行/回传使用自己的任务租约继续收尾。所有变更保留创建人、操作者、原因、前后策略版本与脱敏审计，响应/日志不包含 Key 明文。

## 6. 限额与已接收任务

- 请求频率与 GPU 并发分别限制。并发生成数只计算占用生成资源的任务；未完成任务数包括排队、执行、回传和核对。额度不替代全局公平调度与共享 GPU 锁。
- 发出租约时按 Key/项目/租户的当前生成并发上限检查；收紧上限不抢占已开始的任务，但会延后后续启动。冻结的是任务规格与允许路由，不冻结一个可绕过新资源上限的并发额度。
- RPM/突发限制覆盖所有 HTTP 调用，轮询/下载与生成准入可分别设置预算；每日任务按 Asia/Taipei 自然日计数，账期和时区写入策略。首版默认计数不可因服务重启或轮换重置，额度未配置时不能解释为无限。
- 新任务的 Key/项目/租户限制在准入时原子预留，使用规范操作和逻辑 key_id 去重。同一幂等请求恢复原任务，不再占一次任务/资源额度；不同 Key 创建的新任务不因 prompt 相同被误合并。
- 每日新任务额度按成功准入的不同 job 计数，任务后来失败也不退回该计数。图片张数/视频秒数额度按规格预留，成功后按可交付计量结算，失败/取消按规则释放；内部自动重试不重复预留。
- 轮换、别名入口切换、兼容入口与原生入口之间不能绕过配额。新 Key、同项目或网关调用仍受到项目/租户总上限约束，多个 Key 不能增加实际 GPU 槽位。
- 停用或到期默认阻止后续调用，不隐式取消已接收任务。可在 Admin 单独选择阻止尚未执行任务或按既有状态机批量取消；已有执行仍需确认停止后释放 GPU。后台结算与回传不依赖原 Key 继续有效。
- 已接收任务保留准入时的身份、策略版本和允许路由约束；默认策略变更只作用于新调用，不静默改变已购买规格或扩展到其他渠道。管理员对旧队列的阻止/取消必须单独记录原因；失联、环境不符等实时健康过滤仍始终有效。

资源额度是调用/图片/视频等上限，不另建客户货币余额账本。Sub2API 接入继续由其唯一客户账本处理收费；直连 Key 首版可用于内部或已在外部结算的项目，通过同一调度与资源计量运行，不隐含新增售卖/充值系统。

## 7. 内容下载与撤销效果

新建 Key 默认 `authenticated_proxy`：查询只返回需携带相应凭证的云端 content 地址；每个 GET、HEAD、Range 和刷新请求重新检查 Key 与资源范围，不向该 Key 返回可绕过鉴权的对象存储 URL。Admin 的浏览器下载使用当前管理会话；网关下载必须把可信客户身份带到服务端。

同步图片的 Base64 也是内容交付。缺少 `content:download` 的 Key 只能选择已授权的异步提交/元数据操作，不允许使用会内联返回图片的同步模式；返回前还要复核当前 Key。已有任务的轮询可返回获准状态/元数据，但不能签发无权下载的链接。

管理员可为明确需要普通 URL 下载兼容的 Key 开启 `signed_url`。这时仍私有存储、短时签名，建议有效期 15 分钟，并取 Key 已知有效期、内容剩余保留期与策略上限中的最早截止时间。Key 撤销阻止再签发/刷新，但已签发 URL 可能持续有效至到期。页面必须展示此行为，不能承诺撤销 Key 能追回已下载内容或立即终止已开始的文件流。

两种方式均按云端文件保留期、删除状态和资源授权交付。选择 signed_url 的 Key 不能代替更严格 Key 去刷新其无权访问的内容；测试必须验证代理不会重定向成未受限存储 URL。图片/视频兼容客户端对需鉴权下载的支持作为接入验收的一部分。

## 8. Sub2API 接入与统一身份

项目 Admin 管理本项目直连业务 Key，数据面保留 OpenAI 风格的 `Authorization: Bearer <api_key>`。Sub2API 客户 Key 的秘密值仍留在网关；Admin 展示经批准的外部租户/Key 引用和本地项目/主体映射、附加资源限制，不假定能通过本地页面直接修改外部网关秘密值。

Provider 使用独立、最小权限的网关业务凭证与可信客户声明调用任务服务；服务端同时校验网关权限和经可信映射解析的客户权限，不将所有客户都归为网关服务 Key 创建。客户传入的同名身份头必须剥离；声明或映射缺失时拒绝，不回退为共享管理员主体。

需要让直连与网关访问同一批内容/限额时，管理员显式建立同一逻辑 key_id/项目的映射，服务端验证 issuer 和外部引用；该映射不能由调用者自行指定。未建立映射时按不同命名空间主体隔离，禁止通过“同名 Key”或原始 Key 字符串自动合并。

资源限额在任务服务持久化执行；网关还可收紧自身入口限制。跨服务的货币结算继续采用原有准入/对账协议，不能把 Key 资源额度和 Sub2API 余额各扣一遍。

## 9. 管理及内容端点

| 端点 | 用途 |
| --- | --- |
| `GET/POST /admin/api/v1/api-keys` | 按角色列出 Key、创建 Key 和首次一次性返回秘密值 |
| `GET/PATCH /admin/api/v1/api-keys/{id}` | 查询脱敏详情、更新授权策略/限制，要求配置版本条件 |
| `POST /admin/api/v1/api-keys/{id}/actions` | 固定动作 disable/enable/revoke/rotate；动作幂等，轮换选择旧凭证失效时间 |
| `DELETE /admin/api/v1/api-keys/{id}` | 撤销后逻辑归档，保留内容归属与审计 |
| `GET /admin/api/v1/api-keys/{id}/usage` | 计数、预留/结算用量、拒绝原因与剩余额度 |
| `GET /admin/api/v1/api-keys/{id}/access-events` | 脱敏调用记录、来源 IP、鉴权/限流结果；访问范围受角色限制 |
| `GET /v1/content`、`GET /admin/api/v1/content` | 分别使用业务 Key/管理会话，在授权范围内按项目/创建 Key/标签/模型/时间检索素材、任务产物索引 |
| `GET /v1/content/{id}`、`GET /admin/api/v1/content/{id}` | 统一条目的授权详情，不扩大源对象权限 |
| `GET/HEAD /v1/content/{id}/download`、`GET/HEAD /admin/api/v1/content/{id}/download` | 按策略代理文件或签发允许的 URL，支持 Range；每次访问校验当前授权 |
| `DELETE /v1/content/{id}`、`DELETE /admin/api/v1/content/{id}` | 按内容删除权限处置，活动引用存在时拒绝或延迟清理，保留任务历史 |
| `GET /v1/access-policy` | 当前业务调用者的脱敏有效范围/限额摘要，不泄露其他 Key 或内部渠道地址 |

所有管理变更经过角色和授权上限检查，支持策略修订冲突与审计。create/rotate 的新秘密值只在首次成功响应展示，幂等重试仅返回既有 Key/操作标识，不再次披露；首次响应丢失时管理员通过新的轮换操作取得新秘密，不能创建不受控的第二个 Key。

无凭证、无效、到期、停用、撤销返回 `401`；身份有效但缺少某操作返回 `403`；访问范围外的内容按 `404` 隐藏存在性；频率或资源额度不足返回 `429` 与具体 code、恢复条件及适用的 Retry-After。伪造身份、权限失败与输入拒绝不得消耗 GPU。

## 管理标签与预览权限增量

[48](./48-内容检索标签与受控预览.md) 新增的是管理角色权限 content:manage，只允许独立管理会话替换内容标签；它不是可分配给对外业务 Key 的新 scope。默认仅 administrator 拥有，其他角色不自动获得内容读取、修改或敏感权限。API Key、Worker、网关凭证即使有效，也不能替代管理 cookie/CSRF 调用管理内容目录、标签或预览。

content:read 支持安全管理索引及名称选项；预览和下载均需 content:download，输入另查 content:sensitive。业务内容元数据不因 Admin 标签字段增加披露范围；标签检索/修改不改变 tenant/project/创建 Key 的授权交集，也不改变显式共享策略。对外内容权限和管理权限同名时仍属于不同身份体系。

## 租户与项目的速率约束

本地和可信网关映射的每次业务鉴权，均在同一数据库事务内按 tenant→project→business Key 的固定顺序检查并消费当前 rpm/burst；任一层拒绝则三层扣减全部回滚。查询、生成、内容读取等业务接口共用相应逻辑主体的窗口，不把请求数等同于任务数。不同 Key/项目不能绕过租户上限，不同租户相互隔离。业务 Key 保持原 business:UUID 桶标识以沿用历史；父级使用 tenant:UUID、project:UUID。停用/恢复或修改上限不重置窗口，时间在取得速率行锁后读取。网关服务及受限恢复速率独立保留。

默认新建租户/项目沿用 120 rpm、10 burst；容量评估应计入异步查询与下载，管理员可按实测调整。新管理写入为显式 bounded/unlimited，rpm≤60,000、burst≤10,000，其他计数≤9,007,199,254,740,991；读取旧记录保持兼容。scopes:read/scopes:manage 只属于管理角色，绝不扩充业务 Key 的管理权限。完整规则见 [52](./52-租户项目与分层配额管理.md)。


## 内容授权目录

POST /admin/api/v1/key-policy/options/query 为固定的只读 Admin 查询，要求会话、CSRF 和 keys:manage；不接受业务 Key、Worker 或网关服务身份，不写管理幂等/审计变更或消费生成额度。每页 50 项，已选名称解析和策略保留各最多 1,000 个唯一项目/创建者。停用、到期、归档主体可管理历史内容，不能恢复其凭证或已删除对象。创建者始终与所选项目取交集，未知/范围外统一 unresolved_ids，不能回退为全部租户。服务端保存时批量重查归属，前端解析失败或重开未验证状态必须拒绝保存。实际历史图片列表、下载及撤销已通过真实 PostgreSQL/HTTP 验证，详见 [53](./53-Key内容授权目录与分页选择.md)。

## 正式范围补充：ComfyUI 音频产物

音频生成继续由现有业务 Key 和可信网关主体控制，新增权限/限额必须显式冻结及迁移，旧 Key 不静默获得新音频生成权限。音频内容沿用 tenant/project/creator 交集、撤销与到期语义；音频时长计量不能占用图片数量或视频时长额度。Admin、业务 Key、Worker、网关服务四种身份不混用。当前已实现显式 `audio:create`、Key 最长毫秒及 Tenant/Project/Key 音频日额度，缺省 0；兼容迁移与本地验证见 [55](./55-音频契约与兼容迁移.md)，真实资源验收仍遵守 [54](./54-ComfyUI音频产物范围与开发约束.md)。

## 第 68 增量补充

停用 Key 不隐式取消旧任务。需要处置时，管理员在任务页按 Key 筛选并明确选择当前页目标，确认后通过独立管理会话提交持久批次，原因可选 key_access_changed；业务 Key 不能调用此管理能力。运行与核对中的任务仍需停止证据，结算不依赖业务 Key 继续有效。流程和本地验证见 [68](./68-任务批量取消与持久逐项结果.md)。
