# Workflow 批量推送与验证实现约定

日期：2026-10-22，设计基线 v0.4。细化 [Worker 管理协议](./12-接口契约与Worker协议.md)。冻结结构校验、设备环境验证、真实样本成功和人工运行批准分别记录，任何一步不能替代其他步骤。

## 批量推送

`POST /admin/api/v1/workflow-syncs` 的当前增量实现接受 `direction=push`、不可变 release ID/摘要及 1～100 个互不重复的渠道 ID/期望资源 revision。服务端按渠道 UUID 顺序锁定，逐一检查同项目归属与版本；任一目标不合法时整次提交失败，不留下半批命令。成功原子创建一个 operation、逐目标固定指令及审计，202 仅表示已排队。

每个目标进入排空并清除旧运行批准，Worker 等物理 GPU 无占用后校验依赖并原子保存发布包。各目标独立回执，聚合状态包含 partial_failed；聚合 operation 行串行锁定，防止最后两个回执并发导致状态永远停在 running。重复提交同一幂等键返回同一个 operation。每批冻结指令累计不超过 16 MiB。

Admin 的 Workflow 页支持选择多个渠道；模型页提供独立的样本验证入口。操作中心按目标显示命令状态和安全错误码，回执仅投影 success、applied_revision、environment_verified、release_digest、error_code，不透传 Worker 任意 JSON、工作流或网络地址。详情最多返回 100 个目标，并明确是否截断。

本文件的 push 端点登记不代表完整双向同步验收。`pull_workflow`、导出目录白名单与导入冲突预览的后续实现约束及验证见 [41](./41-Workflow渠道拉取与草稿导入.md)。当前反向读取由管理员指定相对文件，不自动浏览导出目录；目录清单浏览和真实导出文件验收仍待完成。固定指令不安装插件、下载模型或执行任意远程命令。

## 显式发布验证

`POST /admin/api/v1/workflow-releases/{id}/validate` 指定公开模型 ID、模型 revision、目标渠道 ID/资源 revision、规范样本请求和 `sample_budget=1`。只允许一个规范任务，仍经过普通规格、配额、GPU 槽位、journal、产物验证和终态计量。验证主体是可重复使用的 internal_validation 逻辑 Key，不能签发业务凭证。

验证管理幂等记录与生成准入在同一事务提交。为遵守“配额桶先于素材锁”的顺序，内部主体/同项目样本别名可以在独立短事务幂等准备；它们不形成执行任务或配额，任务真正准入时再次校验对象未删除、未过期且已验证。失败残留仅是内部主体和受素材生命周期约束的别名，不能领取或结算。重放已受理请求先返回既有任务，不受随后素材过期影响。

准入持有当前模型与渠道锁，并重新匹配显式 release/model/渠道版本，防止准备素材后公开别名被切换到其他发布版本。使用已有客户素材还要求 `content:sensitive` 并记录审计；跨项目素材拒绝。原有模型 validation-jobs 入口复用同一保护，不保留无锁的替代路径。

运行批准必须引用同一渠道、同一当前运行配置、同一 release 和物理 GPU 的成功验证产物；批准时产物及已验证对象均须尚未删除、过期或进入回收。配置或 Workflow 同步变化清除旧批准，纯显示名称变更不更改运行配置版本。没有真实成功产物时拒绝批准和发布，不能将预设中的 approved 字段当作证据。

## 验证

使用真实 PostgreSQL 测试批量同键并发、重复目标、版本冲突整批回滚、最后两个回执并发的 partial_failed、验证幂等、别名/渠道版本变化拒绝和配置变化清除批准。真实 ComfyUI 依赖检查、取消语义与五类样本质量另外验收。


## 已实现的失败目标专用重试

原操作终态后，操作中心通过只读预览明确选择确定失败渠道；POST 创建关联原操作的新操作，持久唯一后继保证不同请求键也不会重复应用同一失败目标。成功/未知/旧结果需重新验证、配置变化、被更新同步替代或已有后继的目标拒绝；原冻结版本、目标资源 revision 及全部选择原子校验。详情及 ADMIN-TEST-06 的本地验证边界见 [67](./67-Workflow失败目标重试与操作关联.md)。
