# 45 · 渠道模型清单与受控登记

本增量推进 ADMIN-03/05/06、NODE-04 和 WP-05/07/08：将当前只有节点类名的渠道扫描扩展为本机模型文件目录发现，允许管理员检查选中文件的实际 SHA-256，再按检查证据登记到中央模型文件目录。冻结以下边界后同步机器契约、Worker、控制面、Admin 和验证；不把元信息登记视为已验证运行能力。

## 1. 本机范围和预算

使用渠道本地白名单 ComfyUI 根目录下的 `models/`，只读递归发现模型文件；不从客户请求接受绝对目录，不自动读取 `extra_model_paths.yaml` 的外部位置，不跟随 junction/symlink/reparse/hardlink，不下载、安装、加载或删除模型。外部模型目录不在这份默认目录快照的覆盖范围，必须显示该范围，不能将未发现直接解释为整台机器没有该模型。

支持 safetensors、ckpt、pt、pth、bin、gguf、onnx 文件后缀；它们只作为文件读取，绝不反序列化 pickle/torch 内容。单轮最多检查 5000 条目录项、8 层、10 秒，最多回传 1000 个文件条目。达到预算时保留明确的 partial 标记；不可访问或指针目录不允许产生“完整且为空”的成功快照。结果只含规范相对路径、大小、纳秒修改时间、推断类别，不含盘符/绝对路径或模型内容。

目录发现不批量读取大模型。选中文件检查使用独立固定管理指令，单文件上限初值 64 GiB、240 秒以内（本地配置默认 120 秒），按块流式计算 SHA-256；可在 Worker 本地调整预算，仍不超过固定管理指令 300 秒租约。读取前核对目录快照的路径/大小/修改时间，打开后的实际句柄必须仍指向允许目录中的普通单链接文件；Windows 读句柄与目录句柄限制写入/重命名，读取前后再次核对身份/大小/时间。超时、超过体积、目录变化或无法校验时返回固定错误，不能以文件名或部分哈希冒充成功。

## 2. 持久快照和检查操作

沿用 `scan_inventory` 与 `POST /admin/api/v1/channels/{id}/inventory-scans`，保留原节点类名/摘要并增加模型目录快照。云端独立校验闭合 DTO、条目唯一/排序、路径、计数、目录摘要和回执体积，将模型快照绑定当前 boot、渠道 applied/desired revision 与服务器接收时间保存到 Channel.observation。旧 Worker 未返回模型快照时，显示尚不支持，不能沿用旧的“完整”目录许可。

迁移 `e6215c902f30` 扩展 worker_commands 的固定动作检查约束，增加 inspect_model_file，并增加可空 completed_at，记录服务端完成时间作为检查结果的 300 秒登记期限依据；旧数据不回填为新证据。执行迁移前备份并验证归档；迁移不创建新业务表，不改变 GPU 占用规则。降级遇到该新动作记录时明确拒绝，先排空并采用向前修复。

`GET /admin/api/v1/channels/{id}/inventory` 新增 `model_files` 投影和独立 `model_page`（每页 50 条）。只显示经过校验的模型字段；提供完整/部分/不可用/过期状态、采样时间和中央同路径登记的元信息对照。目录快照 300 秒后过期；仅文件名/大小一致只能显示“未校验”，不能显示哈希匹配或设备可运行。

新增 `POST /admin/api/v1/model-file-reads`：接受 channel_id、expected_revision、catalog_digest、relative_path；请求必须对应当前、未过期、同 boot/revision 目录中的文件。权限为 models:write；幂等创建持久 management operation 与 `inspect_model_file` 指令。只读操作不获取 GPU 管理占用，不修改模型/Workflow；设备串行执行固定管理指令。Worker journal 复用操作摘要/结果，重启后可重发既有回执，不能把不同命令当作同一检查。

新增 `GET /admin/api/v1/model-file-reads/{id}`：requires models:read，只允许创建者或管理员读取匹配操作的安全结果；返回 pending/running/succeeded/failed、固定错误码，以及成功时的相对路径/bytes/mtime/SHA-256。过期、旧 boot、渠道 revision 改变不能授权新登记。云端独立验证成功回执和原请求完全对应，不能接受 Worker 额外提供的路径或伪造目录上下文。

检查是对已授权快照的只读观测。若同 boot、命令租约内的合法哈希结果返回时，目录已过期、被新扫描替代或渠道 revision 已变化，仍幂等收取该结果并终结读取操作；详情标记 stale，登记事务继续拒绝过期/不匹配的证据。不能把过期结果转为登记许可，也不能因这种正常来源变化永久阻塞该节点后续管理操作。旧 boot、错误摘要、伪造回执和逾期命令仍按原协议拒绝。

## 3. 由检查证据登记

新增 `POST /admin/api/v1/model-file-reads/{id}/registrations`，权限 models:write。浏览器只提交展示名和模型类别；租户/项目、路径、字节数、SHA-256 均从服务端保存的渠道和检查证据提取。使用相同数据库事务复核操作归属、成功回执、当前 boot/revision、证据 300 秒时效，并写 ModelArtifact、审计及幂等结果。相同路径/哈希的存活登记复用原项；不能覆写其他哈希，或由浏览器自报租户、路径、哈希扩大访问范围。

文件检查是采样事实；外部程序之后可能更改文件，因此登记不会自动发布公开模型、批准运行画像或改变 Workflow 绑定。生成前原有依赖哈希与环境验证继续生效。渠道目录变动后须重新扫描/检查；没有完整目录的情况下不把未列出的中央项标记为确定缺失。

## 4. 图形界面和验证

渠道详情提供模型文件表格、目录完整性/时效、独立分页、选中文件检查、持久操作状态与哈希对照、确认登记操作。只读用户可查看，维护权限控制扫描/检查/登记；关闭对话框、隐藏或离页停止轮询，保留进行中操作 ID 以便继续查询。错误/旧快照和版本冲突必须可见；登记完成刷新对应清单，不展示绝对路径或原始回执 JSON。

验证覆盖原生 Windows 句柄、junction/hardlink/父目录替换、流式哈希/读取预算、大小/mtime 变化、目录部分/排序/摘要、旧 Worker/boot/revision/过期、伪造回执/浏览器字段、重放并发唯一登记、PG 事务/权限和图形交互。完整 Python/类型/前端检查、既有 Workflow 目录/导入及原生 Sub2API 链路按风险回归；最终证据另行登记，真实模型权重、真实设备和 10/20 台仍由原验收要求覆盖。

## 6. 未完成的实测与运行边界

读取范围只包含本地 models 目录中的受控普通文件，目录检查沿用不超过 512 字符的相对父目录约束。外部 extra_model_paths、网络盘和目录指针不据此授予访问；目录部分可用或目录缺失不会被解释成全机无模型。真实大模型的磁盘吞吐、哈希预算、与推理同时执行的影响、真实 ComfyUI/五类 Workflow、私有 S3、真实 Redis 和 10/20 台实机仍待专项联调与验收。

检查是有界只读操作，当前不提供中途取消该文件哈希的 API；页面停止查询不会冒充设备已停止。设备在本地预算和固定命令租约约束下结束，持久操作可按编号查询。登记成功不发布公开模型、不批准运行画像，也不改变既有生成资源占用。

收尾边界补测：三个新增回归先复现了读取期间来源变化导致队列无法继续，修复后及完整 500 项回归均通过。已授权快照的合法只读观测在租约内正常结束，登记仍按当前来源/证据有效期拒绝旧结果。另复现并修正页面重复检查误用旧幂等键；未知创建结果重试沿用原键，已获得操作编号后的新点击使用新键。最终重新构建并通过 11 组模型浏览器检查；本增量 11 组 Workflow 浏览器结果按相关源码和脚本摘要未变沿用。
