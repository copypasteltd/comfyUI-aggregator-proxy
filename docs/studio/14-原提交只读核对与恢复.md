# 原提交只读核对与恢复

生成请求可能已经被服务接受，但浏览器断网、关闭或丢失响应。这时，画布保留首次发送前写入 IndexedDB 的完整请求、幂等键、发布摘要和原连接指纹，选择“只读核对原提交”找回原任务。找回后继续查询原任务、下载或载入原产物。

| 状态 | 用户操作 | 系统行为 |
| --- | --- | --- |
| 本机已保存、从未发送 | 提交已保存请求 | 在 IndexedDB 写事务内占用首次发送，再发送生成请求 |
| 发送中、提交结果未知 | 只读核对原提交 | 只查询原幂等映射，不重新提交或上传 |
| 备份恢复且无任务 ID | 只读核对原提交 | 同样查询原映射；备份不会变成首次生成 |
| 找到且完整匹配 | 查询原任务 | 恢复原任务 ID；备份标记为已核对，保留恢复来源 |
| 本次未查到 | 保留记录，稍后再次核对 | 保持未知状态；未查到不代表没有执行 |
| 原请求不匹配、服务不支持、Key 不同 | 保留原记录 | 明确提示原因，不回退生成，不替换连接身份 |

首次发送的占用和阶段更新位于同一个本机写事务内。两个页面同时操作同一记录时，只有先占用的页面可以发送生成 POST，另一个页面查询原提交。这是原有幂等服务之外的本机保护，不改变服务端并发或配额预算。

接口为 `POST /v1/jobs/lookup`，请求体仍为原 `JobCreate` JSON，认证仍为原业务 Bearer Key，要求 `jobs:read`。`Idempotency-Key` 必须是原值；`X-Expected-Release-Digest` 必须与首次提交时是否提供及其值一致。服务通过 `/v1/access-policy` 的 `X-Studio-Submission-Lookup: 1` 响应头声明支持，任意源 CORS 可读取该响应头。HTTP 高端口直接可用。

服务端在只读一致性快照中按租户、项目、逻辑 Key 查询映射，比较完整规范请求、原幂等指纹、原任务指纹和冻结素材摘要。当前模型已下架、输入素材过期或其记录被清理，不会让核对操作重新准入任务。响应不包含提示词或原输入，产物列表另需 `artifacts:read`。鉴权及 RPM 统计照常执行；不新增任务、幂等记录、计费条目、出站事件或 GPU 调度。

```sh
curl -X POST 'http://你的服务:39443/v1/jobs/lookup' \
  -H "Authorization: Bearer $API_KEY" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 首次提交的原幂等键' \
  -H 'X-Expected-Release-Digest: 首次提交的64位发布摘要' \
  --data-binary @original-request.json
```

首次提交没有发布摘要时，不要添加该摘要头。`outcome: found` 返回原任务，`outcome: not_observed` 返回 `job: null`；后者可能来自尚未提交的事务快照，因此不会自动补发。冲突返回 `submission_mismatch`，冻结信息不可验证返回 `submission_unverifiable`，均保留本机记录。
