# 29 · 本机原件引用检查与 GLB 动画

独立画布新增普通本机原件的引用检查，以及 GLB 内嵌动画播放。原 API、转发、Worker、调度、Admin、数据库、模型和云端保留期限均保持原样。以下引用检查是本机诊断，不代表普通图片/媒体已经可以自动删除。

## 如何使用

1. 打开画布的“存储空间”，点击“检查本机引用”。页面不会在启动时自动扫描全部原件。
2. 展开“普通原件及引用位置”，查看图片或媒体键、原件字节数、媒体类型和已发现的引用分类。已保存画布及可恢复回收站、素材、历史记录、旧副本、本机任务和当前页面编辑均纳入核对。
3. “有引用但缺少普通原件”表示文档引用的本机键没有对应原件。即使缩略图存在，也仍然提示缺件。保留原文档，从既有完整备份恢复，再实际打开或导出作品核对。
4. “引用尚未确认”的文件可能属于另一页面、未保存编辑、失败导入的暂存过程或不受支持的记录。此标签不提供删除建议，文件保持原样。
5. 可下载 `canvas-local-media-inventory.json`。它记录检查时间、文件标识、字节数、引用分类和告警，不含原件正文、提示词、连接配置或 Key。清单不是媒体备份，应和项目资料一起保管。需要完整作品时使用画布 ZIP。
6. 从素材库或已有 GLB 节点点击“交互预览”。有内嵌动画时会出现片段选择、播放/暂停、回到动画起点。默认暂停，切换片段也暂停；复位视图只改变相机，不替代动画复位。
7. 播放中隐藏页面会停止帧更新，返回后继续播放，并忽略后台经过的时间。关闭、离开当前页面、上下文丢失或解析失败会释放帧循环和三维资源。原件保存继续交付同一 GLB 字节。

三维浏览器只使用文件内已有数据，不加载外部贴图、解码脚本或生成服务。缺少压缩解码器、未知必要扩展或 WebGL 不可用时继续提供原件保存。已验证两条合成平移/旋转轨道；更多骨骼、形变、编码、长片段、大文件和物理手机仍待验。

## 只读扫描的数据范围

| 来源 | 检查内容 | 保留规则 |
| --- | --- | --- |
| 当前页面 | 画布、可恢复回收站和素材中的明确本机引用 | 页面内尚未保存的引用也列入；其他页面内存无法枚举 |
| `infinite-canvas` | `image_files`、`media_files`、`image_previews`、图片/视频历史、已识别的旧文档 | 原件只读 Blob 的大小和类型，不解码正文；缩略图单列 |
| `comfy-aggregator-studio:journal` | 已知画布/素材正文、迁移前副本、任务中结构化本机引用 | 未知版本、损坏正文或非文本键告警，不尝试补写或删除 |
| 生成原件 | 继续由既有素材库管理 | 本清单不替代 `studio:` 原件的鉴权、引用保护或删除流程 |

收集器沿用 ZIP 和文档的明确引用规则：识别 `storageKey` 字段及 `references` 中已有的本机前缀，不猜测普通提示词中的字面量，也不抓取外部 URL。未知记录不能被计作已完成核对。原件总字节数只合计已知内容，不含索引开销，不等于设备磁盘占用。

扫描以无版本参数打开已有数据库，所有游标事务为 `readonly`。缺失数据库的初始创建事务立即中止，保持该库不存在。检查不初始化文档、不修复索引、不写 GC 标志、不创建任务、不使用业务 API。各库及当前内存的读取时间不同，结果是诊断快照，不能作为跨库原子删除的依据。

## F-27 后续安全回收契约（设计，尚未实现）

普通图片/媒体在 `infinite-canvas`，已保存文档及任务在 journal。IndexedDB 不提供横跨两个数据库的事务。仅用“先扫引用、再删文件”会在未保存编辑、另一个页面写入或 ZIP 暂存时误删。BroadcastChannel、心跳或一段时间没响应都不能证明所有页面已经退出。

后续实现须将受控的新原件、文档、任务引用和持久占用声明放入同一数据库事务域。当前交付仍为 DBv4、文档 v1、ZIP v3；以下迁移和回收协议没有在本轮启用。

| 编号 | 后续约束 | 必须证明的结果 |
| --- | --- | --- |
| GC-01 | 新原件使用新协议及明确命名空间；与引用、暂存状态和占用声明同库保存 | 旧版普通文件保留，不被新协议推断为孤儿 |
| GC-02 | 文件写入与持久暂存占用声明在同一事务提交后，才能把新键交给编辑器或导入过程 | 文件不会在“已写入但引用尚未发布”的间隔被回收 |
| GC-03 | 文档发布核对预期修订、原件存在及完整引用，在同一事务转移暂存占用到持久引用 | 保存先提交则拒绝删除，删除先提交则拒绝悬空保存 |
| GC-04 | 未保存编辑先持久声明引用；丢失页面的占用默认保留 | 不凭超时、关闭事件或未响应心跳撤销占用，不增加隐含 TTL |
| GC-05 | 新协议以本机数据库版本及记录版本阻止已识别旧客户端写入受控域 | 升级被打开页面阻塞时停止；旧版打开失败后保留数据并要求刷新，不能降级或清库 |
| GC-06 | 全量旧文件只读复制/校验、新引用原子发布、迁移进度持久保存 | 中断后可恢复；旧库记录仍保留，不能在跨库“回滚”时盲删 |
| GC-07 | 旧客户端仍可能写旧媒体库，或来源无法确认时保留旧文件 | 不把无法枚举旧页面的问题伪装成已解决的清理机制 |
| GC-08 | 可回收状态只允许针对新协议原件；再次核对全部文档、回收站、任务及占用后，在同一事务删除 | 未知版本、损坏索引、未确认上传及任务原请求一律阻止清理 |
| GC-09 | 生成请求可能已送到原 API；迁移只能保留原请求、幂等键及任务状态 | 刷新后核对原提交或原 ID，不换身份重发，也不改原 API |
| GC-10 | 先提供显式备份与可理解的本机清理操作，自动策略需明确展示并由用户选择 | 不把诊断清单当备份，不新增默认保留期限、容量阈值或静默删除 |

新协议的占用可以在已知导入失败或已知编辑放弃后明确撤销；崩溃后无法证明已结束的占用继续保留。回收站可恢复项目仍保护原件。普通媒体回收、未知占用处置和旧文件迁移不能与原 API 的八小时云端到期、ComfyUI 移交即删或显存释放混在一起。

后续验收至少覆盖：两个页面竞争保存/删除、暂存后崩溃、发布中止、跨库复制中断、旧页持续写入、未知记录、无配额、退出时写入失败、原任务未知提交及升级阻塞。只有受控新命名空间证明这些性质后，才可启用对应本机回收操作。旧文件和不确定占用允许继续保留；不能为“腾出空间”牺牲原件正确性。
