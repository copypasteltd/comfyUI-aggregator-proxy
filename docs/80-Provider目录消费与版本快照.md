# 80 · Provider 目录消费与版本快照

日期：2026-10-25（Asia/Taipei）。关联待办 01、03、04、47、72；规则 DEV-07、12、14、21、23、24、26、27、30～32。本文先记录实现约束，实际出口和证据在验证后追加。

Provider 按 [79](./79-网关模型目录持久发布协议.md) 使用独立服务身份拉取目录，不发送客户委托头。固定逻辑 instance 与网关 ID 不随凭证轮换变化；配置文本直接验 SHA-256 后严格解析，拒绝重复字段、越界预算、错误主体/版本、未知字段和不支持的请求默认值。账户必须是已存在的、不可调度的 OpenAI 用量账户；分组必须存在且活跃。

新增 Sub2API 向前迁移 257，保存每个 instance/gateway 的不可变目录、已确认指针、模型名归属及任务目录快照。旧迁移不修改，旧任务的快照为空。全量备份和排空原生 Provider 写入后再迁移；宿主启动只探测结构，不自动运行 DDL。控制面数据库迁移保持 1b8e0c5f3247。

消费者先持久保存完整候选和模型归属，再提交 applied；收到 activated=true 才推进本地已确认指针并替换新请求规则。回执响应丢失时保留候选，重放同一回执；本地确认提交失败时下一轮从服务端确认状态恢复。错误使用固定拒绝码，上一确认目录继续可用；控制面不可用时重启从本地持久确认目录恢复。首次 managed 后不可自动回退启动规则。新版本暂未确认时保留旧版；空目录表示下架全部该网关新请求。

拉取循环有固定最小间隔、请求和停止预算，每目标串行，多个目标轮转；不在数据库事务内做 HTTP。跨进程共享本地库时目录指针单调更新，旧进程不能回退新版。新请求在余额/套餐预留的同一事务检查当前目录指针，并保存 instance/revision/digest；规则选择与版本冻结不一致时拒绝而非使用混合价格。旧幂等请求先返回原意图，重试/对账从原意图携带 stamp，不能用当前目录改写它。

规则集合使用不可变快照整体替换，所有读取不修改共享映射。已登记模型名的归属永久保留于本地库；下架后请求仍归本 Provider 处理并受控拒绝，不落入普通供应商。不同网关不能占用同 instance 的同名模型；重启同样验证冲突。

验证出口包含：真实 PostgreSQL 迁移重放与约束、HTTPS 目录/回执严格验证、首次切换、丢回执恢复、重启恢复、空目录、拒绝与上一有效版本、并发版本/资金预留、跨目标归属冲突、原意图恢复和停止清理。实际生产 Redis/S3/ComfyUI、真实 Workflow 和 10～20 台设备验收继续按 [78](./78-完整待办与首版收口清单.md) 保留；本专题不替代 Admin 图形管理交付。

## 安装及运行

先备份并验证 Sub2API 数据库归档，排空旧 Provider 写入，再通过既有迁移流程应用 257；不要从应用启动路径运行 DDL。控制面须已升级至 1b8e0c5f3247。保持既有加密密钥、服务凭证、稳定 instance/gateway 与可信 CA，网关服务应启用。启动配置的 models 现在允许空数组，适合首次由 Admin 接入；尚未 managed 时也可保留受信启动规则。配置结构见 [33](./33-Sub2API服务托管与生命周期.md)。

先在 Sub2API 配置未删除、platform=openai、schedulable=false 的用量账户，以及活跃的标准/订阅分组；它们不是生成设备。再经 [81](./81-Admin网关目录映射与发布核对.md) 选择已发布公开模型并绑定账户/分组/价格。消费者每目标最少间隔五秒、单轮二十秒预算，按目标轮转；首次确认前不宣称生效。账户或分组不可用时拒绝候选，修复后由 Admin 创建重试版本；可用空目录撤下已有模型，即使旧用量账户已不可用。最多每个实例保留 16384 个别名归属和 131072 个历史分组引用，达到保护上限后不静默丢弃旧归属。

目录回执、准入与本地金额预留共同保护新任务；已确认仅表示该逻辑实例的持久确认，不能推导所有副本实时健康。下架不会取消旧任务，也不授予额外内容权限；原属内容读取仍须通过当前客户 Key、分组及控制面内容策略。永久别名归属用于阻止误落回其他供应商，不能通过自动清库释放。
