# 83 · 原生 CI 门禁与失败证据

日期：2026-10-25。关联待办 11 及 DEV-01～03/05/25～32。本文先冻结 CI 的执行、隔离和证据规则；实际验证结果在运行后追加。六类真实 Workflow、设备、质量、S3/Redis、生产和实机容量的验收状态不因 CI 通过而提升。

## 执行边界

使用专用、受信任的原生 Windows x64 自托管 Runner。固定标签为 self-hosted、Windows、X64、render-control-native。禁止 Docker、WSL、VM、容器 services 和 GitHub 托管虚拟机；不将当前开发主机自动注册为 Runner。主分支受信任 push 和主分支手动触发，仓库变量 NATIVE_CI_ENABLED=true 才执行；不执行 pull_request/pull_request_target 中的不受信代码，不请求生产凭证。

GitHub 仅识别仓库根 .github/workflows 的工作流入口，该目录允许作为平台入口的明确例外；实现、准备/清理脚本和配置继续位于 app/，说明及脱敏证据位于 docs/。入口固定 Action 的完整提交 SHA，contents 权限只读，checkout 不持久保留认证。共享宿主上的 CI 串行排队，不通过取消在途运行释放未知资源。

## 必须门禁

| 顺序 | 检查 | 完成条件 |
| --- | --- | --- |
| 1 | 原生工具、路径及执行锁 | Windows x64 CPython 3.13、锁定 Node/媒体工具、独占 CI 锁；数据库明确为回环 55438/render_control_test |
| 2 | 文档、依赖、静态 | 文档/契约、uv lock --check、Ruff、mypy 通过；不自动升级依赖 |
| 3 | 生成物一致性 | 运行契约、OpenAPI/摘要、前端类型与当前源码相符；检查模式不修复或覆盖源文件 |
| 4 | 前端 | 两组 Node 单元及 vue-tsc/Vite 生产构建；失败为非零退出 |
| 5 | 原生 PostgreSQL 回归 | 完整 Python 套件，独立 run_id/basetemp；有效 JUnit、实际测试数大于零，无失败/错误/未解释跳过 |
| 6 | 构建 | 七个应用 wheel 可在锁定构建工具下构建；不得用无测试 exit 0 冒充完整通过 |
| 7 | 文档媒体及发布审查 | README 链接/请求/媒体与仓库敏感信息检查通过 |

CI 必须在每个门禁开始/完成时原子保存状态。某项失败或超时则本轮失败，其余尚未执行项明确标为 not_run；不能重试同一失败直到变绿或调高既有业务预算。完整数据库套件与其他重型数据库联调串行；共享测试库的 CI 还持有数据库 advisory lock。生成物不一致须作为失败由开发者修复后新开一轮。

## 环境与恢复

专用 Runner 预装原生 Python 3.13/PowerShell/Git，并提供经 config/media-tools.lock.json 验证的四个原生媒体文件；不隐式下载未知媒体工具或 ComfyUI 模型。管理员按既有 bootstrap/dev-db/migrate 流程配置专用 checkout、回环 PG 及私有 .env，迁移先备份并验证归档。CI 依赖准备仅按锁安装 Python/Node/构建工具并验证媒体，不初始化、覆盖、停止或重建数据库/配置；真实全新宿主准备继续由待办 73 验收。

所固定的 checkout/upload-artifact v6 使用 Action 自带的 Node 24 runtime，要求 Actions Runner 至少 2.327.1；与 app 内锁定 Node 工具链分开核对。版本依据为对应固定提交的 [checkout README](https://github.com/actions/checkout/blob/d23441a48e516b6c34aea4fa41551a30e30af803/README.md) 和 [upload-artifact README](https://github.com/actions/upload-artifact/blob/b7c566a772e6b6bfb58ed0dc250532a479d7789f/README.md)。Runner 还需按 GitHub 官方 artifact 网络要求允许出站；本地生成摘要不证明上传可达。

本地 Verify 和 GitHub 使用同一驱动，只使用严格限定的测试库。每轮独立临时目录，OS 文件锁及 PostgreSQL advisory lock 防止 CI 自身并发。进程运行有固定时间和日志字节上限，超时清理仅涉及自己拥有的 Windows Job Object 进程树；无法确认清理则失败并留下明确记录。退出不停止用户原有 API、Runner、GC 或 PostgreSQL。

GitHub checkout 使用专用持久工作目录，保留已配置的忽略目录，重置受跟踪源码；驱动拒绝未跟踪的源代码，避免遗留脚本进入测试发现。并发组和文件锁串行保护该 checkout。原始日志与 JUnit 留在忽略的私有目录；不得自动上传 .env、数据库、备份、journal、缓存、媒体源或整个工作区。CI 不拥有长期 PG 服务，其保留/备份/磁盘策略由专用 Runner 管理员配置。

## 公开证据

只上传严格白名单 JSON：源码 commit/摘要、固定门禁名、状态、退出码、超时、耗时、日志摘要/大小、JUnit 计数、清理结果和真实资源验收 false。异常正文、环境变量、argv 中的秘密、数据库 URL、请求/素材/提示词和原始日志均不进入控制台或 artifact。上传步骤 always 执行且仅选择本轮安全报告，保留期 14 天；无报告或摘要漂移不能当作通过。

专用 Runner 注册、NATIVE_CI_ENABLED、首次实际 GitHub 执行和失败 artifact 留存需要独立核对；本地驱动通过不能写成远端 CI 已激活。实现和本地验证可先推进，未获得真实 Runner 证据前，待办 11 保留远端启用出口。

## 操作入口

所有命令在 app 执行，使用已准备的原生环境：

```powershell
# 查看固定门禁；不连接数据库，不启动浏览器。
./.venv/Scripts/python.exe scripts/native_ci.py --plan
# 已有环境运行；每轮自动产生独立 ID，也可显式给出。
./scripts/ci.ps1 -Action Verify -RunId local-ci-20261025
# 依赖准备，不初始化/停止 PG，也不覆盖 .env。
./scripts/ci.ps1 -Action Bootstrap -RunId setup-ci-20261025
# 首次媒体准备可指定包含 bin/ffmpeg.exe、bin/ffprobe.exe、LICENSE、README.txt 的目录。
./scripts/ci.ps1 -Action Bootstrap -RunId setup-media-20261025 -MediaSource C:/ci-provision/ffmpeg-8.1
```

同一 ID 不覆盖既有日志或报告。准备阶段先验证 Win32 主机信息，拒绝已知虚拟机标识；平台标签本身不能证明物理环境。现有媒体文件摘要不符时拒绝覆盖，缺失的四项只从显式且完整验证的来源复制，不访问 ComfyUI 或下载权重。

专用 Runner 首次配置使用 bootstrap.ps1 -WithPostgresToolchain -WithBuildTools，再仅在专用全新目录执行 dev-db.py init 及 migrate.py；已有开发目录不要重复 init。CI 的 database_migrate 门禁通过固定回环/库名校验，把本轮迁移目标限制到 render_control_test，并调用既有备份/归档验证/独立迁移入口；不迁移开发业务库。完整 pytest 的后续 upgrade 在同一 head 上核对，仍保留迁移本身的真实事务用例。

公开报告位置为 docs/evidence/native-ci/<run_id>/bootstrap.json 和 summary.json；原始日志、XML、basetemp 与 wheels 位于 app/.local/native-ci*。主机上的私有日志、旧 run 与备份需要独立保留和磁盘策略，不能无界保留；不把整个目录作为 GitHub artifact 上传。远端变量启用前应确认只有受信主分支可以写入该专用 Runner；不将当前含其他项目/凭证的开发机自动注册。

本驱动覆盖公共工程门禁。Sub2API Go 组件、Provider 编译、原生三种协议模式、浏览器和正式候选安装继续使用 check.ps1 的对应 Suite 与独立证据；涉及这些实现的变更仍须执行匹配门禁，当前 CI 通过不替代那些出口。

待办 11 的远端出口依次为：在专用物理宿主准备 Runner 实际工作目录及上述测试环境；按仓库 Settings 提供的注册流程使用固定标签；配置 NATIVE_CI_MEDIA_SOURCE（已有锁定文件时可空）并启用 NATIVE_CI_ENABLED=true；从主分支执行并核对 16 项门禁和安全 artifact。再在该专用环境做一次受控依赖缺失演练，确认非零失败、摘要可下载、后续门禁未误报通过，恢复依赖后另开一轮验证。记录 Runner/commit/run_id/artifact 摘要并保留失败；不把本地模拟或 Actions 页面显示 workflow 存在当作完成。

## 本地专项与失败边界

[专项摘要](./evidence/2026-10-25/native-ci-unit-summary.json) 保留初始 33 项、扩展 42 项及锁修复后最终 43 项的全部通过记录；原始 JUnit 已移入私有目录，只公开计数和摘要。覆盖实际子进程失败、超时及所属子进程终止、日志上限、锁释放、零测试/失败/跳过/不安全 XML 拒绝、工作流权限/触发/Action 漂移拒绝，以及两个生成器在正常和漂移时的只读行为。生产环境、非回环地址、错误端口/库名/驱动在连接前拒绝。

[数据库互斥](./evidence/2026-10-25/native-ci-database-interlock.json) 已核对第二个连接被拒绝、释放后可重新领取，未改业务行。完整驱动运行期间实际启动的 [并发拒绝记录](./evidence/native-ci/ci83-concurrent-refused/summary.json) 为固定 ci_checkout_busy、非零退出、后续 16 个门禁均 not_run；没有原始日志、配置或数据库备份上传。这是本地负向证据，不是实际 GitHub artifact 验收。

首轮完整驱动暴露 CI advisory lock 与现有派单锁重复；在确认 PID/可执行文件/启动时间及父进程后，只终止所属回归启动器，驱动完成失败记录并释放自己的连接/进程树。原失败 summary 和私有日志保留，不把中止的部分套件计为完整通过。[诊断与修复验证](./evidence/2026-10-25/native-ci-lock-collision-and-fix.json) 记录旧键 634720183、新 CI 专用键 634720199，并验证持有 CI 锁时，另一连接仍可领取实际派单锁和迁移锁；并发 CI 拒绝、释放后重新领取均通过。新增跨模块锁编号回归，不能通过提高等待预算掩盖冲突。

该修复对应 CI 的 advisory 编号重复。第 82 增量记录的 Sub2API 并发鉴权 rate_states 行锁超时/502 仍未定位，继续按待办 29 独立复验；CI 通过不提升其并发容量状态。

依赖准备可复用摘要一致的成功 bootstrap；修复后的 Verify 必须使用新 run_id，不覆盖原失败。运行源码摘要复核见 [历史证据复用范围](./evidence/2026-10-25/native-ci-runtime-evidence-reuse.json)：251 项运行源及 84 项网关相关输入未变化，因此保留第 82 增量的独立协议证据；不宣称本轮重跑 Go/原生生成链路或重建旧候选。
