release_id 是不可复用的候选标识；Python 分发版本维持 0.1.0，由源树摘要和文件摘要区分构建。当前目录没有 Git 提交时 source_revision=null，不伪造 commit。release-manifest 记录格式、目标平台、Python/应用/契约版本、源树、全部 payload 文件的字节数/SHA-256、数据库 head、禁止自动迁移、Worker 协议及 journal 源码摘要、五类能力、已验证实际发布列表、固定 Sub2API commit/后端摘要和未签收边界。实际 Workflow 未提供时 validated_releases=[]，不能填测试模型作为生产发布证明。

构建只复制明确允许的产物，不复制 .env、密钥、证书私钥、数据库、Worker journal/spool、.local、测试 Redis/ComfyUI 替身、客户媒体或整份 node_modules。依赖 wheel 保留其随附许可证，固定 Sub2API 上游许可证随发布包保存。对外发布、安装系统服务和真实生产切换另按已授权目标执行；本轮在 app/.local 下构建和验证。

## 2. 完整性与安装

构建输出 ZIP、外置 SHA-256 与可独立运行的标准库安装工具。安装调用必须提供从可信交付渠道取得的归档 SHA-256；摘要只证明与给定值一致，不把同时被替换的 ZIP/摘要文件当成发布者认证或签名。

解包前完整校验 ZIP 目录、清单和所有文件：拒绝绝对/盘符/反斜杠/空段/点段/父级路径、NTFS ADS、Windows 设备名、首尾空白/点、大小写冲突、重复成员、符号链接/特殊文件、加密成员、清单外文件、缺失文件、哈希/长度不符和超出数量/字节/解压比例限制。清单 JSON 拒绝重复键与未知字段。校验通过前不创建目标安装目录；已存在的目标绝不覆盖。目标和受控暂存路径在递归删除/移动前检查绝对路径与归属，不经第二种 shell 转交文件操作。

安装创建独立 venv，仅从包内 wheelhouse 按完整锁定、require-hashes 的 requirements 安装；no-index、only-binary、no-deps，禁用网络和源码构建，不使用开发 editable 包或用户 site-packages。失败仅清理该次明确创建的目录。安装完成核对七个分发、运行依赖、契约资源和迁移文件，记录归档/清单摘要及解释器信息；venv、安装记录和运行数据与不可变 payload 分离。

## 3. 原生入口及数据保全

入口校验已安装 payload 后启动 api、runner、gc 或 worker；API 直接使用包内 Admin 静态资源，进程从显式 state_dir 运行，不读取开发目录的 .env。云端配置与 Worker JSON 使用显式文件，先校验再启动；异常只输出脱敏错误码，不输出配置正文、密钥或完整 ValidationError。TLS 由显式证书/私钥路径提供；默认 API 只监听回环，非回环绑定要求明确指定。

启动 API/Runner/GC 不执行数据库升级。迁移仍通过先备份/归档校验的专用入口，缺失工具或备份失败必须拒绝；数据库 head 与候选兼容性须在运行前检查。Worker 使用外部 state_dir/journal/spool，升级/回退不删除、复制覆盖或自动迁移未知 journal；不得强杀执行中任务、释放 GPU 未知占用或重提不确定任务。该包提供独立执行入口，生产 systemd/Windows 服务、低权限账号和 ACL 的实际安装及排空切换另验收。
