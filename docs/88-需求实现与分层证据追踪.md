## 离线门禁与维护约束

仓库根目录使用项目原生 Python：

```powershell
& app/.venv/Scripts/python.exe docs/tools/development_evidence.py --write-report
& app/.venv/Scripts/python.exe docs/tools/verify_docs.py --write-report
```

[校验器](./tools/development_evidence.py) 校验需求/验收编号全集、重复或遗漏、设计关联、具名 Python AST/Go 函数、历史实际通过记录、测试及实现文件摘要、报告摘要、证据层级、剩余待办和本文矩阵。它只读取仓库内有界文件，拒绝绝对路径、`..`、反斜杠、链接/目录联接及过大输入；不启动服务或虚拟化。文档主门禁同步执行同一检查，失败会阻断原生 CI 的 docs 阶段。

后续实现变更若触及被引用文件，应先运行适当测试，增加新的版本化证据，再调整对应引用及证据读取规则；不能只把当前摘要覆盖到旧报告中。更新机器清单后，用以下显式命令刷新可读矩阵，再审查差异：

```powershell
& app/.venv/Scripts/python.exe docs/tools/development_evidence.py --refresh-matrix --write-report
```

离线清单固定保留 `full_acceptance: pending`，不接受手改为 passed/complete。未来要签署真实验收，须另行提供资源、版本、运行记录、失败与限制，并明确扩展证据规则；不能用静态校验通过提升真实标志。新增需求/场景/删除测试/源码变化/报告变化会触发失败，而不是默默沿用旧证明。
