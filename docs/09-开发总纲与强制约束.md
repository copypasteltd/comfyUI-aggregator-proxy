# 09 · 开发总纲与强制约束

版本：开发设计基线 v0.4 · 2026-10-22。本文将已确认需求转成编码、审查与交付规则；规则已落文档不表示功能已实现。

## 1. 范围、权威与变更

需求见 [01](./01-需求规格与约束.md)，业务行为见 [02](./02-系统架构与任务机制.md)～[08](./08-APIKey鉴权与访问控制.md)，实现约束见本文及 [10](./10-技术栈与工程结构.md)～[16](./16-开发任务分解与交付清单.md)。[契约目录](./contracts/README.md) 中的 JSON 供静态校验和将来的契约测试使用，不能当成服务已存在的证据。

优先级为：用户明确指令 → 根目录 AGENTS.md 的环境限制 → 已确认需求与强制不变量 → 已接受的接口/数据契约 → 实现细节。机器契约与文字冲突时必须同步修复，不能任选有利的一份。文档 03 的示意 ID 不要求 UUID 语法；真实 ID 格式由文档 12 统一。

影响公开字段、状态、鉴权、计量、调度、数据库、原生运行环境的改动，须先提交变更说明，列出涉及的规则 ID、兼容行为、迁移与验证，再一起更新实现。普通修复按现有授权推进；需要用户决定的范围变化才另行提出。首次建工程时登记依赖精确版本与锁文件；不得在编码时把“待验证”默认为“支持”。

## 3. 固定业务不变量

- 一个业务 job 仅有一个当前有效 attempt；同一 attempt 可有多个历史租约代数，旧代数不能完成任务。一个 GPU 生成槽可在上传前释放，但 job 结果权继续有效，不能因 GPU 已释放误接收其他 attempt。
- 未知执行不进入可重试池。只有“未提交”或“已停止且产物处置明确”等证据允许重新领取；隔离失联机器后允许灾难重算时必须记录人工决策和重复算力风险。
- 本地对象不是交付完成；云端对象大小、哈希、媒体规格和不可变版本验证后才发布 manifest。ETag 不代替通用 SHA-256。
- 可见 Key 策略已收紧，则新的授权读取不能沿旧缓存放行。已接收任务按冻结规格/路由完成，生成并发仍按当前资源上限；禁用 Key 不自动取消旧任务。
- 同一客户任务在网关和任务服务有稳定绑定；付款、退款、最终结算不能靠非幂等回调各做一次。图片/视频资源额度不是第二套货币余额。

## 4. 完成定义

一个开发项只有在代码、契约/迁移、匹配风险的验证、错误路径、权限审计、运行配置和文档同步后才可标记完成。每份证据写清版本、环境、命令、时间、结果和覆盖边界，不能只有截图或“测试通过”一句话。

设计审查通过只表示可以实现。协议模拟通过只表示控制协议行为；真实 ComfyUI、实际工作流质量、10/20 台设备、网络吞吐、Sub2API 客户余额与下载策略须分别联调。缺少硬件时保留真实设备验收为未完成，不阻止独立的文档/协议开发，也不能发布成完整首版已验收。

代码审查优先检查：是否新增绕过身份/状态/配额的入口、是否改变 GPU 与结果所有权、是否在故障中重复提交、是否泄露共享候选或内容、是否有未设上限的后台活动。命名、格式、类型和静态扫描由工具承担，避免仅凭人工浏览判断分布式正确性。

Worker 新领取与提交前容量门禁、缺少观测时拒绝新派单、同 boot 单调观测、一小时确认后保留及有界清理规则以 [44](./44-Worker容量保护与本地产物保留.md) 为实现补充。不得为了兼容旧 Worker 默认为容量正常，也不得在压力下提前清理未确认或未到期产物；已提交任务的恢复、租约和回传须继续执行。

重复失败保护见 [46](./46-生成失败归因与规格隔离.md)：固定失败码须以实际 prompt 的受控事实归因；未知停止不能变成可释放状态。规格隔离在物理 GPU 锁内持久裁决，只影响新客户领取，显式管理验证可检验修复；恢复验证不批准环境、不更改渠道、不取消任务，也不解除未知占用或管理保留。

已确认失败的内部重试以 [82](./82-确认失败重试分类与跨GPU约束.md) 为当前分类补充：明确未提交的准备传输失败与有完整当前 prompt 停止证明的白名单 OOM 共享两次预算；OOM 每任务最多一次，必须使用原冻结路由内另一当前批准的物理 GPU。绑定的期望/应用/验证摘要须与冻结发布一致，原 OOM GPU 跨后续准备重试继续排除。不得把新 Worker 能力推断为旧 API 已支持，也不得将缺少扩展证明的旧 Worker 事件自动重跑。

## 正式范围补充：ComfyUI 音频产物

正式范围已增加 ComfyUI Workflow 音频产物。开发必须同步扩充任务/能力契约、Worker 产物适配、实际音频媒体校验、分层配额与计量、内容交付、图形 Admin 和 Sub2API；不能仅放行扩展名/MIME 就标记支持。沿用原生运行、无 Docker/WSL/虚拟化、四类身份、未知执行不放锁及测试浏览器 finally 清理约束。音频扩展以 0.5.0 冻结，Worker 协议继续 0.4.0 并使用显式能力声明；旧 Key 和父级默认无音频权限/额度。范围见 [54](./54-ComfyUI音频产物范围与开发约束.md)，实现契约与分层证据见 [55](./55-音频契约与兼容迁移.md)。

## 122 · 显式 HTTP 渠道例外

按用户明确指令，无主机管理端的 ComfyUI 可使用独立 Linux 原生 Worker，显式开启 allow_api_only 与 remote_http。采用 comfy-api-only-v1 声明 API 版本/节点/模型选项，回执 environment_verified=false、api_profile_verified=true，不能替代本地 Git/权重摘要核验。仅发布真实调用通过的受控 Workflow；云端 GPU 槽、journal 与未知提交核对规则继续适用。容量 scope=worker_spool 只代表 Worker 本机，02 位于其 Linux spool；01 原文件尚不自动删除，03 仍保留八小时。部署示例与完整约束见 [122](122-RTX5070纯HTTP接入与调用验证.md)。
