# 151 · 已发布预设工作流分类归档

用户要求把合并前已发布的 45 个 Workflow 按路径归类，保留在当前版本供后续调用。范围固定为 15 个图像、6 个视频、10 个音频、14 个 3D 入口；179 个未发布候选不混入可调用预设。

## 归档契约

- 工程目录采用 `app/workflows/presets/`，按媒体类型、调用类型和既有模型别名建立独立目录。每项保存真实执行图的可移植副本、原生画布、参数绑定、公开 usage、请求示例、不可变发布标识和逐文件摘要。目录索引列出全部 45 个别名及设备。
- 原生设备在 `workflows/平台预设/2026-11-16/` 中建立相同分类的可编辑画布副本。保留源设备现有文件，不覆盖、不移动、不删除；只新增本批拥有的路径。
- 业务 API 的模型别名、冻结版本、路由和限额保持当前配置。画布副本不会自动回写冻结版本；需要发布新能力时继续通过既有验证和发布流程。
- 工程副本将媒体输入、用户文本、输出前缀替换为明确示例；设备专用绝对路径通过独立本地配置还原，不把主机私有路径或客户素材放入公开仓库。发布标识中的摘要指向服务端原始冻结 manifest，文件摘要指向归档副本，二者不得混淆。
- 所有媒体/参考槽位须由调用者上传并填写；目录整理不提交生成，不把可见、可打开或历史验证等同于当前设备实时生成验收。
- 通过已有源 Workflow 写入协议部署，先持久化操作身份，未知响应使用原操作恢复；逐文件回读校验。沿用用户原有设备占用，不释放这些占用，不重启 Windows、ComfyUI 或生产生成服务。
- 原生浏览器转换与打开检查在独立 Key 工作区执行；所有本次创建的浏览器资源在 finally 中关闭。禁止本地 Docker、WSL 或其他虚拟化环境。

## 使用边界与后续更新约束

1. 搜索模型别名定位预设。画布保留输入占位符，调用前必须填入自己上传的素材及文本；共享目录编辑会反映到源机，个人修改另存 `@personal`。
2. 当前节点声明缺失、模型选择失效或扩展控件不兼容仍可能阻止原生运行。本次未检查主机权重文件，也未执行生成；截图中的红框按真实状态保留。不能把文件已保存和已打开称作生成成功。
3. 前端的数值步长可能改变字面值，例如 518 变为 520、204800 变为 200000；预览状态和第三方 LoRA 控件也可能不同。完整 API 模板在独立文件及画布 `extra.platform_preset.workflow_api` 中保留，供核对和后续恢复。源站原冻结发布不受这些画布差异影响。
4. 新增或替换节点/模型需要另行验证依赖、设备画像、输入输出和业务生成，再发布新的不可变版本；不能静默修改旧摘要或把 179 个未发布候选混入此目录。
5. 后续新建日期版本目录并复用归档器、转换器、摘要核对和源写入的持久操作记录；同步本编号目录、中英 README、更新日志、相应媒体与 Git 远端。原生路径和公开仓库不保存 API Key、会话、真实客户素材、权重文件或设备私有绝对路径。

本轮未使用本地虚拟化、未启动常驻服务、未重启设备或生产服务；所有本次浏览器已关闭。原始冻结版本继续由服务器数据库保存，受保护导出及设备路径映射保留在本地忽略目录。Skill 1.5.1 的现有调用协议继续可用，此次没有修改 Skill 内容或重发 Skill。
