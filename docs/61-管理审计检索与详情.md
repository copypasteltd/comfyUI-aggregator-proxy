# 61 · 管理审计检索与详情

2026-10-24，第 61 增量。本地实现、原生数据库恢复、浏览器与精确候选安装验证通过；完整首版和真实设备出口保持原范围。

## 首版缺口与交付

现有 Admin 审计页只能翻页，未展示请求 ID、已有版本或关联操作信息，无法检索一次渠道/Workflow/模型/Key 变更。本轮交付有界审计查询、安全详情、明确的版本记录和完整图形筛选/关联查看，推进 ADMIN-11、KEY-12、WP-02/08/09/10/13/14，遵守 DEV-14/15/17/23/25/26/27/28/29/31/32。

业务 API Key 仍只用于对外生成和内容 API，不得访问此页或管理审计接口。管理会话仍要求 audit:read；当前为已有全局管理角色权限，不宣称已有项目级管理员授权。审计查询不改变任务、GPU、配额、凭证、结算、事件或记录保留期。

## 查询契约

沿用 GET /admin/api/v1/audit-events，不新增路径和业务 scope。机器形状冻结在 contracts/admin-audit-query.schema.json；应用契约保持 0.5.0，Worker 0.4.0。查询字段封闭：page 默认为 1、最多 10,000，每页最多 50；actor/action/resource/request_id 为可选精确匹配，created_from/created_before 为 Unix 秒的半开时间窗。所有过滤取交集，拒绝未知字段、控制字符、布尔/小数数值和颠倒时间。

actor 使用已记录的主体 ID 或 system/runner 等固定主体名，最长 128；action 为小写动作编码、最长 128；request_id 为字母数字与点、横线、下划线、冒号组成的 1～128 字符。resource 接受规范 UUID 或带前缀的公开资源 ID，服务器统一为存储的 UUID；不把用户输入作为 SQL。时间为 0～4102444800 的整数秒。

保留原 Page 的 data/page/has_more 和原 AuditView 字段，增加 total、snapshot_at、filters。列表与总数使用同一 PostgreSQL REPEATABLE READ READ ONLY 快照，固定 UTC、5 秒语句和 1 秒锁等待预算；失败返回固定脱敏错误，不把上次成功快照标成当前结果。每次翻页重新取快照，不承诺跨 HTTP 页冻结数据库历史。

[86](./86-数据库故障脱敏诊断与并发观测.md) 保持上述响应与预算，另将固定 SQLSTATE/原因写入本次请求的脱敏日志。85 的历史分页超时及 86 的注入/恢复证据分别保留，不把后续通过当作历史根因已解决。

AuditView 增加可空 actor_name、revision_before/revision_after、operation_id 以及 detail_redacted。历史记录未保存的内容返回 null，不从当前配置倒推过去版本，也不补写历史。关联主体名称以本次查询的当前名字标注，历史主体 ID 不变。详情从此次返回的有界安全行展示，不增加一个未授权的任意资源读取入口。

## 安全投影与写入

详情只允许固定的版本/数量/布尔、受限状态/角色/原因编码、公开标识和摘要，不返回任意历史 JSON、Worker 回执正文、渠道地址/密文/凭证、策略正文、Workflow 图、提示词或媒体。最多读取 16 KiB 的单条 detail，超过上限在 SQL 投影中改为空并标记已隐藏；未知键、错误类型或超长值同样隐藏，不能靠截断正文泄露前缀。列表最多 50 行，当前主体名称批量解析，禁止 N+1 查询。

具有版本的管理变更新写入明确的 revision_before/revision_after；创建记录的 before 为 null。沿用既有 revision 的历史记录只可提供已知 after。渠道相关命令保存 operation_id；历史缺失不伪造。所有补充字段仍与变更、审计和 outbox 同事务提交，幂等回放不产生第二次变更。对没有配置版本概念的任务/回执事件保持未知，不发明版本。

运行画像批准的新记录以实际变更版本的渠道为资源，详情关联 Workflow 发布；旧记录保留原绑定资源且不回填版本。单渠道绑定与批量同步均按目标渠道写入版本和操作关联，汇总操作继续保留。

新增迁移 f96c8a3d1025（前序 e85b6c2d9014），只为 audit_events 加创建时间及 actor/action/resource/request_id 的五组检索索引，无新增业务表、不删除记录、不改变已有 JSON。开发与测试库变更前先原生备份并验证归档；恢复核对迁移前实际行和升级/降级的索引状态。大生产库索引耗时/部署窗口须另实测，不把本机小库时间当生产承诺。

## 图形交互

沿用现有 Admin 的深色导航、浅色工作区、蓝色操作色和等宽标识。审计页的工作是还原一次管理动作：顶部为主体、动作、资源、请求和时间筛选，明确“应用筛选/重置”，表格显示可识别动作、主体名/稳定 ID、资源、时间与详情入口；详情按“动作与关联 → 版本 → 已记录的安全补充”排布。提供“筛选同一请求”和关联操作入口，只作导航，不自动执行指令。

保留首屏加载、无记录、失败和最后成功快照；切换筛选回到第一页。隐藏、离页、会话失效时取消请求、释放定时器并关闭详情；恢复可见先复核会话再取快照。390px 下筛选可折行、详情适配视口；键盘可操作并有明确标签。已有操作中心继续使用原页面；审计拥有独立页面，不在通用组件里继续堆条件。
