# 60 · 数据库、对象与密钥联合恢复校验

2026-10-24，第 60 增量。本地实现、分层验证、开发库联合演练与精确候选安装已通过；不据此签收完整生产恢复。

## 要补齐的交付能力

现有 restore-rehearsal.py 只恢复 PostgreSQL 并核对表行数和迁移版本，不能检出相同行数下的内容变化，也未证明对象字节、渠道密文和业务凭证 pepper 可恢复。本轮新增通用只读恢复校验，以及原生数据库、文件副本和密钥重载的联合演练。图片、视频和 ComfyUI Workflow 音频复用此流程。

交付为 contracts 的 recovery-checkpoint 契约、infrastructure/restore_verification.py、独立 scripts/verify-recovery.py，以及 scripts/joint-restore-rehearsal.py。适用 DEV-07/09/10/18/23/25/26/27/29/30/31/32，推进 WP-03/05/13/14，不删减原首版出口。

## Checkpoint 与只读校验

1. Checkpoint 版本 1，应用契约仍为 0.5.0，Worker 仍为 0.4.0，无 DDL。它记录创建时间、随机 nonce、数据库 revision、按名称排序且唯一的表名/行数/HMAC、对象媒体计数/总字节、加密主密钥 canary、pepper canary/version，及整个文档的 HMAC-SHA256 签名。不得包含 DSN、原 Key、主密钥、pepper、提示词、文件正文或对象路径。
2. 使用独立随机恢复密钥文件；不把它放进 checkpoint，不复用运行主密钥或 pepper。逐表 HMAC 将 nonce、表名、列元信息及长度分隔的完整 PostgreSQL JSONB 行编码绑定，按实际主键排序；恢复后须全行一致，不能只比较行数。签名先验证，再访问恢复库或对象存储。重复 JSON 字段、未知字段、过大文件、无效签名均拒绝。
3. 数据库连接在 REPEATABLE READ/READ ONLY 事务中读取，固定 UTC、锁/语句超时，检查实际 public 表集合与安装代码模型一致。元数据行、单行字节、对象数量、累计对象字节和总运行时间均有限额。网络传输不持有行写锁；校验不修改租约、任务、GPU、账本、GC 或任何业务数据。
4. 通过独立 canary 核对恢复主密钥、pepper 和版本；解密当前渠道、历史渠道 revision、冻结 attempt 和 Worker command 中的渠道密文，只计数，立即丢弃明文。不从不可逆 verifier 恢复客户 Key，不打印密文/明文或 SDK/数据库异常原文。
5. 对所有尚未物理删除的对象，保留原 key/version，逐个从配置的存储有界读取、计算长度与 SHA-256。完整读取还核对同一打开文件句柄的 fstat 长度，或同一次 S3 返回 Content-Range 的总长度，防止只读取正确前缀而漏掉尾部追加。包括到期和待回收但仍在物理存储的记录；已确认物理删除的对象不复活。S3 继续遵守文档 59 的版本/Range 校验及私有版本化桶预检。
6. 相同原版本的对象需先由存储提供方备份/复制流程恢复，再执行 verify。工具不伪造 S3 VersionId、不替换 object_records 中的历史版本、不自动创建/公开桶，也不声称完成实际 S3 对象备份。
7. 成功表示当前数据库完整行、原版本对象字节和运行密钥与 checkpoint 一致。它不等于可以开放派单：活动 job、GPU 占用、在途网关资金及 Worker journal 仍须按文档 15 核对。工具不启动 API、Runner 或 Worker，不自动清理占用、重发任务、结算或批准 Workflow。

## 原生命令与演练

verify-recovery.py 提供 keygen、snapshot、verify；配置、恢复密钥与 checkpoint 路径必须显式传入，不从当前工作目录隐式加载 .env。输出仅为固定代码和脱敏数量；失败非零。新文件独占创建，写完 flush/fsync；有界解析 checkpoint 和恢复密钥。安装候选携带此入口，使用其自身解释器及运行包。

在 app 目录执行的开发入口示例（对应文件名须尚不存在）：

```powershell
New-Item -ItemType Directory -Path .local/private -Force | Out-Null
.venv/Scripts/python.exe -X utf8 scripts/verify-recovery.py keygen --recovery-key-file .local/private/recovery-v1.key
.venv/Scripts/python.exe -X utf8 scripts/verify-recovery.py snapshot --config .env --recovery-key-file .local/private/recovery-v1.key --checkpoint .local/backups/readonly-checkpoint.json
.venv/Scripts/python.exe -X utf8 scripts/verify-recovery.py verify --config .env --recovery-key-file .local/private/recovery-v1.key --checkpoint .local/backups/readonly-checkpoint.json
```

默认上限为总行数 1,000,000、单行 8 MiB、对象 10,000 个、对象总量 64 GiB、300 秒；可用 --maximum-rows/--maximum-row-bytes/--maximum-objects/--maximum-object-bytes/--maximum-seconds 显式收紧。硬上限分别为 1,000,000、32 MiB、10,000、1 TiB、3600 秒。语句上限 30 秒、锁等待 1 秒。运行账号须限制私密目录读取权限；Windows ACL 由部署账号配置，工具的文件模式不代替 Windows ACL。checkpoint 与独立恢复密钥须分别备份保管。

原生联合演练仅使用本项目回环开发库/本地对象适配，在已登记开发 API/Runner/GC 停止后运行，复用迁移 advisory lock；生产或 S3 配置明确拒绝此演练入口。源库使用一致导出快照，先 pg_dump 并 pg_restore --list 校验，再恢复到新建且精确跟踪的一次性数据库；复制每个未物理删除的原版本文件并验证摘要，以新配置文件重新加载相同运行密钥、pepper 和独立恢复密钥，再用通用 verifier 比较完整行及对象。源库不写入，恢复库不启动调度，finally 清理本次恢复数据库、文件与秘密副本。

演练命令为 `.venv/Scripts/python.exe -X utf8 scripts/joint-restore-rehearsal.py --recovery-key-file .local/private/recovery-v1.key`。原生归档和私密 checkpoint 保留在 app/.local/backups，输入的独立恢复密钥保留在私密目录，以便后续验证；本次临时恢复库、对象副本和重载用秘密副本均在 finally 删除。只把脱敏数量、摘要和清理结果写入 docs/evidence。

另以完全隔离的合成目录验证输入图片及图片/视频/音频产物、跨 Key 拒绝/授权 Range/HEAD、渠道密文、业务凭证实际鉴权，以及活动/未知执行与结算记录未被改写。损坏对象、同数量篡改行、错误主密钥/pepper/恢复密钥、篡改签名、缺少版本文件与超限应被检出。协议/合成产物不代表真实 ComfyUI 质量，原生开发库若无存活对象也须如实记录数量。
