## 2. 兼容输入契约

保留七种已有任务类型、原 source_image/mask/references 和 1.0～1.2 Workflow。新增 `input.media`，元素只允许 `slot` 与 `asset_id`；新增 `input.texts`，为命名字符串映射。客户不能提供本地路径、节点 ID、模型权重名、URL、工作流或 shell。

Workflow 1.3 用 `input_slots` 声明每个槽的 name、kind（image/video/audio/model）、label、description、required、max_bytes、mime_types 和 path_mode；`text_slots` 声明文本用途及长度。绑定来源为 `media:<name>` 或 `text:<name>`。所有声明都必须实际连接到最终输出，未声明、重复、缺少必填或未消费输入一律拒绝。一个请求最多 16 个素材槽、16 个文本槽，总文本最多 32,000 字符。旧图不能因升级而接受新的未声明输入。

素材类型由上传入口显式选择 `kind`，默认 image；实际内容再验证。图片 20 MiB、音频 256 MiB/600 秒、视频 512 MiB/120 秒、GLB 512 MiB；还需服从冻结槽位的更小上限。视频仅 MP4/WebM，音频沿用完整解码校验，网格沿用自包含静态 GLB 校验。输入仍归原 Tenant/Project/Key 所有，默认 24 小时；非终态任务引用沿用已有保留保护，不能跨 Key 引用。

旧 references 数组继续最多四张图片；命名素材可以包含最多十六张图片。Key 的 `max_references` 默认仍为四，Admin 可显式设为零到十六；上传媒体的数量、种类和用途仍必须符合该发布版本。上传 multipart 只允许一个 file 和一个可选 kind，重复字段、额外文件或字段拒绝。Sub2API 同步扩展原生 `/v1/assets` 及 `/v1/jobs` 的命名输入；新增 259 迁移扩展类型、字节及非图像尺寸约束，保留原素材所有权与不可变绑定。已有 Sub2API 的 3D 计费隔离仍单独处理，不能套用图片价格。

`comfy_relative` 用 ComfyUI 确认的输入相对路径；`comfy_absolute` 仅由具备本地 ComfyUI 目录的原生 Worker 解析到 input 根内的实际文件。HTTP-only 渠道不能假造 Windows 绝对路径，应拒绝不兼容的版本。上传回执只接受 input 目录，受控随机文件名和禁止覆盖继续适用。

1.3 显式声明使用参数：未声明的 seed、fps、strength 等不能被接受后悄悄忽略。结构化脚本和曲谱是受限文本，不作为命令或文件路径执行。声音策略与父任务资源另有逐项实现及验证；没有实现前不能在 discovery 中声称支持。

对于时间线与说话人配置等既有 JSON 字符串，绑定可携带 RFC 6901 `pointer`，只替换运营者冻结文档中已存在的标量叶子。不同槽位分别注入文件名或原样文本；不接受客户 JSON 文档、结构替换、追加字段、重复键或非有限数字。单文档最多 1 MiB；整字段绑定与嵌套绑定重叠会被拒绝。这样可分别传入分镜提示、共享参考图与参考录音转写，而无需调用方修改原图。

动作迁移可只提供正式声明的图片/视频素材，不强制传入未被流程消费的提示词。时长以毫秒为最小单位，使用精确十进制校验；34.157 秒合法，34.1571 秒拒绝。续拍的公开时长扣除继承且被裁掉的上下文帧：124 帧、22 帧上下文、24 fps 的续拍交付 4.25 秒，而不是把继承帧重复计入。

### 声音与续拍资源

1.3 视频输出可声明 `audio_policy`：generated、source_video、reference_audio、silent；后两种有声来源必须指向必填的视频/音频素材槽。冻结图负责实际声音连接，云端验证最终音轨有无，不把条件音频等同于无损保留；需要保留原声音的发布包直接连接源音频至合成节点。来源、音轨验证与听感验收分别记录。

续拍请求使用 `input.context.job_id`，仅引用同一 Tenant/Project/Key 的成功父任务。父任务须主动产出已验证的 H3 AV safetensors 上下文，发布包的兼容摘要必须相同。上下文不是公开上传/下载素材，不接受 URL、本地路径、pickle 或用户提交的张量。独立对象保留 8 小时，非终态子任务引用保护；完成前未持久化上下文的生成任务不能成功。Worker 通过当前租约和 fencing 拉取、核验摘要、写入 ComfyUI input，并使用 journal 恢复上传。公开 usage 声明是否可续拍、是否产出上下文及兼容范围，不暴露设备路径。

经 Sub2API 调用时，父任务使用 Sub2API 返回的 `rc_…` ID，由网关按当前用户及 Key 查询并转换为已冻结的同一目标服务内部任务 ID；不能直接引用其他 Key、其他目标服务或客户自报的内部 ID。幂等摘要仍按客户原始请求计算，重放不因父任务后来到期而新建计费。

原生依赖锁可增加 `files`，逐项记录 `custom_nodes/` 下已有节点代码及必要配置的相对路径、SHA-256 和字节数。用于记录非 Git 安装及现场已适配源码；不自动下载或执行文件，不包含 `.git`、缓存和客户输入输出。单文件最多 64 MiB、最多 2,000 项；Worker 同步时校验现有文件，摘要不同即拒绝。原有 Git 提交与模型权重锁继续适用，不能用空锁冒充依赖完整。1.3 的 `output_basename` 为经过摘要的任务唯一文件基名，供拒绝目录分隔符的原生导出器使用；不接受客户文件路径。

## 3. 发布与验证约束

遵守 DEV-01～03、07～20、23、25～32。新增输入不得绕过准入配额、当前 Key 检查、幂等、资源范围、GPU fencing、Worker journal、未知提交核对、产物校验或保留机制。仅新 Worker 显式支持的版本可调度，旧 Worker 不接收 1.3 图。

每个模型采用稳定 ASCII alias 和可读显示名，功能不同的模式区分命名；名称中的 2K/4K 以实际可验证规格为准。固定模型、声音、参考角色、主产物和内置辅助资源都写进版本说明。任何尚未真实验证的候选保留未发布状态。

开发、数据库、媒体工具及远程设备均使用原生进程，不使用 Docker/WSL/虚拟化。浏览器在 finally 关闭本次创建的 page/context/browser，保留用户原有会话。阶段验证不等于完成 ALL-01～09；最终须逐项核对线上权威状态。
