# 28 · API Key 访问记录实现约定

2026-10-23，设计基线 v0.4。补齐 WP-02/09/10 的访问追踪，涉及 DEV-14/15/16/23/25/26/27/28/29/32。先增加契约和 PostgreSQL 表，再接入 HTTP、Admin 与保留清理；不改变现有任务、配额、GPU、货币账本或 Worker 协议。

## 记录归属与内容

仅记录 `/v1/` 与 `/gateway/v1/` 业务 HTTP；每个服务器生成的 request_id 最多追加一条。管理、内部 Worker、静态文件和健康检查不计作客户访问。方法只保留标准 HTTP 方法，路径只保留服务端匹配的路由模板；未匹配路径使用固定通配标签。禁止保存原始路径参数、查询串、Authorization、Cookie、请求/响应正文、提示词、签名 URL、外部主体头或 User-Agent。

本地凭证先按不可还原 verifier 校验，再确定逻辑 Key。已撤销/过期的真实凭证、停用 Key、IP 拒绝、限流和业务拒绝可以归入该 Key；只知道 identifier、错误 secret、缺失或错用身份不能归属到某个客户。轮换继续归入原逻辑 Key。无可信归属的请求只写匿名记录，不出现在任意 Key 的查询中。

网关请求必须先通过服务鉴权与来源限制，再按当前服务下的显式绑定确定 Key；客户自报外部主体头不能建立归属。已验证绑定对应的停用 Key 可记录拒绝。受信网关提供的客户 IP 与实际连接 IP 分开保存；未通过验证的头不入库。只有服务身份的结算请求无 Key 归属。

追加字段为 UUID、tenant/project/key/gateway 归属、服务器 request_id、开始/记录时间、入口类别、标准方法、路由模板、连接/客户 IP、HTTP 状态、受控错误码、单调时钟耗时、收发字节计数和响应完成状态。计数指 ASGI 实际消费/成功发送的字节，不宣称客户端已收到；下载中断仍可能有 200 响应头，必须同时显示未完成状态。

## 持久化与可用性

新增 `access_events`，迁移是加表、约束与索引，旧客户端不受影响。tenant/project/key 要么全部为空，要么通过复合外键指向同一 Key；网关 Key 还通过复合外键指向同服务的显式绑定（该绑定增加冗余唯一约束作为引用目标）。入口类别、完成状态、标准方法、状态码、非负大小/耗时有检查约束。request_id 唯一；按 `(key_id, created_at, id)` 与 `(created_at, id)` 索引支持查询和清理。历史记录不随逻辑 Key 删除。

记录在响应完成、断开或异常后追加，不在处理过程中缓存正文；不以 HTTP/日志请求持有任务事务锁。访问日志不参与任务/收费正确性，写日志失败不能把已受理任务改成失败并诱导客户换 ID 重提。采用独立、无空闲连接池的短事务，每进程最多 2 个写入，连接 3 秒、语句 2 秒、锁等待 500 毫秒；超载不排无界内存队列。匿名失败最多记录每进程每分钟 30 条，超出只累计数量。

写入失败、容量丢弃与匿名采样分别计数；脱敏警告每类每分钟最多一条。Admin 返回本 API 进程启动以来的写入健康快照，明确其会随进程重启归零，不能证明历史完整或多副本整体状态。进程崩溃/日志写入失败可能丢记录，访问日志不能充当完整账本或财务审计。

默认保留 30 天，配置 `GEN_ACCESS_LOG_RETENTION_DAYS` 可设为 1～365。查询按服务端当前保留窗口过滤；Runner 每轮最多删除 500 条到期记录，按行锁 SKIP LOCKED 避免副本互相阻塞，不删除任务、计量、终态 outbox 或管理审计。

## 读取契约与界面

`GET /admin/api/v1/api-keys/{identifier}/access-events` 沿用冻结契约的 `keys:usage`，当前仅 administrator 具备该权限。业务 Key、Worker、网关服务凭证及观察者均不能读取。API 当前的管理员是全局角色；不把尚未实现的项目级管理范围写成已支持。

可选 `result=all|success|denied|error`，默认 all；可选 `before` 为有长度/版本校验的不透明游标。成功为完整的 2xx/3xx，拒绝为完整的 4xx，错误为 5xx 或未完整交付。每页最多 50 项，固定初次查询快照上界并按记录时间/ID 倒序续查；游标绑定 Key 与筛选，不能因换 Key 或换筛选混入其他记录。不接受任意排序、原始 SQL 或无界页码。

响应包含 Key 的安全标识/名称/启停/逻辑删除时间、snapshot_at、retention_days、data、first_cursor、next_cursor 和 capture_health；first_cursor 让返回首页仍沿用原截止时间。该上界不是跨 HTTP 请求保持的数据库 MVCC 快照，迟提交或保留删除可能影响后页，刷新可开始新查询。明文 Key、verifier、原始请求、外部身份引用和账本授权引用不得出现。停用或逻辑删除的 Key 仍可读历史；未知 Key 返回 404，非法游标/筛选返回 422。

Admin 在 Key 行提供“访问记录”，进入独立详情页，显示主体、保留窗口、成功/拒绝/错误筛选、时间/接口/结果/IP/耗时/字节/请求 ID，以及加载/错误/空状态。只在显式刷新/翻页请求数据；换 Key、筛选、离开页面和隐藏页面取消旧请求，取消后不能用迟到响应覆盖新主体。返回上一页使用有界游标栈，重启查询清空旧快照；不创建额外轮询或 SSE。

首次直达或会话过期后重新登录，保留已解析的站内路径，清除查询串与 hash；不读取外部 redirect 参数。登录后仍按当前会话权限控制页面，不能通过保留路径绕过权限。

## 验证出口

使用原生 PostgreSQL 与真实 ASGI HTTP 验证成功、授权/IP/限流/校验拒绝、未知 Key 不误归属、轮换与撤销、网关显式绑定、同一 request_id 唯一、复合归属约束、游标快照/过滤/资源绑定、跨角色与身份拒绝、过期清理边界、响应中断、日志写失败/容量饱和不改变已处理响应及秘密不落库。浏览器使用真实 HTTPS/数据库验证入口、筛选和拒绝记录，finally 关闭本次浏览器；固定响应只能另记为界面测试。

迁移前通过项目原生备份入口验证归档；执行迁移后做 schema drift 和恢复演练。测试通过只证明相应数据库/HTTP/界面行为，不替代真实 Sub2API、设备、媒体和规模验收。实际结果见文档 17。
