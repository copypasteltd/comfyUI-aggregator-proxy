# 30 · 网关请求关闭与恢复协议

2026-10-23。接续 [20](./20-网关准入与对账实现约定.md)、[25](./25-Sub2API原生适配实施约定.md) 与 [29](./29-Sub2API持久意图与账本事务约定.md)，涉及 DEV-07、11～15、23～27、29～32。本文先冻结服务端关闭与查询协议；实现和实际验证结果另记于文档 17，不能提前宣称完整 Provider 已接通。

## 请求身份与权限

增加两个仅限已验证网关服务身份的接口：

| 方法与路径 | 行为 |
| --- | --- |
| POST /gateway/v1/admission-requests/lookup | 按完整意图身份读取最小准入状态，不创建记录、不返回客户正文或媒体 |
| POST /gateway/v1/admission-requests/close | 与准入创建互斥；未创建则持久关闭，已有 pending 则安全撤回，confirmed 不回退 |

JSON 请求固定为 provider_request_id、external_task_ref、price_version、authorization_ref、external_tenant_ref、external_key_ref，不能混入生成请求、客户 IP 或任意任务 ID。前三类稳定引用与已持久 Provider 意图一致；外部主体只由认证上游记录构造。请求规格见 [机器契约](./contracts/gateway-request-identity.schema.json)。使用 POST 是为避免把预授权引用放入 URL；lookup 仍是只读操作。

服务凭证、允许来源网段和网关自身归属照常检查。此处不要求客户 Key、绑定或租户仍启用，避免撤销授权后无法清理旧预留；只允许查询/关闭该服务原请求，不具有新建、confirm、运行中任务取消、内容读取或后台管理权限。其他网关端点继续按当前业务策略鉴权。关闭不存在的请求也须由本服务完整身份认证，不提供匿名查询。

## 持久化与锁

新增 gateway_request_fences 表，保存网关、请求 ID、公共任务引用、价格/预授权引用、外部主体和 closed_at。网关内 provider_request_id 与 external_task_ref 分别唯一；不保存提示词、客户凭证、IP、金额或素材。迁移从现有 admission 与原绑定回填，先备份核对再执行，不能通过删任务腾出标识。

新 admission 创建在同一任务事务最先插入/锁定 fence，核对完整身份，再执行既有幂等、配额、Key、发布、资产和任务写入。closed_at 非空则明确拒绝，即使更换正文、重试入口或原请求晚到，也不能创建或恢复任务。外部任务引用被另一个请求使用时返回冲突；不让唯一约束异常成为 500。

数据库触发器再次锁定并检查同一 fence，拒绝绕过应用仓储的旧写入、关闭后的写入及绑定/价格/预授权错配；admission 的绑定身份不可变。fence 身份不可修改、记录不可删除、已关闭记录不可重新开放；存在 admission 时不能直接把 fence 改成 closed。迁移锁定相关表并回填、核对历史记录后安装这些约束；部署时停止旧 API 写入，备份迁移完成再启动新版，不混用协议写入版本。回退不能删除已有关闭证明。

close 同样先锁 fence。没有 admission 时写入 closed_at，关闭标识固定为 gcl_ 加 fence UUID；之后不得删除或重新开放该记录。存在 admission 时使用原 admission 行锁及原终态记账事务撤回 pending；已经 confirmed 的任务保持原状态。锁顺序为 fence → admission/幂等 → 既有配额和任务锁；其他处理路径不得在持有后续锁时反向锁 fence。

并发 create/close 必有一个先获得相同 fence：关闭先提交则创建失败；创建先提交则关闭读取原任务，只能撤回未确认准入。事务失败全部回滚；关闭回执丢失可用完整原身份重复 close/lookup。只读 lookup 返回 unknown 只是观测结果，不能作为退款或换 ID 重提的依据。

## 响应与账本衔接

响应回显六个身份字段，以及根据已认证服务生成的 gateway_id；status 为 unknown/admitted/closed，另有 closure_id 与 admission：unknown 两者均空；closed 只有稳定 closure_id；admitted 只有原 AdmissionView。身份不匹配或相同任务引用换请求 ID 返回 409。禁止把准入状态、闭锁状态或 job 状态相矛盾的响应视作有效证明。

只有 closed 证明旧请求在该服务下永远不能创建远端任务。Provider 必须将目标 gateway_id 随预授权意图持久保存，再核对服务、实例、完整身份及关闭标识，在自己的同库事务中保存证明并释放原预留；不能按临时更换的凭证或当前配置猜测旧意图归属，也不能仅凭 404、HTTP 成功码、unknown 或当前客户 Key 停用就退款。Go 客户端的请求身份须显式绑定预期 gateway_id，回显不符即拒绝。账本消费按 [29 的关闭证明增量](./29-Sub2API持久意图与账本事务约定.md) 实现和验证；它使用独立 ReleaseClosed 事务，不借用 ReleaseUnsent 或伪造结算事件，恢复循环仍是后续接线出口。

admitted 即使已经 aborted/expired/rejected 也仍具有原 job 与唯一终态事件；Provider 继续使用现有结算/ack 协议。confirmed 后的任务由原运行与取消协议管理，close 不授权绕过客户策略中断执行。后台服务只得到最小准入投影，不得到生成请求或产物内容。

fence 属于持久防重记录，不能按短期访问日志保留策略清理；未来归档必须保留拒绝迟到请求的权威标识。close 使用独立服务恢复速率桶，默认每分钟 120、突发 20；该桶先于 fence 锁定，不占客户新建额度。lookup 仍受通用服务鉴权速率限制，但不写恢复桶或防重记录。元数据读写与 HTTP 仍遵守现有时间/字节上限，不在数据库事务里进行远端调用。新增客户端方法显式单次调用，不自动重试；写入结果不明时保留原预留。

## 验证出口

使用真实 PG 检查关闭先于迟到创建、并发 create/close、重复关闭与进程重建、已提交准入回执丢失、pending close/confirm 竞争、已确认任务不回退、撤销 Key 后可清理、主体/引用冲突、服务间隔离与错误 realm 拒绝。Go 元数据客户端检查 HTTPS、无客户主体头、完整回显/状态约束和写入不确定性。只运行已审查的本项目测试，不运行上游容器测试。

完整 Provider 还需将已验证的关闭证明消费接入派发恢复循环，并完成租约/退避、上游路由、媒体、用量/缓存消费者、套餐与跨服务原生进程崩溃验收。既有四阶段验收、五类 Workflow 和 10/20 台实机范围不变。

2026-10-23 实测：含关闭协议、数据库保护和迁移回填的 [完整 Python 回归](./evidence/2026-10-23/python-tests-request-fences.xml) 220 项通过，耗时 185.67 秒；新增 39 项包含 27 项 PG/HTTP 用例及 12 项冻结契约/DTO 用例。创建/关闭、确认/关闭各进行 8 轮竞争；故障注入验证关闭与审计共同回滚，直接/旧写入被数据库拒绝，关闭记录不能删除、重开或变更归属。应用重建验证持久记录，不计为真实进程崩溃；完整跨服务四阶段验收仍未完成。

[关闭消费之前的 Go 客户端报告](./evidence/2026-10-23/sub2api-controlclient-tests-before-closure-consumption.json) 为 14 项顶层测试、28 个子用例通过，耗时 77.63 秒，覆盖独立服务身份、六项引用回显、目标网关校验、状态矛盾和回执丢失不重试。服务端使用真实本地 PG 的 ASGI HTTP，客户端使用原生 HTTPS 协议服务；这两层不冒充完整 Sub2API 服务与控制面的跨语言运行联调。
