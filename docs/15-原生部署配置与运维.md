## 1. 进程与网络

云端首版：HTTPS 反向代理、control_api、control_runner、PostgreSQL、Admin 静态资源，外加私有 S3 兼容存储和既有 Sub2API。原生 Linux 服务由 systemd 管理；各服务独立低权限账号，API 不运行迁移，Runner 使用数据库锁可多副本。现有网关依赖 Redis 时按其原生要求配置，不把 Redis 变成项目任务唯一源。

Windows：每台机器一个 Worker 管理本机登记 GPU/ComfyUI 实例，ComfyUI 保持独立环境并默认回环监听。Worker 服务账号仅能读批准输入/模型清单并写 journal/任务目录，不用管理员权限执行每个任务。服务封装在 WP-00/14 选择并固定版本；原生开发后台进程使用 `Start-Process -WindowStyle Hidden`，登记 PID，结束时仅清理本次启动者。

公共443只路由客户 API、Admin和下载；internal/gateway 另绑定私网监听并配置反向代理白名单，不能因为路径名字有 internal 就认为受保护。数据库只对 API/Runner/备份账号开放，Worker 不直连。SSE 代理关闭缓冲并设置合理空闲超时，文件代理开启流式背压，禁止读整个视频再返回。

本机开发数据存 `.local/`；正式 Windows 运行数据路径由部署配置指定，建议低权限账号专属数据目录，journal 与唯一产物不放临时目录。此建议不是授权在当前任务向项目外写文件。任何生产实例路径/ACL/配额必须登记后再创建。

所有“初值”是可调整设计参数；容量/时长/磁盘未实测时不能把它们写成用户设备承诺。数值与文档01/03统一，今后修改需同步相关契约和验收配置。配置单位体现在字段名/Schema，禁止把毫秒/秒或MiB/MB混用。secret file 应限定服务账号读取，备份/诊断默认排除。Range/HEAD 与普通GET采用同一授权和并发预算。

固定 Sub2API 的配置可选 public_origin 为受信 HTTPS 纯源，显式 URL 返回需要它；禁止从客户 Host/Forwarded 拼接链接。sync_wait_milliseconds 省略或 0 采用默认 60,000，其余允许 1～60,000；同步等待最多 8 个，媒体并发最多 8 个，单流缓冲 64 KiB。Provider 元数据请求为 30 秒、同步图片入口为 90 秒、下载为 300 秒，宿主写预算另加 5 秒；反向代理预算须与之匹配。媒体最长 2 GiB、内联图片 32 MiB，客户端和控制面限制继续生效；这些边界不构成带宽承诺。

新增 251 产物归属迁移必须与 247～250 一起单独演练和安装。先备份并验证可读，再运行上游迁移流程；启动只读检查关联表，不能以安装 Handler 替代迁移。该链仅在随机测试库验证，应用开发库保持原 Alembic 版本；完整 Sub2API 服务未启动。

素材/编辑增量另需 252 上传意图及归属表，旧 247～251 不改。受信 upload_directory 可为配置文件旁的相对路径或绝对路径，省略时为配置旁 render-control-spool；必须位于本应用持久工作目录，限制服务账号读写，不接受链接目录或客户文件名作为路径。素材/编辑共用两个上传槽，正文最多 128 MiB、单文件 20 MiB、64 KiB 复制缓冲；仅读本请求随机文件，finally 关闭并删除，不扫描用户文件。共享编辑路由选择模型时也遵守预算，转交原上游时重放原正文和 Content-Type。

素材/编辑入站读取预算为 60 秒，完整上传及异步编辑为 180 秒、同步编辑为 240 秒，远端素材上传为 90 秒；同步生成仍为 90 秒，元数据/下载沿用 30/300 秒，宿主写预算另加 5 秒。反向代理、磁盘配额及服务账号 ACL 须按此配置；这些初值不构成生成时延承诺。上传回执不确定时保留持久意图，后继相同请求按原网关和幂等键恢复，不能换目标重传；详见文档 35。

## 3. 初始化与上线步骤

1. 在原生测试环境固定应用、锁文件、数据库、Node/Python、Worker协议、ComfyUI/节点/模型和Sub2API版本；只安装批准来源，记录哈希。
2. 创建最小权限数据库/存储账号，初始化主密钥与独立管理账号。初始管理员通过一次性本地管理命令创建，秘密不进脚本/日志，无默认密码；该命令在 WP-02 实现。
3. 单独执行 Alembic 迁移并检查版本；启动 API/Runner，只开放回环/测试私网。启动时readiness验证数据库migration/必要存储能力，不以GPU可用与否混同API进程存活。
4. 登记节点身份/凭证、物理GPU、ComfyUI实例和渠道。Worker恢复journal后探测/扫描，应用desired版本并回执；导入/验证Workflow、批准画像，再发布公开别名。
5. 在Admin配置测试Key，执行授权、隔离、队列、取消和文件策略测试；固定Sub2API Provider端到端对账。未联通时模型保持未公开，不向客户暴露空能力。
6. 按文档14门禁分批接入10/20台，记录带宽与算力；启用监控/备份/日志轮转后签收发布清单。生产域名/证书/网络策略另经实际环境验证。

| 存储/下载 | 上传失败/重试/校验失败、带宽/出站、代理并发/内存、生命周期待删；背压与断点恢复 |
| 控制面 | API延迟/错误、PG连接/锁等待、outbox最老年龄、管理P95新鲜度；不要把20Worker心跳量当全部流量 |
| 账本 | 预留与job不一致、终态结算pending/重复、孤儿公共ID；幂等对账并保留证据 |

高基数 job_id 不作为监控标签，放日志/trace；提示词和Key不进指标。告警阈值需在试运行记录后配置；严重不变量破坏先暂停相应能力/派单，再通过受审计恢复工具处理。

[84 · 指标与脱敏关联](./84-监控指标与脱敏请求关联.md) 提供两个独立监控身份的只读入口、固定分类指标、专用只读 PG 池、五秒缓存、容量覆盖与失效语义、十类外部告警规则及原生 promtool 检查。原生 CLI 生成新凭证文件，只输出 SHA-256；部署配置与安全响应读取同一严格阈值模型。规则和日志具备本地验证不等于生产采集、日志轮转、通知及处置已部署，待办 68 继续独立验收。

## 5. 备份、恢复与灾难处理

数据库、对象不可变版本、渠道加密密钥和网关绑定需有一致恢复策略。Worker journal 保存在各节点持久盘并可受控备份；云端数据库备份不能替代它。首次上线前选择数据库备份/PITR和对象版本/保留方案并演练RPO/RTO，证据记录真实值，不只验证备份文件存在。

恢复流程：停新准入与领取 → 隔离旧API/Runner写入 → 恢复DB/对象/密钥 → 全节点进入reconciling → 对照journal、Comfy进程/输出、云对象和网关账本 → 确认每个旧槽/attempt/预留 → 小批开放。恢复较旧DB后不允许直接扫描queued全部重发。

Worker磁盘损坏/节点永久失联且执行未知时，隔离该节点的网络/凭证和生产调度，保存灾难决策记录。确认旧实例不再提供有效结果后才由受控策略新建attempt；可能发生重复计算，但只能发布/结算一个结果。不能靠人工直接DELETE occupancy来“解卡”。

删除/GC分两阶段：标记不可新引用、等待活动引用与保留约束解除，再按对象key/version删除并确认。上传失败/待确认唯一输出优先恢复而非清理。敏感诊断仅收集版本、脱敏错误、摘要和指定日志，不打包整个客户任务目录。

## 第 57 增量：Worker 启动与身份接管

完整约束见 [57](./57-Worker启动身份与原生进程保护.md)。本增量没有 PostgreSQL DDL，沿用 `d62f7b08a9e1`；新增本地 SQLite 身份元数据及 Windows Global 节点 mutex。先升级控制面，再排空、核对并停止旧 Worker，最后升级 Worker。旧进程不认识新 mutex，不能与新进程并行；不同设备也不能共享同一凭证。

升级前保管原配置、凭证和 journal。先以同一运行账号执行 `--validate-config`：预检不创建 state、不取得锁、不注册，也不证明服务端接受凭证。凭证必须是 Admin 导出的双字段 JSON。正式运行时新 Worker 为全部内部请求附带 `X-Worker-Node-Id`；新控制面在事务前拒绝凭证配错节点，Worker 也核对注册回执的 node_id/boot_id。旧控制面忽略该头时不能提供注册前的保护，因此部署顺序不可倒置。

含运行事实且未绑定身份的旧 journal 默认以 `journal_identity_unbound` 拒绝启动。确认原节点、控制面和在途事实后，在同一启动命令增加 `--adopt-legacy-journal`；先在 state_root/identity-backups 写入一致备份并校验，再绑定，不重置尝试、claim 或管理指令。备份失败、超时、超限均拒绝继续。首次成功后去掉接管参数；它不能覆盖已有身份。保留备份及原始 journal 的运行账号访问限制。

`worker_node_in_use` 表示本机同一身份已有进程；先查原进程，不改目录绕过。`journal_identity_mismatch` 应恢复正确配置；不删除身份表。mutex 在崩溃后可被接管不代表 GPU 已停止，未知提交必须继续核对。正常停止会等待实际本地线程结束后才释放资源，禁止用强制终止代替排空。新增元数据的旧版本回退、跨账号/服务会话 ACL、生产升级与对象/主密钥联合恢复仍需独立演练。
