# 27 · Worker 元数据响应边界约定

2026-10-23，设计基线 v0.4。落实 DEV-09/10/19/25/26/29/32，补齐 Worker 对 ComfyUI 元数据的读取边界。本文不改变公开 API、Worker 线协议、数据库结构或配置文件；现有 Worker 使用固定的保守上限，实际环境超限应调整并验证，不能静默忽略。

## 读取预算

所有 ComfyUI JSON 通过统一的同步/异步流式读取器处理。先检查状态及响应头，再逐块读取；编码前和解压后的字节均受上限约束。不能先执行普通 GET/POST 将响应完整缓存，再检查 content 长度。

| 元数据 | 字节上限 | 其他约束 |
| --- | --- | --- |
| prompt 提交与图片上传回执 | 64 KiB | 必须是 JSON 对象；prompt_id 为 1～128 位 ASCII 字母、数字、下划线或连字符，禁止路径和查询字符 |
| system_stats | 256 KiB | 必须包含对象类型的 system |
| queue | 2 MiB | running/pending 均为列表，每组最多 1,000 条；异常不视为空队列 |
| history | 8 MiB | JSON 对象，最多 1,000 项；条目与 status 必须为对象 |
| object_info | 16 MiB | 最多 10,000 个节点类，类名非空且最长 256 字符；值必须为对象 |

只协商 identity/gzip；gzip 使用标准库增量解压，并在解压器内限制每次输出。拒绝其他编码、重复 gzip 成员、尾随数据与截断压缩流，避免先解压出无界正文。Content-Length 只能提前拒绝超限，缺省或虚报不能绕过实际流量计数。JSON 按 UTF-8 严格解析，拒绝非对象、非有限数值、超过 64 层或 500,000 个值的结构；结构遍历使用有界深度的迭代器栈。

每次请求在现有禁止跳转、禁止环境代理的基础上使用连接/读取/连接池等待各 5 秒、写入 20 秒上限；元数据读取预算为 30 秒。异步路径以总超时取消请求；同步路径在响应头、每块读取和解析结束检查总预算，正在阻塞的单次网络读取最多再占用 5 秒。同步线程不以“线程取消成功”虚构已经中断底层请求。所有正常、超限、解析异常、网络异常和取消路径关闭响应，调用方仍负责关闭其 HTTP 客户端。

## 执行与管理语义

提交 prompt 前必须已经持久化 journal 的 posting。POST 发出后发生超限、非法 ID、解析错误、超时、HTTP 错误或连接丢失，均属于提交结果未知：保留同一 association/attempt，禁止自动重新 POST、换机或释放 GPU。同步提交适配报告 submission_unknown；异步执行进入现有隔离与恢复流程。

恢复查询遇到无效/超限 queue 或 history 时返回 unknown，不能据此确认 absent，更不能给出 safe_to_resubmit。即使有效响应未找到关联，也继续禁止直接重提。运行中 history 格式错误同样不能当成执行停止的证据。

队列观测保留 reachable=false 和脱敏错误码；管理探测、清单扫描和诊断失败只回传受控错误，不记录响应正文、渠道凭证或完整 Workflow。扫描超限不会把渠道标为已验证。图片上传回执必须给出安全的相对文件名及 input 类型，不能用其覆盖或读取任意本地路径。

## 验证出口

协议测试使用有实际 close/aclose 记录的分块传输，覆盖普通及 gzip 超限、虚报/缺省长度、压缩截断和尾随数据、非法 JSON/对象、取消与时间预算、跳转不跟随，以及 POST 后 journal 重启恢复和只发一次。同步及异步执行入口均须有未知提交验证；管理和队列观测验证错误不会伪造空闲。

这些是本机 HTTP 协议与 journal 证据，真实 ComfyUI、代理压缩行为、节点清单规模和五类 Workflow 仍需另行验证。具体测试数量和运行结果仅在执行后登记到文档 17。
