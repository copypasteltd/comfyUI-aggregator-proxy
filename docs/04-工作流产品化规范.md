# 04 · 工作流产品化规范

## 1. 产品单位

对外销售的单位是一个有明确输入、质量档、输出和资源要求的能力版本，而不是一份任意 ComfyUI JSON。

一个公开模型别名可以对应一个冻结工作流和多个经过验证的硬件运行配置。客户请求接收后，将实际 workflow release、权重哈希、节点版本、预设、seed 与价格一同冻结。修改旧 JSON 或替换同名权重不能悄悄影响已排队任务。

工作流的功能门槛与资源门槛分别验收：能生成样本不证明能在所有显卡稳定运行；低显存能跑也不证明达到商用等待时间。

首版由 Web Admin 提供 Workflow、底层模型文件、公开模型及渠道能力绑定的管理入口，具体交互见 [Admin 专项设计](./07-Admin可视化管理后台.md)。公开客户仍只提交受控参数，管理端导入权限不开放给客户 API。

## 2. 五类能力的标准输入与语义

| 能力 | 必需输入 | 可公开的受控参数 | 关键语义 | 不允许的替代 |
| --- | --- | --- | --- | --- |
| 文生图 | prompt | size、quality、seed；负面词仅在模型支持时 | 从文本生成一张完整图片 | 把内部 step/CFG 任意开放而无资源边界 |
| 图生图 | prompt、source_image | 输出尺寸、重绘档/strength（若支持）、seed | 保留哪些结构、允许多大变化需定义 | 把单图参考模型当成支持精确蒙版编辑 |
| 多参考文图生图 | prompt、有序 references≥2 | role、可选已验证权重档、size、quality、seed | 每张图是人物/场景/风格/物体等何种条件 | 接受多张但仅连接第一张；把批处理当多参考 |
| 文生视频 | prompt | size、seconds、quality、seed；fps 若确实可变 | 文本驱动动态场景；音频能力独立声明 | 先出图再运镜却无说明地宣称等价原生文生视频 |
| 多参考文图生视频 | prompt、有序 references≥2 | role、size、seconds、quality、seed | 人物/场景/风格多条件如何作用于整段时间 | 仅有单首帧或首尾帧，却宣称任意多参考视频 |

“首帧”“末帧”是时间约束；“人物参考”“场景参考”是条件约束，不能相互隐式转换。若实际方案为“多参考出一张关键帧 → 单图生视频”，可以作为显式两阶段能力发布，但必须说明中间结果、保真限制、耗时和整体计费；不能把它作为已经实现原生多参考视频的证明。

2026-10-23 兼容增量：允许 `references_to_video` 的单图 `first_frame` 形式，只能进入恰好绑定 `reference_0` 的发布包；参考槽位必须连续且数量一致，指定权重必须实际绑定。它是首帧引导输入，不构成 CAP-05 多参考能力验收；完整规则见 [38](./38-标准化参考输入与Workflow选项.md)。

## 3. 能力清单字段

每个公开模型至少说明：

| 分类 | 必需内容 |
| --- | --- |
| 标识 | public_model、capability、release_version、发布时间、active/paused/deprecated |
| 输入 | prompt 长度；图像类型/大小/解码上限；source/reference/mask 的数量与关系 |
| 参考图 | min/max 张数、数组顺序、允许角色、默认槽位、角色组合、是否支持多人物 |
| 尺寸 | 枚举或明确范围、宽高倍数、总像素上限、支持的画幅、裁切策略 |
| 质量 | 公开档位对应的固定预设；不同档位的时间和价格依据 |
| 视频 | 时长枚举、帧数规则、原生帧率、是否插帧、是否有音轨、编码与容器 |
| 参数 | seed、负面词、strength、参考权重等参数的类型、范围、默认值和互斥关系 |
| 资源 | 硬件档、峰值 VRAM/RAM、磁盘、模型加载、执行/编码/上传预算 |
| 输出 | 主产物数量、MIME、尺寸、媒体校验、预览图和元数据要求 |
| 费用 | 规格计量单位、价格版本、失败与取消策略 |
| 证据 | 测试环境、样本集版本、成功率、异常样本、平均/P50/P95、许可证资料 |

缺失的能力不显示为可用。公网能力详情不泄露模型磁盘路径、内网地址和节点凭证。

## 4. 工作流发布包

以下目录为发布内容的逻辑分解示意；当前 Admin 使用冻结的 JSON `WorkflowManifest`，不读取下列 YAML 目录布局。[93 · 离线发布包工具](./93-真实Workflow离线发布包构建.md) 已提供从现有本机依赖生成 `manifest.json`、来源记录和校验和的实际入口。模型与节点代码不复制到包中，实机批准仍通过现有渠道验证完成。

```text
workflow_release/
  manifest.yaml             # 能力与依赖、运行画像
  workflow_api.json         # 可提交给 /prompt 的 API-format 图
  request_schema.json       # 客户可调参数与组合限制
  bindings.json             # 受控参数 → 固定节点输入的绑定
  output_adapter.json       # 最终输出选择规则，必要时引用受控适配代码
  dependency_lock.json      # ComfyUI、自定义节点、Python、模型哈希
  presets.json              # quality/size/seconds → 可执行参数
  benchmark.json            # 硬件档的资源与耗时测量
  samples/                  # 用例输入、seed、期望语义与已检查输出索引
  provenance.json           # 权重/插件来源、许可与发布记录
```

API-format 工作流必须实际通过 API 提交验证，不能将编辑器用于展示 nodes/links 的 UI 工作流直接作为 API 模板。模板、绑定与输出适配器一起版本化。

自定义节点源码属于服务的受信执行代码；发布时固定提交与依赖。运行任务时不自动更新节点、联网下载模型或执行用户指定脚本。

## 5. 发布清单示例

下面为说明结构的占位示例，数值和节点 ID 不构成对真实模型的推荐或测量结果。

```yaml
release: example-text-image@1.0.0
public_model: render-image-v1
capability: text_to_image
status: draft
template_sha256: cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc
input:
  prompt_required: true
  min_reference_images: 0
  max_reference_images: 0
parameters:
  n: {enum: [1], default: 1}
  size: {enum: ["1024x1024"], default: "1024x1024"}
  quality: {enum: ["standard"], default: "standard"}
  seed: {type: integer, minimum: 0, maximum: 2147483647}
bindings:
  prompt: {node_id: "6", input_name: text}
  seed: {node_id: "3", input_name: seed}
output:
  adapter: save-image-v1
  final_node_ids: ["9"]
  expected_count: 1
  mime_types: [image/png]
  max_bytes: 33554432
runtime_profiles:
  - id: gpu-profile-to-be-measured
    approved: false
    peak_vram_mib: null
    peak_ram_mib: null
    warm_p95_seconds: null
    cold_p95_seconds: null
    execution_timeout_seconds: null
```

`approved: false` 的画像不能用于生产准入。资源、时长或许可证未就绪时，发布门禁保持 draft，而不是用猜测数值填充。

## 6. 参数编译规则

1. 先按能力 schema 校验参数及其组合，再解析公开档位。
2. 将公开 quality/size/seconds 映射为发布包中的固定预设；记录 effective_parameters。
3. 复制不可变模板，只允许修改 bindings 白名单中指定的输入。
4. 输入图片映射到本任务隔离路径和经过验证的节点槽位；输出文件名前缀由服务生成。
5. 提交前检查节点类型、权重、预设与运行画像一致；记录最终图的摘要。
6. 不做全文件字符串替换，不按显示标题猜节点，不接受客户指定 node_id 或 checkpoint_path。

公开 `quality` 不等价于一个通用 steps 数值。每个模型可以采用不同步数/采样器/精度预设，客户看到的是已测试的质量档。`seed` 在首次接收时补齐，重试不再次随机。

模型原生支持的画幅可能要求 8/16/32 等倍数，视频帧数也可能有特殊公式。必须从选定工作流声明规则；不假定所有模型都使用相同倍数或 `frames = seconds × fps`。

## 7. 五类工作流的额外要求

### 7.1 文生图

- 至少冻结一个生产档与对应横竖/方形画幅，具体数量由实测与产品取舍决定。
- 中英文提示词分别有样本；若模型不善于某种语言，文档说明或提供显式翻译功能，不暗中改写客户 prompt。
- 原生负面提示词、透明背景、超分、文字准确性分别声明支持，不随 OpenAI 参数存在而自动承诺。
- 如果有超分或后处理，作为工作流整体的一部分纳入时间、显存和最终输出验证。

### 7.2 图生图

- 明确源图是构图约束、内容参考还是潜空间重绘输入；三者不是同一种功能。
- strength 若开放，应覆盖低、中、高档验证，检查语义方向是否符合用户理解。
- 定义原图与输出尺寸不同时使用缩放、裁切还是留边；执行前保存归一化策略。
- 蒙版编辑只有在独立样本验证通过后开放；核对 mask 尺寸、alpha/黑白含义和未遮罩区域保留规则。

### 7.3 多参考图与文本生图

- 客户输入的数组顺序端到端保持；每一张参考图均有稳定 index 和 role。
- 定义支持的是同一人的多视角、多个人物、人物加场景，还是风格参考；不能笼统保证这些全部等价支持。
- 有参考权重时设定离散可测试档；不把任意浮点权重和任意图数的组合全部开放。
- 若内部使用拼图/接触表或预处理合成，必须作为有损转换明确记录并实测，不能宣传成未经验证的原生多图输入。
- 对每个参考槽位做替换和移除对照，检查确实影响目标属性，而非只处理第一张图。

### 7.4 文生视频

- 固定已支持的离散时长和分辨率组合；长时长可能需要更大资源画像，不能只按分辨率匹配 GPU。
- 元数据同时报告请求时长和实际时长；选定编码方案应给出帧级容差，避免静默裁切补齐。
- 默认可交付基线建议为 MP4、H.264、yuv420p、明确帧率；原生输出若需转码，计入工作流后处理。
- 没有音频就声明 `has_audio:false`；不得给无声音轨的结果宣称对白、配乐或音画同步。
- 原生生成帧、插帧与变速分开记录；不要靠重复帧延长来冒充更长生成。

### 7.5 多参考图与文本生视频

- 至少有双参考样例，支持的人物/场景角色需写入能力清单；高于两张的上限通过每个组合实测后开放。
- 单首帧、首尾帧、参考人物跨帧一致性分别做用例，不能相互借用验收结论。
- 检查参考角色在首、中、末段的约束效果；接受视频文件可播放不代表参考条件已实现。
- 若要音频输入、对白、唇形或多镜头，需要新的工作流契约；不混在“多参考视频”这一名称里默认承诺。
- 原生多图模型不可用时，保留选型缺口；可另外评估明确标注的两阶段方案，但完整目标的 CAP-05 是否满足必须单独判断。

## 8. 输出收集与校验

ComfyUI 输出适配器需要按节点类型解析，支持图片文件、视频文件或自定义输出记录。只选择发布清单中的最终节点；预览、临时帧、调试图不作为收费产物。

| 产物 | 自动校验 |
| --- | --- |
| 图片 | 可解码、尺寸/像素与规格匹配、编码/MIME 一致、字节上限、数量、SHA-256 |
| 视频 | 容器可读、视频流存在、帧尺寸、时长容差、帧率、编码、音轨声明、可抽取首中末帧、字节上限 |
| 缩略图 | 与主产物关联、尺寸/格式正确，不单独冒充主成果计费 |

文件出现不等于写入结束。依据节点完成事件、文件写入稳定和媒体探测确认后再上传。路径应位于已配置的任务输出根目录，防止错误节点返回任意文件；Windows 路径使用安全 ID，不把 prompt 或客户文件名直接拼为目录。

默认交付文件不携带完整 ComfyUI 工作流、内部路径或密钥信息；需要保留的生成元数据通过经过筛选的 API 字段提供。删减元数据不能删除必要的署名/许可要求。

## 9. 质量与资源基准

建议每类能力准备至少 20 个基础语义用例，覆盖中文/英文、横竖画幅、人物/物体/场景、低/中/高压力输入。每个公开规格必须有执行记录；基础用例总数不能代替规格组合覆盖。

多参考能力额外包含顺序交换、第二张图替换、移除参考、角色冲突等对照。质量评估由维护者查看样本，区分“生成有效”与“条件满足”；自动媒体校验无法证明角色一致性和审美质量。

每个硬件画像测量冷加载、热执行、模型切换、峰值显存、主机 RAM、编码、文件大小和上传时间。至少有连续运行样本，并保留失败样本；样本量不足时不报告具有误导性的高分位承诺。

发布前冻结可接受的质量评分表，例如提示词主要对象、构图、参考角色、视频时序与明显伪影。阈值由产品样本评审确定，不能仅用“看起来不错”作唯一验收标准，也不把单次 seed 的好结果当稳定能力。

## 10. 版本与发布流程

```text
候选工作流 → 依赖盘点 → API模板与参数绑定 → 功能样本
→ 硬件画像 → 质量评审 → 故障/恢复验证 → 小流量灰度 → active
```

发布包不可变。修正模板、节点、权重或默认预设形成新 release；公开别名可以在新请求入口切换，但已接收任务继续使用旧版。旧依赖只有在无排队/执行/恢复任务引用后才能移除。

回滚只影响新接收请求，活动任务按其冻结版本继续或明确失败处置。禁止通过直接覆盖 Windows 同名 checkpoint 来完成全设备热更新。

## 11. 选型产出与当前缺口

下一阶段应得到五份能力发布记录。可共享同一个底座模型，但须分别验证五类输入语义；每份至少给出一套可生产画像、实际样本和一套失败边界。

当前尚无设备清单、已安装权重/插件清单、现有工作流、视频时长目标和质量样本，故本轮不虚构具体模型选择或显存门槛。选型表应包含：候选、已有部署、能力是否原生、参考图语义、许可资料、峰值资源、吞吐、质量、稳定性、决定与未通过原因。

## 12. 首版 Admin 导入、同步与发布

1. 管理员可上传 API-format JSON/发布包，或选择已登记渠道，由 Worker 从授权目录/清单导入。每次保留来源、模板摘要和差异，先进入草稿，不自动赋予生产可执行权限。
2. 页面提供能力/参数/输出表单、API JSON 编辑、模型依赖选择和版本对比。UI-format 工作流需完成受控转换与实际 API 校验后才可作为模板；无法解析时列出缺失字段或节点，不能保存成假成功发布包。
3. 冻结版本后可选择一个或多个渠道分发模板/参数绑定/清单，逐渠道校验 ComfyUI、自定义节点、模型哈希、输出适配与配置版本。探测清单、同步模板、通过样本、批准画像分别显示，不合并为一个含糊的“已同步”。
4. 模型清单扫描区分文件名、类型、哈希与校验时间；未知或同名异哈希时标记待核实/冲突。权重分发、插件安装和环境升级不在任务运行时自动执行，缺失依赖在后台明确列为阻塞。
5. 功能验证通过且资源画像经批准后，管理员建立渠道能力绑定。依赖、地址/实例或关键环境变化使验证失效，绑定停止新派单，完成重新验证后恢复。
6. 在公开模型管理页选择 Workflow 版本、允许渠道、规格和价格版本引用，并执行发布。Sub2API 映射确认后才显示对外生效；失败保留上一有效版本或未发布状态，操作可恢复和重试。
7. 停用/回滚影响新准入，活动任务保留原发布包与依赖。删除工作流/模型登记须检查任务和发布引用；界面删除不直接移除 Windows 文件。禁止以覆盖同名权重实现不留版本的升级。

发布门禁是首版 Admin 的真实功能，不得由后台维护者手改数据库绕过。实际 Workflow/模型供应情况仍待 M0 盘点，不能因为后台能导入就宣称五类能力已就绪。

## 正式范围补充：ComfyUI 音频产物

音频是 ComfyUI Workflow 的正式产物，继续使用草稿、冻结、同步、绑定、模型与依赖清单、样本验证和运行批准。发布版本必须声明输入参数、输出节点、允许格式和音频规格；Worker 音频适配以实际 history/文件样例验证，客户端不能覆盖图或任意路径。任务、输入和格式清单尚待冻结，详见 [54](./54-ComfyUI音频产物范围与开发约束.md)。
