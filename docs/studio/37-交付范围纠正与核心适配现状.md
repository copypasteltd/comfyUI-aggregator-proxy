## 后续开发与验收约束

1. 先确定当前请求会改变哪个已有用户流程，优先修改现有组件和适配器。没有明确需求或具体缺陷，不因历史待验自动增加功能。
2. 涉及生成链路时，检查获准模型发现、合法输入/参考、显式提交、原任务查询、结果取回和保存。已通过且源码未变的证据可注明复用；合成接口证明映射/UI，真实 API 证明实际执行，两者不互换。
3. 服务端失败保留原任务和说明；画布不得修改 API、直连 ComfyUI、重建队列、静默换模型/Key重提。未签收能力不宣称可用。
4. 仅运行受影响的验证。新静态版本检查自身资源/业务路由和存储兼容；纯文档修改检查内容一致性、链接和源码未变，不重复生成、构建或录屏。
5. 汇报本轮改动和具体未解决问题；可选项和外部依赖分开，不再每轮把46行当成全部未开发清单。双语说明及更新记录同步到独立功能分支。
