## 实施与迁移边界

固定上游归档和原版目录保持原样。本项目维护 app/integrations/sub2api/overlay/backend 中的新增文件，验证脚本从已核对 SHA-256 的归档构建独立工作目录；生成副本应用文档 32 的鉴权补丁与文档 33 的组合根补丁，两处文件均受精确替换及摘要门禁约束，不修改 go.mod/go.sum，不执行上游测试。新增 247～250 迁移与已有迁移一起由上游 ApplyMigrations 执行，不修改已执行迁移的摘要。测试使用本项目原生 PostgreSQL 内新建的随机命名空库，DDL 前保存并校验空库备份，finally 删除本次创建的库；不连接其他项目或生产库。

原生检查入口为 app/scripts/check.ps1 -Suite Sub2APILedger。Go 测试程序在自身执行迁移前还要核对实际服务地址、端口、随机测试库命名与空库条件；不能仅信任环境变量中的 DSN。测试子进程验证非测试库会在迁移前被拒绝。此检查只查询本项目原生实例的系统库元信息，不对系统库执行 DDL。应用的 Alembic 开发库与其迁移版本不参与此增量。

此原生测试库仅允许 127.0.0.1:55438，显式使用 sslmode=disable；固定 Go lib/pq 默认 require，而本地开发 PG 未启用数据库 TLS，不能沿用 psycopg 的默认行为猜测连接模式。该设置不适用于远程或生产数据库。重复验证复用本脚本登记的独立工作副本，逐文件核对固定上游和此前补丁摘要；维护源码以外的修改、未知文件或越界路径会拒绝，固定原版目录仍不改动。目录解析按父目录缓存，源码核对限时 180 秒。运行用例显式 -vet=off，gofmt 另行检查；不宣称上游依赖 Go vet 已通过。

原生测试程序的缓存身份包含固定源码/Go 工具链归档摘要、go.mod/go.sum、全部叠加源码与共享客户端摘要、编译参数和平台环境，命中后仍核对二进制摘要；失配则在 app/.local 重新编译。test2json 转换器也使用固定工具链和二进制摘要核对，显式保存于项目内，不调用可能隐式构建至用户缓存的 go tool 查询。编译、转换器构建与用例入口分别限时 900、300、420 秒，只清理本次拥有的进程树。复用二进制仅省略重复编译，测试每次使用新的独立数据库并重新执行。

## 数据与状态

| 表 | 保存内容与约束 |
| --- | --- |
| render_control_intents | 公开任务 ID、不可变公开模型及客户请求摘要、受信实例/user/Key/IP、目标网关、操作与幂等摘要、规范请求摘要、加密请求、价格快照、冻结金额、派发次数、不可变远端绑定、终态图片数/视频计量、唯一终态与账本引用 |
| render_control_effects | 同事务写入的预留/终态副作用通知；只含 ID、受信主体及金额，不含请求正文、凭证或媒体地址；领取有租约及 fencing，确认不再次计费 |
| render_control_closures | 与原意图一致的目标网关、六项引用、关闭标识及规范摘要；只追加，和释放资金的终态共同提交 |
| render_control_recovery | 与预留共同提交的工作、到期时间、租约 owner/until、fence、失败退避、关闭/客户取消意向及可信取消 IP；按原目标/实例领取，旧租约不能改变意图 |

状态为 reserved → dispatching → admitted → settled；reserved 可在派发次数为零时原子撤回到 released/not_dispatched。尚未绑定任务的意图可凭原目标的持久关闭证明进入 released/remote_closed，保留派发次数。网络调用前必须持久化 dispatching 与次数；一旦可能已发送，普通撤回接口拒绝释放资金。远端回执丢失时保留原公开 ID、provider_request_id 与冻结资金，不能仅按 404、客户 Key 撤销或超时推断未执行。服务端权威结算可在远端绑定回写前到达，但必须匹配目标网关、实例、派发记录、external_task_ref、authorization_ref、price_version 和 job ID。

服务端及元数据客户端的持久关闭协议见 [30](./30-网关请求关闭与恢复协议.md)；单次查询不存在仍不足以证明在途请求不会稍后创建。目标保存和关闭消费实现按下文增量验证；获取证明、租约、退避及准入恢复已由协调器组件接通，有界宿主与实际组合根补丁见文档 33，完整运行仍待验收，不能按超时自动退款。

## 原子账本规则

1. 锁顺序为 user → API Key → intent；准入在 Key 后读取并共享锁定所属分组。预留检查 Key 属于该用户、启用/期限、标准分组与余额；本增量只接受 balance 计费，订阅分组明确拒绝，不能自动改走余额。套餐支持是完整出口的未完成项。
2. 同事务保存意图并更新上游 users.balance/frozen_balance。金额采用 10^-8 定点整数与 PostgreSQL NUMERIC，拒绝浮点金额、溢出、负值和超界价格。每个意图最高 1,000,000 美元；图片按张，视频按开始的整秒向上取整。价格由服务端配置提供并冻结，结算按冻结单价与已验证终态计量计算，不能接受控制面自报金额。
3. 幂等范围是实例、逻辑 Key 与规范操作；重放返回同一任务及原冻结价格，改变规范请求则冲突。幂等凭据只存摘要，原始客户 Key 不进入此表。请求正文以 AES-256-GCM 加密，AAD 绑定实例、user、Key、任务及请求摘要；恢复解密失败本身不改变或释放冻结。
4. 预留将同一 Key 尚未结算的本 Provider 冻结总额与上游 quota_used、5h/1d/7d 有效窗口用量共同比较，避免并发准入穿透。未完成的 Provider 预留始终占额，即使跨日也保守保留。普通上游路径没有相同预留机制；本增量不宣称解决其在途超额问题。
5. 权威终态、上游 usage_billing_dedup、余额/冻结、Key quota/rate 计量、副作用 outbox 共同提交。事件 ID、规范事件摘要和意图唯一终态共同防重；重复同事件返回原账本引用，指纹/归属/用量或第二终态冲突则拒绝且不动钱。已禁用或软删除的 Key 不阻止旧任务结算。文档 29 初始实现沿用固定上游的软删除 Key 不新增计数行为；后续 [40](./40-Sub2API倍率与套餐计费.md) 收紧为原 Key 仍记终态计数，保持原删除/禁用状态，不追补已终态历史。用户和 Key 硬删除受外键保护，不能丢弃未归档账本。
6. 终态成功金额不能超过冻结；失败/取消/过期的图片与视频用量必须为零。终态一次性归还全部冻结与实际扣款之差，不允许 capture、release 各走独立请求。数据库提交响应丢失视为待核对，调用者读持久意图后用原 ID 重放。
7. outbox 原有租约领取、过期重领和 fencing 保留。后续原生用量/缓存消费按 [39](./39-Sub2API用量与缓存持久消费.md) 接线：短事务写 usage_logs 和上游认证失效 outbox，事务外两遍删除余额/窗口缓存，失败持久退避；消费不再次计费。通知、套餐/倍率及完整运行仍按各自出口验收，不能把 outbox 落盘当成这些全部完成。

规范请求最多 2 MiB、JSON 深度最多 32、值节点最多 10,000。视频时长只接受最多三位小数的十进制数值；拒绝指数格式，直接按毫秒定点解析，不用任意精度指数构造大整数。内核预留/转换事务总限时 10 秒、锁等待 2 秒、SQL 5 秒；恢复/查询 5 秒；恢复和副作用批次均最多 100。副作用租约为 1～60 秒，过期领取增加 fencing，旧消费者不能确认。

## 验证要求

### 目标网关与关闭证明增量

本轮沿用 DEV-07、11～16、23～27、29～32，新增 248 向前迁移，不修改已执行的 247。Reserve 必须接收由受信配置构造的目标 gateway_id，在资金预留同一事务落盘；幂等重放保留原目标，当前配置变化不能重绑原意图。Finalize 同样核对目标网关与实例。历史记录的未知目标保留 NULL，不从当前配置猜测回填；未知目标禁止继续派发或消费关闭证明，仍保留资金与原始记录，等待有证据的迁移处置。

增加 render_control_closures，保存原意图、目标网关、完整六项引用、关闭标识和规范摘要。只允许使用 controlclient 经 HTTPS 验证完整回显后生成的私有字段 ClosureProof；客户 JSON、手工构造 RequestResolution、unknown、admitted、HTTP 成功码或序列化后的证明都不能构造该能力。显式开发回环 HTTP 可读取协议元数据，但不能生成资金释放证明。重启后可重新查询同一关闭记录取得证明，不能直接把外部 JSON 反序列化为可信证明。

ReleaseClosed 在 user → Key → intent 的同一事务中核对原目标和完整引用，保存关闭证明，再沿现有唯一资金终态事务释放全部冻结、写去重与副作用；记为 released/remote_closed，不伪造远端结算事件。dispatch_count 保留，允许此前可能发送过的意图关闭。只有 reserved/dispatching 且无 admission/job 绑定的意图可消费该证明；已绑定或已结算任务继续使用原结算协议。客户撤销或软删除不阻断旧预留清理。重复同证明返回原账本引用；证明不同、其他终态或迟到派发/绑定/结算均拒绝。

数据库保护意图目标和关联身份不可重绑，关闭证明不可修改或删除，并在事务提交时核对证明与 released/remote_closed 状态及原六项引用一致；无证明的直接更新与只有证明却未释放的事务均失败。余额、去重、证明或 outbox 任一写入失败，整体回滚。部署须停止旧 Provider 写入，核对备份后执行独立迁移，再启动匹配新存储契约的版本，不混用旧写入程序。新增迁移先在随机原生测试库与真实上游迁移链验证；完整服务部署、恢复租约/退避、路由和媒体接线不由此增量宣称完成。

关闭消费验证包含 HTTPS 回显与伪造/序列化证明拒绝、目标变化后的幂等重放、错误目标结算、模拟未知旧目标保护、并发重复关闭、关闭与派发/绑定/结算竞争、撤销 Key 清理、数据库中途失败回滚、数据库约束与关闭提交后的原生子进程退出恢复。历史结果见文档 17：客户端 17 项顶层测试、32 个子用例，账本 37 项顶层测试、55 个子用例通过；[当轮源码与运行核对](./evidence/2026-10-23/sub2api-closure-consumption-closeout-before-recovery.json) 记录 299 个迁移、104 张测试表、备份与清理。HTTPS 使用协议测试服务，不能代替完整跨服务恢复验收。
