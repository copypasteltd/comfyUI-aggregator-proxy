# 20 · 网关准入与对账实现约定

2026-10-22，DEV-12～18、23～24、32；补充文档 03、08、11、12。实现进行中，固定上游 Sub2API 的运行接入须另行验收；本文件不修改 job 状态、Worker 事件或业务 Key 策略的冻结版本。

1. 网关服务凭证使用独立 `gateway_` realm；不能调用公网业务、Admin 或 Worker API。管理端登记 issuer 和每个网关的允许网段。外部租户/Key 引用只从已验证服务请求进入 `/gateway/v1`，必须命中管理端建立的绑定；缺失映射直接拒绝，不回退共享 Key。每个外部主体有独立的本地逻辑 Key、策略与计量，无客户货币余额。
2. 网关资源请求附外部租户、外部 Key 和原客户 IP；控制服务在当前策略下检查范围、IP、速率、内容及下载权限。客户端向 `/v1` 伪造同名头不能改变身份。绑定和服务凭证只能由管理身份维护；秘密一次显示，服务密钥只存 pepper 版本和 HMAC 摘要。
3. Provider 先持久化 public task 意图并在 Sub2API 幂等预留货币额度，再向 admissions 发送规范请求、稳定 provider_request_id、external_task_ref、价格版本和预授权引用。控制面在同一 PG 事务冻结任务及映射，初态 admission_pending，默认有效 120 秒；不派单。预留 unfinished 与媒体资源，不在此时增加最终接收日的 daily_jobs。
4. confirm 锁 admission，再按全局→租户→项目→Key、日期排序锁配额，最后锁 job。确认时重新检查当前身份/策略版本、发布版本和当日额度；跨日将媒体预留移到最终确认日，并只增加一次 daily_jobs。成功转 queued；确认回执丢失可重放原 intent。abort、过期和 confirm 竞争由同一 admission 行锁裁决；过期或拒绝释放预留且产生唯一终态事件，不允许迟到 confirm 复活任务。
5. 终态在同一事务写资源 usage 与 `gateway.settlement` outbox；不依赖客户继续轮询。Provider 的后台恢复器拉取自身未确认事件，在 Sub2API 自身数据库幂等结算/退款后用 ledger_ref 确认事件。控制面不计算、存储或扣减客户货币余额。事件、job 与网关绑定均唯一；重复相同确认成功，不同账本引用冲突。
6. 后台对账的 settlements 拉取/确认仅按本服务已持久化的 task 绑定授权，允许处理客户 Key 后续停用的旧终态，避免阻断退款。它不能获取素材、提示词、任意客户任务或新建任务，是端点目录中明确标记的 service_reconciliation 例外；其余网关接口逐请求执行当前业务策略。停用网关服务仍会阻断该服务全部调用。

准入创建回执丢失的关闭与最小状态查询遵循 [30](./30-网关请求关闭与恢复协议.md)。两个固定 admission-requests 端点也是明确的 service_reconciliation 例外；按完整原意图身份与本服务归属操作，不新增确认、内容或任务执行权限。unknown 不能作为退款证明。

增量管理接口位于 `/admin/api/v1/gateways` 与 `/gateway-bindings`，沿用 keys:manage、管理会话、CSRF、写入幂等与 revision；业务 Key 无权维护映射。`GET /gateway/v1/settlements` 和 `POST /gateway/v1/settlements/{id}/ack` 供 Provider 后台对账。新增路径进入端点目录与实际 OpenAPI；客户端类型随导出更新。

图形 Admin 的“网关接入”页维护服务身份、来源网段、启停、凭证轮换和外部主体绑定。新绑定采用默认拒绝模型/发布版/渠道的独立 Key 策略，管理员在“API 密钥”页配置其授权；不能因建立映射自动扩大客户能力。网关凭证只在当前创建/轮换弹窗显示，关闭和离开页面立即清空。

固定上游的适配必须覆盖公开图片/视频提交、查询、内容代理、独立主体、持久化公共 ID/预留及后台对账，不能把一个仅能转发 HTTP 的客户端写成完整 Provider。Go 工具链只在 app/.local 使用原生 ZIP，官方 SHA-256 验证后才解压；下载或构建失败保留为未验证，不调用虚拟化。

原生源码验证使用 `app/scripts/verify-sub2api-native.py`：固定源码提交和归档摘要，模块严格沿用上游 go.mod/go.sum，工具链/模块/构建缓存与二进制均在 app/.local；默认只编译上游后端，不启动上游服务或执行其测试集合。编译限时并清理本次子进程。上游测试依赖包含 testcontainers，本项目禁止运行会调度容器的测试；将来只选择已审查的纯进程/原生数据库测试。原生编译成功、Provider 接入完成和真实网关账本联调是三个独立状态。


## 原生联调修订：服务身份与凭证标识

固定 Go 客户端必须显式配置稳定 `GatewayID`，取 Admin 返回的网关 `id`，与 `credential_identifier` 相互独立。凭证轮换改变认证标识和秘密，不改变目标服务、准入证明、既有意图或账本归属。Provider 沿用 `gateways[].id` 配置字段，禁止从凭证前缀推导它；缺少或非法稳定 ID 时拒绝初始化。本轮未新增 DDL，修复和实际跨进程证据见 [43](./43-Sub2API原生跨进程联调.md)。
