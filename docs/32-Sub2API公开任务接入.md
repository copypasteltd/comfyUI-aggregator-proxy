# 32 · Sub2API 公开任务接入

2026-10-23。接续 [25](./25-Sub2API原生适配实施约定.md)、[29](./29-Sub2API持久意图与账本事务约定.md) 和 [31](./31-Sub2API恢复租约与协调器.md)，涉及 DEV-07、11～19、23～27、29～32。本文记录 Provider 原生任务 HTTP 处理器增量；后续服务托管与组合根接线见 [33](./33-Sub2API服务托管与生命周期.md)。最终图片/视频兼容、素材、媒体代理和完整运行的范围不缩减。

## 身份与路由

新增 Provider HTTP 处理器供固定 Sub2API 的组合根挂载。原生端点为 POST /v1/jobs、GET /v1/jobs/{id}、POST /v1/jobs/{id}/cancel。挂载必须传入上游 APIKeyAuthMiddleware，不能传客户头作为 Subject。处理器再次读取上游认证上下文中的 user、Key 及其一致性，实例来自受信配置，IP 使用上游可信代理解析；不读取客户伪造的外部租户/Key/IP 头。

提交受当前分组模型白名单和显式配置的模型/能力/分组绑定约束，不按模型名称伪装为其他供应商。只接受冻结 job-create Schema 的五种 task_type 与受控字段，严格拒绝重复/未知字段、大小写替代字段、越界数值、过深结构、URL/路径素材和任意工作流。请求限 2 MiB，解析使用十进制数值；n 固定为首版单图。模型具体规格、素材归属、已批准发布版本等仍由控制面准入权威复查。

模型价格由受信 Provider 配置给出，不能从请求体、头或控制面自报金额读取。未带 Idempotency-Key 时每次生成新键；提供时要求单一、可打印 ASCII、1～128 字节，同键同规范操作保留原 ID/请求/价格/目标。规范操作仅按能力确定，后续兼容入口必须映射到同一操作。

## 事务与投影

新增 250 向前迁移，在原意图保存公开模型及客户请求摘要；既有意图的未知模型保持 NULL，不能猜测或向客户输出。新预留在资金、意图、恢复工作和 outbox 的共同事务内保存模型。模型和客户请求摘要不可变；247～249 的摘要保持不变。客户请求摘要不包含后来合并的模型默认参数，冻结正文摘要仍绑定实际提交正文；配置变化后的幂等重放保留原参数/价格/目标。视频默认时长只来自受信模型配置，使用 seconds 字段，不发明通用五秒默认值。查询按受信实例/user/Key 和公开 ID 加条件，不允许通过内部远端 job ID 越权定位。

POST 只做本地持久预留并返回 202，带稳定公开 ID、Location、Retry-After、Cache-Control: no-store 与服务生成的 X-Request-ID。恢复协调器推进远端准入/确认；不在客户端连接内做第二次无持久记录的派发。响应不暴露内部请求/预授权/远端 ID、账本引用、资金或原始错误。

查询在未绑定时投影 admission_pending；绑定后以当前受信主体读取控制面任务，校验原模型与能力，保留公开 ID。任务及产物 ID 只作安全元数据，下载权限由后续媒体端点逐请求检查；不能把服务结算权限当成客户内容权限。终态状态与资金状态分开：远端终态可以先于本地结算，查询不能自行扣款或释放。

取消先按原主体读取，再在原 user → Key → intent → recovery 锁顺序持久记录关闭意向；未派发的工作可由恢复器安全撤回。可能已派发而尚未绑定时只关闭原请求并取得证明，不能按超时退款；已绑定时向控制面取消原 job，确认后的生成取消遵守控制面安全语义。取消请求或回执丢失不会新建任务或直接改资金，已有终态不回退。关闭意向应使当前恢复令牌失效，防止旧进程用旧模式覆盖取消。

## 接线与验证边界

本轮先实现可挂载的原生任务处理器与真实上游认证/PG/HTTPS 协议测试，不自动修改固定原版目录，也不启动未经配置的 Sub2API 服务。固定上游现有鉴权只对图片任务查询跳过余额检查；在本项目生成副本中用经过摘要核对的单处补丁，给 GET /v1/jobs/rc_{32位小写十六进制} 与 POST 同路径/cancel 增加相同性质的既有任务例外。仍执行真实 Key/user/IP/分组认证；过期/耗尽 Key 可读/取消旧任务，已禁用/删除 Key 拒绝。新建、其他方法/路径/ID 不跳过计费检查。不得通过改写 URL 或开启 simple 模式绕过。

补丁规格保存在 app/integrations/sub2api/overlay/backend/render_control_patches.json，认证文件只允许一处精确替换；输入、输出和规格均纳入摘要，固定归档与原版目录保持原样。生成副本复用时先核对之前已登记的补丁版本，再按维护规格更新；未知修改拒绝。后续文档 33 另登记组合根文件的精确补丁，除这两处文件外其余上游文件仍逐文件核对原归档；新增代码与测试仍由本项目维护。后续文档 34 已增加生成兼容、原属内容访问及相应既有资源的读取例外；完整 Provider 仍待图片编辑、素材/模型发现、共享列表、实际副作用消费者及完整控制面运行验收。

测试必须使用真实上游认证服务/仓储与随机原生 PG 库，禁止用任意头生成认证上下文代替。覆盖匿名/错 realm、伪造身份/IP、同 Key 并发幂等、同键冲突、不同 Key 隔离、模型/分组限制、字段与大小边界、预留无 HTTP 派发、取消与恢复令牌竞争、远端元数据错配和错误脱敏。匹配源码的实际结果记在文档 17；通过组件用例前不改完成标志。

## 原生任务处理器增量实测

处理器、严格解析器、持久取消和协调器取消分支已实现。视频输入统一使用冻结契约中的 seconds，修正原 Go 内核曾使用 duration_seconds 的偏差；图片拒绝视频参数，视频默认值只从模型配置合并。客户请求摘要与实际执行摘要分别保存，配置默认值更新不会使相同客户请求的重放改变原冻结执行。250 只向前增加字段和数据库保护，不更改 247～249。

2026-10-23，[当轮原生测试](./evidence/2026-10-23/sub2api-ledger-tests-before-hosting.json) 67 项顶层测试、127 个子用例通过，另 1 项子进程 helper 在主进程跳过；耗时 33.14 秒，含重新编译 12.02 秒。真实上游认证/仓储、Ent runtime、原生 PG 与 HTTPS 协议测试服务共同验证了上文边界；完整迁移链 301 项、105 张测试表通过重放。11 个冻结 Schema 正反例与维护夹具一致，Schema 摘要受入口门禁保护。客户端未修改，其 17 项顶层测试、32 个子用例的既有通过报告及摘要仍匹配。

[当轮收尾记录](./evidence/2026-10-23/sub2api-ingress-closeout-before-hosting.json) 核对 28 项文件、固定归档、原版与补丁后的认证文件、入口、二进制及报告摘要。备份已核对、测试库和测试进程已清理；开发库未迁移，既有 HTTPS API/Admin 仍健康。首轮入口漏导入 Ent runtime 的失败记录保留于文档 17，后续补齐初始化后才取得通过结果。

当轮结果验证可挂载组件；后续文档 33 加入后台生命周期和上游组合根补丁，[该轮组件报告](./evidence/2026-10-23/sub2api-ledger-tests-before-compatibility.json) 为 77 项顶层测试、152 个子用例通过。再后续的 [34](./34-Sub2API生成兼容与产物访问.md) 加入图片同步/异步、视频 JSON、原属媒体访问及仅作用于 Provider 的 OpenAI 鉴权错误外形，该轮组件为 90 项顶层测试、182 个子用例通过。素材/编辑及最新组件证据见 [35](./35-Sub2API素材与图片编辑接入.md)。当前只支持受信固定余额单价，套餐与分组/用户价格倍率、模型发现、完整标准化输入、列表/显式共享、实际副作用消费者与完整跨服务运行仍须完成，provider_implemented 和 runtime_integration_verified 继续为 false。
