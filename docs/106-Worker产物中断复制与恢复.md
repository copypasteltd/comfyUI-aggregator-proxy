# 106 · Worker 产物中断复制与恢复

2026-10-26（Asia/Taipei）。继续落实待办 42/55/61、DEV-07～11/18/23/25/26/29/31。当前 Worker 在 ComfyUI 完成且队列停止后，直接以 xb 打开最终暂存文件；若进程在复制中途退出，恢复时再次打开同一路径会触发 FileExistsError。即使原始产物完整保留，任务仍会隔离，无法正常继续回传。本增量先固定本地恢复约束，再复现、实现和验证。

## 固定边界

1. 仍需原 prompt 的成功 history 和不在队列中的停止证明，之后才收集原输出；不新增 POST /prompt、换机重算、GPU 提前释放或自动删除路径。
2. 已有目标只能在整个现有文件逐字节匹配当前稳定源文件前缀后续写。完整一致的副本复用；空文件可以续写；不同内容、更长的文件、非普通文件、多硬链接和目录重解析点均保留并隔离。
3. 不截断、不覆盖已有字节，不删除、移动未知文件或另建无限临时副本。读取和复制均使用有界块及原发布包大小上限，继续计入原 spool/容量规则，不增加预算。
4. 使用同一已打开源句柄核对源文件身份、大小和修改信息；现有前缀核对后及复制结束再次检查。源变化时保留文件并核对，不把暂时变化当作可重试生成失败。
5. 写入 flush/fsync、最终副本摘要及大小一致后，才允许 journal 保存产物包，再沿用 outputs_collected、gpu_released、上传及 complete。复制/同步失败后不生成成功清单。
6. Worker 自有 state_root/outputs/attempt 路径逐层检查普通目录，拒绝 symlink/reparse；最终目标只允许普通、独占的文件。服务账号与可信管理员 ACL 边界保持，不承诺抵御恶意本机管理员在检查间替换路径。

公开 DTO、数据库、事件协议、输出文件命名、媒体校验和确认后一小时保留不变。没有匹配源证据的旧暂存文件继续保留；不清空旧 journal。真实六类 Workflow、Windows 物理故障/存储及 10～20 台验收保持独立开放。

## 验证出口

- 六类任务分别验证新文件、空文件、部分副本及完整副本，历史完整内容保持。
- 不匹配或超长副本、大小上限、源变化、写入/fsync 中断、硬链接及目录重解析保护。
- 原生子进程退出后的部分副本恢复，以及实际 Worker 恢复路径不重新生成、只发布/释放/确认一次。
- 匹配风险的回归、完整工程门禁、来源精确候选与安装证据；实际执行结果完成后追加，不能预先签收。
