## 使用流程

1. 新连接默认填入 **`https://gen.sub2share.xyz`**，输入管理员分配的**业务API Key**后连接。已保存连接会保留其地址；旧 HTTP 连接请明确切换到 HTTPS 地址。默认只在页面内存使用，刷新后需重新填写；仅在可信设备选择记住。退出会移除当前连接保存的Key。
2. 读取当前Key的模型目录、说明、参数和完整合法规格。目录可见不保证设备立即空闲、额度充足或模型当前执行正常。
3. 新建/打开已有画布，或从“案例”打开可编辑项目。案例可以不带Key先看，打开案例不会自动上传或提交生成。
4. 在画布选中素材后点“新建创作”，或从模型入口打开表单。核对完整规格，以及旧参考槽或命名槽的类型、大小、顺序和角色；按text_slots填写台词、歌词等文本。续拍须核对同Key成功、兼容且未到期的父任务；Schema没有prompt时不强加提示词。
5. 明确点击“提交1项生成任务”（批次数量随界面显示）。先上传必要素材，再通过原API创建异步任务。返回任务ID后可继续编辑；关闭网页不表示远程取消。
6. 在节点或任务页查询**原任务**；刷新后继续恢复已有记录。结果未知时只读核对，不换模型、Key或幂等键盲目重提。取消要等待原服务确认，停止本页等待不是取消。
7. 成功后点击“载入产物”，浏览器鉴权取回并校验文件，再加入画布/素材。图片可继续做参考，视频和音频可播放，GLB可按需预览或保存原件。不能解码时使用原件下载，不伪装转码。
8. 保存项目；重要内容另存原件或导出作品ZIP。任务JSON主要用于原任务核对，不能代替含全部原件的作品备份。

恢复后五类真实生成、画布回填、独立原件校验及刷新通过，详见[文档39](39-设备恢复与真实生成补充验收.md)。初次排队到期与历史视频失败保留；不把模型目录可见或包验证通过当作全部模型已执行。

## 接口适配逻辑

| 用户操作 | 原有接口 | 前端责任 |
| --- | --- | --- |
| 连接/发现 | `GET /v1/access-policy`、`/v1/models`、`/v1/capabilities` | 合并权限、用法、Schema、preset及槽位；按当前声明生成表单 |
| 上传素材 | `POST /v1/assets` | 按实际slot/kind上传；命名媒体形成input.media，专用文本形成input.texts，父任务仅传input.context.job_id；保留原上传标识并核对原件信息 |
| 提交生成 | `POST /v1/jobs` | 合法JSON、业务Key、原幂等键与既有发布摘要契约；不调用旧同步/TTS脚本 |
| 查询/恢复/取消 | `GET /v1/jobs/{id}`、`POST /v1/jobs/lookup`、`POST /v1/jobs/{id}/cancel` | 已知ID查原任务；lookup仅在原服务声明支持时使用；如实显示失败 |
| 载入/另存 | `GET /v1/content/{id}`、`GET /v1/content/{id}/download` | 固定源站Bearer鉴权，核对字节/MIME/SHA，再展示或保存 |

所有业务请求由浏览器直达原API，`credentials: omit`；不使用管理Cookie，不把Key放URL。画布服务器只提供静态文件，没有生成后端、代理或第二套队列。原服务未声明必要契约时明确提示，画布不会自行改服务。

## 数据与保留

云端产物通常完成后八小时到期，准确期限以API的`expires_at`为准；已经下载的本机副本不会因此自动删除。项目、素材与任务记录主要保存在当前浏览器源站。删除或清理使用现有显式入口，保留被项目引用的原件。

默认 API 改为 HTTPS 不会迁移或删除已有连接、项目、原件和任务；服务源站是本机身份的一部分，新 HTTPS 连接不会冒充旧 HTTP 任务身份。画布换域名、端口或浏览器配置文件不会自动带走本机数据。先在旧站导出项目ZIP/所需原件和任务JSON，在新站导入并重新填写Key；核对新副本后再处理旧数据。导入不会重新生成。不要清空或降级日志v5，不把仅支持v4的旧包当恢复目标。

## 原生开发与静态部署

在独立Git仓库根目录执行；已验证的工具为Node22.14.0/npm10.9.2，禁止Docker/WSL/虚拟机。

```powershell
Set-Location web
npm ci
$env:VITE_BASE='/studio/'
$env:VITE_STUDIO_MODE='managed'
$env:VITE_AGGREGATOR_ORIGIN='https://gen.sub2share.xyz'
npm run dev
```

开发入口为`http://localhost:3000/studio/`。构建时保留这些环境变量，执行：

```powershell
npm run typecheck
npm run build
```

只部署`web/dist/`。`VITE_AGGREGATOR_ORIGIN`只含公开地址，不含Key；未设置或为空时默认使用`https://gen.sub2share.xyz`；非空构建配置仍可显式覆盖。独立静态服务使用现有39445端口和SPA路由，API仍在39443。域名/反代由用户安排，不引入HTTPS门槛，不改原API的CORS或服务配置。

当前静态目录为`/opt/infinite-canvas/releases/canvas-20261113.156.1/`；当前上线结果以文档40为准。新增静态版本只切画布自身指针，校验资源和业务深链、保留旧页面所需资源及存储兼容性，不重启/切换原API。案例业务路由是`/library`；`/examples`是PNG目录，不能混用。[Nginx样本](deployment/nginx.conf)与[独立单元](deployment/infinite-canvas-static.service)用于理解现有交付，不是要求本次重装服务。

154.0兼容恢复包已准备，精确复用153.1应用和完整v5存储契约；回退会失去新版输入界面。154实际回退未演练，不能当作无缺陷的恢复方案。[原始历史记录](history/21-历史部署与验证记录.md)保留各时点的回执。纯文档变更不重发静态包。
