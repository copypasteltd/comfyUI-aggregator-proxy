# 31 · Sub2API 恢复租约与协调器

2026-10-23。接续 [29](./29-Sub2API持久意图与账本事务约定.md) 和 [30](./30-网关请求关闭与恢复协议.md)，涉及 DEV-07、11～16、23～27、29～32。本文冻结本轮增量；当前实现与验证结果记于文档 17，不把协调器组件当成完整 Provider 服务。

## 持久工作与租约

新增 249 向前迁移及 render_control_recovery 表，保存 intent_id、到期时间、租约 owner/until、递增 fence、连续失败次数、脱敏错误码和 continue/close 意向。预留在资金、意图、outbox 的同一事务中建立恢复工作；迁移回填已有活动意图。历史未知目标不会从当前配置猜测，保留冻结与记录，不领取为可派发工作。

领取按原目标网关、Sub2API 实例和活动状态过滤，用到期顺序及 SKIP LOCKED；一次最多 100 条，fence 递增。每个协调步骤只即时领取一条，不把已领取的长批次放在内存等待。租约采用数据库时间，允许 10～300 秒；协调器默认 90 秒，并要求至少覆盖两次远端调用限时及 20 秒事务余量。失败退避从 2 秒指数增长至 300 秒，连续失败计数饱和，不能因重启清零。

已领取的派发、绑定、关闭消费和未发送撤回，在原 user → Key → intent 锁之后锁恢复行，核对 owner/fence/未过期，再变更。领取只锁恢复行，不反向锁用户或意图。失效租约不能提交状态或完成本次恢复工作；结算事件仍可由独立服务消费者按原唯一资金事务处理。租约时间检查使用实际数据库时钟，不能用长事务开始时间证明仍有效。

每次 HTTP 前重查当前租约，跨 HTTP 不持有数据库事务。租约无法撤回已经在途的 HTTP；重复发送始终使用原请求 ID、原目标、原规范请求与远端持久 fence，保护迟到请求。任何超时、失联或 lease 过期本身都不退款、不生成新任务 ID。

## 协调步骤

协调器必须绑定原目标的 HTTPS 客户端，凭证中的服务 ID 与目标一致；不接受明文开发传输作为资金恢复连接。公开 Handler 仍须从认证记录构造 Subject，不能从客户头传入实例或主体。组件只处理已有持久意图，不替代公开路由、请求验证或当前内容授权。

| 当前状态/观测 | 下一步 |
| --- | --- |
| reserved 且 continue | 解密原规范请求，先提交派发记录，再以原身份请求准入；解密失败保留预留并记录待处置错误 |
| dispatching 且 continue | 服务身份查询完整原意图；unknown 且无远端绑定时允许按原 ID/正文重新准入，每次重发前持久记录派发；不能按 unknown 退款 |
| 远端 admitted/pending | 原子保存原 admission/job 绑定；复查租约后确认；回执不明留待下次按原身份查询 |
| 远端 admitted/confirmed | 保存/核对绑定，继续等待权威结算，不重建任务 |
| 准入/确认出现不可继续的业务错误 | 持久转为 close 意向；后续仅查询/关闭旧请求，不能换 ID 重新派发 |
| close 意向 | 使用服务身份关闭原请求；closed 凭 HTTPS 能力走 ReleaseClosed，admitted 绑定原任务并等待结算，confirmed 不取消 |
| 远端 closed | 无绑定时按原证明原子释放；已有绑定则视为冲突，保留预留待核对 |
| 已有绑定但远端 unknown，或身份冲突 | 保留资金和绑定，记录冲突；不重新创建 |
| 本地 settled/released | 不再领取，不因旧恢复回执改变终态 |

网络错误、429、5xx 和存储不确定性保留原意图并有界退避。错误持久化只保存固定协议码，不存响应正文、凭证、素材或提示词。已撤销客户 Key 的旧任务仍可用服务查询/关闭和结算；业务确认继续遵守控制面的当前授权。

独立结算批次最多 100 条。先按原目标及数据库中保存的实例核对事件，再提交 Finalize，得到持久账本引用后 ack；ack 失败下次使用相同终态重放。未知意图、归属不符或金额冲突不 ack，须进入后续运维核对。每个网关服务的财务事件须归属同一个 Provider 数据库，不能让互不共享账本的实例混用同一服务事件队列。实际用量/缓存/通知消费者仍需接线，不能用再次扣款补副作用。

## 迁移与验证出口

不修改 247、248 的摘要；停旧写入、验证备份、独立迁移后再启新版本。原生随机测试库运行完整上游迁移链，finally 清理。无 Docker、WSL 或上游容器测试；不打开无用浏览器。

验证领取互斥、不同目标/实例隔离、到期重领 fencing、数据库时间与退避、预留工作共同回滚、旧租约禁止派发/绑定/关闭、回执丢失后原 ID 重放、绑定/确认恢复、客户撤销后的关闭、原子退款、唯一结算与 ack 重放。先用真实原生 PG 与 HTTPS 协议服务验证组件；完整控制面和 Sub2API 原生服务的跨进程崩溃、公开路由、媒体交付、套餐、副作用消费者及真实设备仍保留为完整出口。

## 当前实现与实测

新增 recovery.go、coordinator.go 与对应测试，249 迁移保持 247/248 摘要不变。Store 的恢复变更入口在原资金锁顺序后核对租约，Coordinator 只接受匹配原目标的具体 HTTPS 客户端，不持有数据库锁跨 HTTP；宿主调用 Step 领取一个到期工作，ReconcileSettlements 独立消费最多 100 条结算。组件没有隐含后台线程或内存工作队列。

2026-10-23，[客户端报告](./evidence/2026-10-23/sub2api-controlclient-tests-before-compatibility.json) 17 项顶层测试、32 个子用例通过（7.97 秒）；[当轮账本及协调器报告](./evidence/2026-10-23/sub2api-ledger-tests-before-ingress.json) 52 项顶层测试、62 个子用例通过（17.05 秒，复用已核对摘要的当轮二进制），另 1 项 helper 主进程跳过。完整迁移链 300 项、105 张测试表通过迁移重放，先核对空库备份、最后删除本次临时库。

新增用例包含 16 条工作由 4 路并发领取、不同目标/实例隔离、同 owner 重领后旧 fence 拒写、实际数据库时钟及退避饱和、预留与恢复工作故障共同回滚；HTTPS 服务注入准入/确认已生效但回执丢失、未接受时重发原 ID/正文、租约在回执到达前过期、Key 撤销后的关闭竞争、绑定 unknown/密文损坏保留冻结、ack 未收到或已收到但回执丢失、未知结算不 ack。远端调用期间另外取得资金行锁，验证没有跨 HTTP 持锁。原生子进程在准入回执丢失并保存退避后以 73 退出，后继进程从真实 PG 查回原任务并确认，不重复创建。

[当轮源码与运行收尾](./evidence/2026-10-23/sub2api-recovery-closeout-before-ingress.json) 记录 17 项叠加文件（含共享客户端）、验证入口及二进制摘要、未变的应用数据库版本、HTTPS 健康与进程身份。该记录保留为原生任务接入前的历史快照。

后续 [公开任务接入](./32-Sub2API公开任务接入.md) 增加 250：客户明确取消时另存 cancel_requested 和经真实鉴权解析的 IP，首次取消使旧 lease/fence 失效，重放保留首次 IP；与系统因业务错误而进入 close 的意向分开。未派发只撤回本地预留，pending 关闭原请求，confirmed 以原主体及取消时的可信 IP 调用原任务取消，再等待权威结算；普通系统 close 仍不取消 confirmed。取消响应丢失继续核对原任务，不直接退款。[当轮接入及恢复报告](./evidence/2026-10-23/sub2api-ledger-tests-before-hosting.json) 为 67 项顶层测试、127 个子用例通过，301 个迁移、105 张测试表重放通过；[当轮收尾](./evidence/2026-10-23/sub2api-ingress-closeout-before-hosting.json) 已核对匹配源码。

服务托管按 [33](./33-Sub2API服务托管与生命周期.md) 实现有界后台 Step/结算轮询、并发停止及在途取消，上游组合根补丁已编译通过。[当轮测试](./evidence/2026-10-23/sub2api-ledger-tests-before-compatibility.json) 为 77 项顶层测试、152 个子用例，未增加迁移；停止保留资金与租约，控制到期后的后继恢复保留原请求且不重提。锁探针对独立短事务有 500 毫秒等待上限，若调用方自身跨 HTTP 持锁仍会超时失败；另在 HTTP 阻塞期间用 NOWAIT 验证资金行可立即加锁。

后续 [生成兼容与产物访问](./34-Sub2API生成兼容与产物访问.md) 复用同一预留与协调器，跨原生/兼容入口保留 ID、规范摘要及原冻结规格，同步超时不重提；该轮组件回归为 90 项顶层测试、182 个子用例。素材/编辑继续复用同一机制，上传单独持久保存原目标并使用远端稳定幂等键恢复，最新组件证据见 [35](./35-Sub2API素材与图片编辑接入.md)。完整上游与控制面跨进程运行、实际副作用消费者和真实生成仍须完成。
