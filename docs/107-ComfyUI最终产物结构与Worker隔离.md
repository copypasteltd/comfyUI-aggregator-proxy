# 107 · ComfyUI 最终产物结构与 Worker 隔离

2026-10-26（Asia/Taipei）。关联待办 17/23/43/55/60，DEV-09～11/19/25/26/29/31。当前 checked_history 只检查 history 的第一层，收集器随后直接对最终节点、文件集合和成员调用 dict 方法。自定义节点若返回错误结构，AttributeError 可越过 Execution 的异常处理，再由 Worker 主循环等待任务时传播，停止同进程其他任务。本增量先固定异常上游的处理边界，再复现和实现。

## 固定规则

1. 只提取冻结发布包声明的 final_node_ids 和 history_field；不猜测节点、不切换字段、不把未声明节点的产物混入清单。继续支持图片 images、视频 videos/gifs 和音频 audio。
2. 选中节点必须为对象，选中文件集合必须为数组，文件成员必须为对象；filename/type 必须为非空字符串，subfolder 可省略且缺省为空字符串，存在时必须为字符串。未知的附加字段保持兼容且不执行。
3. 缺少选中节点/字段仍表示空产物，沿用现有 output_count_mismatch；合法结构但不允许的目录、路径越界、数量或 MIME 仍沿用既有拒绝行为。结构无效则返回现有固定 invalid_comfy_response，不包含上游值、路径或提示词。
4. 异常结构不证明原执行未发生、停止完整或可重跑。保留原 journal、prompt/association、未确认文件和 GPU 状态，进入核对；不新增生成请求、不发布、不自动释放或收费。
5. 校验在任何文件访问或复制之前完成，不增加 HTTP/字节/列表/时间预算。继续使用现有有界解码，不解析或遍历未声明节点。
6. Execution 应按现有 DomainError 路径退出并保留隔离，不抛出 AttributeError 使 Worker 主循环终止。没有扩大捕获所有程序错误的范围，也不放宽 history、journal 或停止证明规则。
7. 恢复扫描启动的任务可能在扫描下一行 journal 时失败。结束扫描前重新读取未确认行；若不在运行、对应任务已结束或已标记待核对，必须继续隔离，不能用扫描开始时的局部结果清除任务刚设置的隔离。待核对标记先于异步清理，不能把仍在清理的失败任务当作正常活动。正常活动中的恢复任务可以继续，已确认的正常任务不留下永久隔离。

公开 DTO、事件、状态机、数据库、发布包、输出命名、媒体校验和确认保留协议不变。真实六类图、节点实际输出、质量、10～20 台及生产验收继续独立开放。

## 验证出口

- 六类能力的节点/集合/成员/字段异常应受控拒绝，调用收集不读取文件、不产生包或事件。
- 合法的四种 history 字段、可省略 subfolder、附加字段和未声明节点保持原行为；空产物/禁止目录/路径等旧拒绝不变。
- 实际 Worker 读取原生 HTTP 夹具中的错误 history 时保留 journal，不重复生成、上传、释放 GPU；同一进程可继续管理并回传另一已完成任务。
- 匹配风险的专项、完整工程验证与候选来源/隔离安装按实际结果记录；未执行出口不得预先签收。

## 已执行的专项

[修复前](evidence/2026-10-26/history-shapes-before-107.json) 实际运行六类共 90 个错误结构场景，均未按预期受控拒绝；原失败保留。[首次专项](evidence/2026-10-26/history-shapes-focused-107.json) 已通过 230 项，但 12 个主循环场景证实恢复扫描会清掉执行任务刚设置的隔离标志；并非测试夹具错误，已补恢复尾部的新鲜 journal 核对。

[加强后的专项](evidence/2026-10-26/history-shapes-focused-verified-107.json) 共 248 项通过，零失败/错误/跳过，647 个应用输入前后一致；新增 128 项：90 个六类错误结构、20 个四字段兼容/空产物/顺序与固定错误、18 个实际 Worker 主循环场景。原生 HTTP ComfyUI 夹具和真实 SQLite journal 参与；控制面为受控 HTTP transport，不是真实 GPU/物理故障。

原先 248 项通过的[首次完整专项](evidence/2026-10-26/history-shapes-focused-final-107.json)保留为历史记录。随后增加失败任务仍在异步清理的确定性时序卡点，[一个修复前失败](evidence/2026-10-26/history-shapes-cleanup-before-107.json)再次证实只检查 task.done() 不足。现于清理前设置任务待核对标记，并在恢复尾部同时检查；加强后的 248 项通过，耗时 179.246 秒。

主循环中的异常任务没有生成 POST、事件、上传或 GPU 释放；原 prompt/association/journal 保留，节点保持隔离且没有新领取。另一已完成正常任务成功回传并确认一次，Worker 主循环和 HTTP 客户端继续运行。另六个健康场景确认两任务均完成后不会永久隔离。测试在 finally 取消所属循环、关闭 Worker 和原生 HTTP 线程。
