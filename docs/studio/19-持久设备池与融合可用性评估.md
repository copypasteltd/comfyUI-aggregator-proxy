# 19 · 持久设备池与融合可用性评估

本轮补齐 F-41 的设备选择层：画布仍提交一个公开模型；平台在原持久队列内选择合格物理 GPU。代码、原生数据库、合成页面、线上部署和真实设备容量分层记录，完整签收仍为 **HOLD**，新功能为 **pending-test**。

## 方案与使用

1. Admin → 模型与路由 → 编辑映射，选择同一冻结 release 已逐卡验证、批准的渠道。
2. “设备调度策略”默认原领取策略；管理员显式选择“就绪设备加权均衡”后，界面按物理 GPU 展示权重。同卡多个渠道只出现一份权重。
3. 保存会下架模型，重新通过既有发布条件后才可接新任务。权重是相对分配份额；不改变并发、价格、生成参数或超时。
4. 客户端继续使用现有 `/v1/models` 说明和异步任务接口，不填写 GPU。接收时冻结原授权渠道、release 和池版本，修改模型不扩展旧任务。
5. Admin 的“设备分配”读取当前池累计次数和最后序号。它表示 Worker 已接受分配，不等于生成成功或容量达标。
