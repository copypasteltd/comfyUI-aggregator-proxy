# 101 · 依赖不可用错误与安全重试边界

2026-10-26。接续 [100 审计](100-项目全量检查与目标差距清单.md) 的 R07，完善控制 API→Sub2API 的依赖错误投影。此项改变公开错误语义，先冻结 [机器策略](contracts/dependency-error-policy.json)，再同步实现和验证；不将历史数据库故障根因标记为已关闭。

## 1. 具体问题与兼容范围

本增量前，通用 DBAPIError 处理返回脱敏 500，Provider 将上游 CallError 默认投影为 502。锁等待、连接中断、数据库关闭等已知依赖不可用情形和程序/配置错误难以区分；SQLAlchemy 连接池超时还落入通用异常处理。

本次为明确依赖不可用提供稳定 503、固定安全错误码和等待提示。保持现有错误信封、请求关联、权限、额度、事务/HTTP 超时和持久恢复规则。仅替代 [86](86-数据库故障脱敏诊断与并发观测.md) 中“其他未处理 DBAPIError 均为 500”的投影规则；旧诊断日志契约及历史证据保留。已有 audit_query_unavailable 等领域专属 503 和 IntegrityError 的 409 不变。

## 2. 冻结规则

| 编号 | 输入事实 | 对外行为 | 安全边界 |
| --- | --- | --- | --- |
| DEP-01 | 固定白名单 SQLSTATE：锁不可用、查询取消、死锁/序列化、连接故障、资源不足、数据库停机 | 控制 API 返回 503、error.code=dependency_unavailable、Retry-After=2 | 57014 只表示查询取消，不一律称超时；503 不承诺两秒内恢复 |
| DEP-02 | SQLSTATE 缺失/未知且 SQLAlchemy 明确 connection_invalidated is True | 同 DEP-01 | 不依靠异常文本猜原因；真假值相等的非 bool 值不视为 True |
| DEP-03 | 已知只读、权限不足、表不存在，或未知类别且没有明确断连 | 保持脱敏 500/internal_error | 已知非依赖类别优先，不因连接失效标志掩盖配置/结构错误 |
| DEP-04 | SQLAlchemy 连接池 TimeoutError | 503/dependency_unavailable，固定等待提示 | 无原始异常、SQL 或 DSN；不向 ASGI 重新抛出；不伪造 SQLSTATE |
| DEP-05 | Provider 收到控制端 HTTP 503 | 503、error.type=api_error、error.code=dependency_unavailable、Retry-After=2 | 忽略远端错误正文/错误码/Retry-After 值，不转发私有诊断 |
| DEP-06 | Provider 其他既有错误和未知 5xx | 保持各自现有映射 | 不把 500/504 一律改成 503；401/403/404/409/429 等按原规则 |
| DEP-07 | 任何依赖错误响应 | 保持无缓存和请求关联 | 不增加数据库来源、SQLSTATE、驱动文本、内网或凭证等公开字段 |
| DEP-08 | 写请求收到 503 或连接中断 | 保留原持久意图、幂等身份和资金预留，先查询/核对 | 503 不证明事务未提交；禁止新建 ID 盲目重提，不新增数据库/GPU 自动重试 |

Retry-After 是客户端等待提示。业务调用须使用原 Idempotency-Key 和原语义，已存在任务优先查询原任务。Provider 对准入结果未知继续使用原 RequestIdentity 查询；关闭/释放必须有原协议要求的证据。Connection invalidated 本身也不能证明 commit 未发生。

原日志白名单、查询预算、速率限制和容量限制不变。错误处理只能改善识别，不能解决底层锁/慢查询/IO 原因，也不能用 503 代替定位历史 502。

## 3. 实现及验证出口

1. 使用实际 HTTP 处理链验证固定白名单、断连标志、恶意/损坏驱动元数据、配置错误、IntegrityError 及查询取消；请求/日志中不泄露私有文本。
2. 原生 PostgreSQL 注入网关限流行锁、审计关系锁、查询取消和连接池占用，观察错误及恢复。原预算保持，失败调用不消耗网关限流或创建业务任务。
3. Provider 使用实际 HTTPS 客户端验证 503 传递，保持写请求 Uncertain；模拟“准入已持久化但返回 503”后，仅查询原意图、保留预留，最终只确认/计量一次。
4. 更新一次性原生故障探针，使用实际 API/Provider/Worker/PG 跨进程复验；ComfyUI/Redis/S3 夹具与真实资源验收明确分开。
5. 匹配风险完成 Python/Go 检查、完整工程回归、来源绑定及新的候选验证；同步需求证据、中英 README、更新说明和 Git。未执行的检查保持待验证，不沿用旧报告冒充当前。
