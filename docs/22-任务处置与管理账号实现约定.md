# 任务处置与管理账号实现约定

日期：2026-10-22；基于设计基线 v0.4。本文细化 [Admin 需求](./07-Admin可视化管理后台.md)、[数据库事务](./11-数据字典与数据库事务.md) 和 [接口协议](./12-接口契约与Worker协议.md)。实现与运行证据见 [开发记录](./17-开发记录与运行说明.md)。

## 任务处置

任务列表和详情返回租户、项目、逻辑 Key、优先级、版本、关联重试任务、执行尝试与 GPU 占用证据。默认不返回提示词；原始输入只有显式请求且具备 `content:sensitive` 时返回，并记录敏感读取审计。详情不返回渠道凭证、对象存储路径或内部下载令牌。

取消、重试必须携带稳定的 16～128 位可打印 ASCII `Idempotency-Key`；优先级修改还必须携带与请求 `expected_revision` 一致的 `If-Match`。管理幂等记录、业务动作和审计在同一 PostgreSQL 事务提交。重复请求返回同一结果；相同幂等键不同请求返回 409。

- 未领取任务可以立即取消；已领取任务只记录取消意图，由 Worker 提供停止或结果证据。管理操作不能直接释放物理 GPU、覆盖未知提交或把失联当作空闲。
- 只允许对 `failed/cancelled/expired` 且已无活动尝试和 GPU 占用的任务发起手动重试。重试建立有 `retry_of` 关联的新任务，保留原任务及种子，重新校验当前 Key、素材、模型、路由与配额，重新计算受理数。成功任务和未知执行状态拒绝重试。
- 网关任务必须由 Sub2API 的新预授权流程重试；通用后台重试拒绝网关及内部验证主体，避免绕过唯一金额账本。界面解释拒绝原因。
- 只允许尚未领取的 `queued` 任务修改优先级，范围 -100～100。领取器按优先级和提交时间排序；优先级修改不改变配额和原受理时间。
- 数据库约束保证当前尝试属于本任务、产物归属 Key 与其任务一致、重试父任务在同一租户/项目/Key 范围。

## 管理账号

管理账号只使用独立的 Admin 会话，不颁发业务 Key。首版支持 `administrator/operator/workflow_maintainer/observer` 四个固定角色；仅 `users:manage` 可列出、创建、启停、调整角色和重置密码。暂不声明自定义角色或分项目管理范围已实现。

用户名去除首尾空格并规范为小写，创建后不可修改；密码为 12～1024 字符，用 Argon2 保存。管理请求幂等摘要中的密码使用带服务端 pepper 的 HMAC，不保存明文或可离线猜测的裸密码摘要。所有响应、审计与事件均不返回密码或密码哈希。

启停、角色和密码变化增加账号版本，立即使旧会话失效。事务内串行校验“至少一个启用的 administrator”；禁止并发停用或降级最后的管理员。用户名唯一性、请求幂等、乐观版本冲突均由数据库事务处理。账号不提供物理删除，以保留审计关系。

## 验证边界

要求真实 PostgreSQL 并发测试覆盖同键重试只创建一次、配额重新检查、未知尝试不能重试、并发最后管理员保护、密码/角色变更后的旧会话失效，以及 HTTP 的 CSRF/角色/If-Match/幂等错误。浏览器验收任务详情、取消/优先级/重试入口和账号表单，所有自动化创建的浏览器资源必须在 finally 关闭。模拟证据不替代真实 ComfyUI、Sub2API 计费或 10/20 台实机验收。
