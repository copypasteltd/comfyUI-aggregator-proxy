# 52 · 租户项目与分层配额管理

日期：2026-10-24（Asia/Taipei）。本轮实现与本地验证通过，不代表完整首版验收。

## 1. 范围与兼容

补齐首版 Admin 对租户配额的实际管理入口，落实 ADMIN-01/09/11、JOB-03、KEY-01～12、DEV-13～17/22/23/25～32。管理员可创建租户及其项目，修改名称、启停和七类资源限制；查看当前未结束/生成占用与当日任务、图片、视频的已用与预留。实体 ID、项目所属租户及已接收任务的归属不可修改；历史引用保留，不增加物理删除动作。

新增 scopes:read、scopes:manage 管理权限。所有既有管理角色可读，只有 administrator 可写。业务 Key、Worker、网关服务身份不能调用这些管理接口；业务 scope 枚举保持不变。全部写入要求独立 Admin 会话、CSRF、Idempotency-Key；更新同时要求 If-Match 和 expected_revision。幂等重放返回原结果，不再次创建、增版本或审计。

租户创建不会暗中创建项目或授权模型；项目、Key、Workflow、渠道和公开模型仍按既有显式归属与权限管理。名称规范为 NFC、去首尾空白，1～128 字符，不含控制字符；同名允许，身份以 ID 区分。租户/项目启停分别持久化；停用任一层拒绝新的业务调用。已经接收的任务继续沿用冻结准入、路由、重试和计量；不因停用释放未知 GPU、清零计数、取消任务或生成第二份结算。网关已有请求的受限恢复/对账继续执行原服务身份规则。

## 2. 配额与请求速率

七类限制沿用 bounded/unlimited 显式模式：rpm、burst、daily_jobs、unfinished_jobs、generating_jobs、daily_image_count、daily_video_milliseconds。新管理写入必须提供完整 limits；bounded 为非负整数，unlimited 的 value 必须为 null。普通计数最多 9,007,199,254,740,991；rpm 最多 60,000，burst 最多 10,000，以限制持久速率窗口的大小。旧记录读取保持原契约，不通过读取接口重写既有值。日周期为 Asia/Taipei。

本地业务 Key 和可信网关映射业务请求，均在同一 PostgreSQL 事务内按 tenant→project→key 的固定顺序消费三个速率桶，使用各层当前 rpm/burst。任一层拒绝时，前面已计算的扣减一并回滚；更换或轮换 Key 不绕过父级限额。平台网关服务速率和受限恢复速率继续独立存在。速率状态不随配额编辑、停用或恢复清零；降低上限立即用于后续判断。

业务准入继续原子预留三层日额度/未结束额度，领取重读当前生成上限。编辑配额只更新配置版本与审计/outbox，不改资源桶、调度历史、任务状态或客户账本。上限低于当前使用量时保留真实占用；后续请求按新限制判断。用量快照不代表余额、收费、精确剩余容量或未来启动时间。

## 3. 接口与持久化

新增 GET/POST /admin/api/v1/tenants、GET/PATCH /admin/api/v1/tenants/{identifier}；项目使用对应 /projects 路径。分页每页最多 50，page 为 1～10,000；支持名称/ID 搜索、启停状态与项目的租户筛选。读取采用一致快照，批量查询父级及 active/当日资源桶，禁止逐行无界加载。

新增只读 /admin/api/v1/scopes/options，提供分页项目选择、名称/ID 搜索与指定 ID 解析。选项含可信租户/项目 ID、名称和启停状态；默认或 enabled=true 只列可用组合，enabled=false 只列任一层停用的组合。指定 project_id 时允许解析已停用的当前归属。渠道、Workflow、模型文件、公开模型、API Key 和网关绑定六类创建表单的“所属项目”选择器统一使用该接口，不能受 SessionView.scopes 的旧 100 项快照截断。旧会话字段保留为兼容缓存，不作为服务端授权依据，也不能被视为完整目录。

Key 内容共享项目/创建者等辅助授权列表仍需继续统一分页，不包含在本轮六处所属项目选择器的通过结论内；其完整性验收保持未完成。

tenants 与 projects 增加 revision，默认/迁移值为 1，数据库约束 revision>=1。修改使用行级 NO KEY UPDATE 锁与版本比较，保持同一事务的幂等结果、配置、审计和 outbox；不锁住无关租户，也不跨 HTTP 持锁。迁移前停止开发服务、备份并核验归档，之后核对默认值和既有配额/归属；完成 42 表恢复演练。存在新增配置版本时，降级拒绝丢失并发控制事实。

资源限制形状以 [resource-limits.schema.json](./contracts/resource-limits.schema.json) 为准；同步运行时 schema、DTO、OpenAPI、端点与角色目录、生成前端类型和 fixture。

## 4. 页面与交互

管理对象是租户/项目及其配额，使用者是全局管理员和只读运维人员。页面单一任务是选择作用域、查看已用与预留并修改明确上限。沿用控制台深蓝 #10293a、正文 #173346、背景 #f3f6f8、操作青 #087e8b、成功绿 #268162、受限橙 #bf5e31；标题 Bahnschrift/微软雅黑、正文 Segoe UI/微软雅黑、ID 与数值 Cascadia Mono/Consolas。布局采用租户/项目分栏切换、分页目录与详情抽屉；配额表将配置上限、父级限制、已用与预留对齐，不增无关装饰或后台轮询。

新增侧栏“租户与项目”。空租户可直接添加项目；创建/编辑抽屉提供名称、状态及显式无限制选择。限额更改前展示在途任务保留的实际影响；保存成功刷新目录，版本冲突保留输入并提示重取。只读角色无写按钮。项目选择器按需搜索和翻页，关闭或卸载时取消不用的读取；已有编辑对象可显示已停用归属，但不允许移动。桌面和手机均可完成创建、编辑和选择，不依赖悬浮或横向整页溢出。

## 5. 验证计划

以真实原生 PostgreSQL/HTTPS 验证创建、分页/搜索/ID、默认值、版本竞争、并发幂等和回滚；确认配置不清零桶、调度和计量。验证本地/网关的父级速率共享、三层拒绝整体回滚、不同租户隔离、停用/恢复、已经接收任务与受限恢复。覆盖非法 mode/null/负值/布尔/超限、跨租户项目、错误身份、CSRF、If-Match 和只读角色。

真实浏览器覆盖桌面/手机的租户→项目→Key 创建、配额编辑、冲突、停用、只读，以及超过旧 100 项之后的项目搜索/选择；所有自建浏览器和临时资源在 finally 关闭/清理。执行 Ruff、类型、完整 Python、前端构建、固定原生 Sub2API、候选隔离安装、迁移与恢复、文档及资源核对；历史证据与新运行分别记录。禁止 Docker/WSL/虚拟机和子代理。
