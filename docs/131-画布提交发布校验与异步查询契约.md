# 131 · 画布提交发布校验与异步查询契约

受托管画布在发现模型后可能遇到 Admin 重绑别名。新增可选 `X-Expected-Release-Digest` 请求头，保证新任务只使用用户选择的发布；旧客户端省略此头时行为与指纹保持一致。此补丁不增加第二套队列或修改 Worker 协议，不需要数据库迁移。

## 接口与不变量

- `POST /v1/jobs` 可携带 64 位小写十六进制发布摘要。非法值返回 422；匹配当前授权发布时正常准入，不匹配返回 `409 model_release_changed`，不建立任务、配额预留或持久幂等绑定。
- 携带此头时将摘要加入原始请求指纹；同一幂等键不能改用另一个摘要。省略时沿用原指纹。相同请求重放先返回原任务，再考虑当前别名是否改变、下架或引用是否到期。
- 准入事务对模型行持共享锁，覆盖读取发布、校验摘要和冻结执行规格，Admin 重绑与本次准入有明确先后关系。
- `GET /v1/access-policy` 在补丁实际实现后返回 `X-Studio-Contract: 1`；此头声明上述发布校验及本契约中的查询提示，不声明所有画布或真实 GPU 测试已经通过。
- `GET /v1/jobs/{id}` 对非终态返回与现有 POST 相同的 `Retry-After: 2`。终态不要求继续自动查询；网络错误不能推断任务失败。浏览器仍需服从业务 RPM 与 429/503 的提示。
- CORS 保持允许任意来源，并暴露 `X-Studio-Contract`；业务请求使用 Bearer 且不携带管理 cookie。HTTP 高端口与用户自管反向代理沿用现状。

机器契约见 [studio-submit-policy.json](contracts/studio-submit-policy.json)。实施须同步领域指纹、应用端口、仓储事务、路由、OpenAPI、兼容回归和部署记录。画布正式工作副本在 `无限画布/`，向本仓库 `app/apps/studio_web/` 同步审阅后的源码、锁与来源摘要，供后续原生构建；完整评估和验收归档到 `docs/studio/`。

## 3D 能力发现修正

真实目录核对发现 `/models` 返回 11 个模型，`/capabilities` 只返回 10 个，遗漏 TRELLIS2。原因是 `model-discovery.schema.json` 原条件仍把非音频全部视为需要 size 的图像/视频，并把 GLB 当成图片 MIME 校验；顶层枚举增加 image_to_3d 并不足以兼容完整投影。

在现有契约中为 image_to_3d 明确独立分支：输出必须为 model/gltf-binary；preset 只保留 quality，不接受 size、seconds 或音频字段；参数只声明 quality/seed/n。图片、视频、音频原约束继续分别执行。先更新文档机器契约，再同步运行时副本和摘要。补充完整 CatalogAdministration 投影与负向回归；修正不得掩盖不合法发布，也不修改发布记录、Workflow 图或既有文件限制。
