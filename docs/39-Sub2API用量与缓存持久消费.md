## 业务行为

预留与终态事务继续只执行一次资金变更。持久 effect 由独立后台循环领取，补写 Sub2API 原生 usage_logs，并刷新余额和 Key 窗口缓存；消费失败、重启和重复领取均不能再次扣费。订阅套餐、分组倍率及完整跨服务运行仍属于后续出口，本增量不改变当前仅接受 standard 分组的行为。

启用宿主时，每个模型必须显式配置 usage_account_id，指向既有、未删除、platform=openai 且 schedulable=false 的统计账号。启动和新预留均检查该账号；本组件不创建账号、不写入其凭证、不让普通供应商调度使用它。公开模型名最多 100 个 UTF-8 字节，匹配固定版本 usage_logs 的限制。客户端不能指定统计账号。预留时将统计账号和当时的分组 ID 冻结到意图，后续配置或 Key 分组变化不能重绑历史统计。

新增向前迁移 254；247～253 不改写。历史意图的统计映射保留 NULL，不从当前配置猜测回填。缺少映射的终态 effect 持续保留、退避并暴露固定错误码，不能伪装已记用量。组件级低层账本测试仍可创建无统计映射的意图，生产宿主不得接受缺少映射的配置。

## 消费事务

1. 领取按持久实例隔离，SKIP LOCKED，一次一个，默认租约 30 秒；只处理已到 available_at 且未确认的记录。旧 owner/fence 或过期租约不能首次完成本地步骤、退避或确认。
2. 本地步骤在短 PostgreSQL 事务中核对 effect 与不可变原意图。终态 settled 写一条原生用量；未派发/远端关闭的 released 只刷新缓存。图片数、视频毫秒计量、实际金额、公开模型、原分组和统计账号来自持久意图。图片模型未配置尺寸时，处理器把既有 1024x1024 默认值加入冻结规格；消费只读该请求，不能使用当前配置。尺寸审计标记 input，保留原请求尺寸，不伪装为实测输出。用量以原 ledger_ref 作为 request_id，唯一键为 request_id 与 api_key_id；重复必须逐项核对关键计量和归属，冲突拒绝，不吞掉不一致记录。
3. 金额经 NUMERIC 参数写入，不经浮点换算。当前余额计费 billing_type=0、rate_multiplier=1；图片 billing_mode=image、视频 billing_mode=video，视频秒数向上取整。用量记录不调用普通计费 Apply，不修改余额、冻结或 Key 计数。
4. 同一事务将用户关联 Key 的哈希失效事件交给固定上游 auth_cache_invalidation_outbox，并标记 local_completed_at。沿用上游跨进程 L1/L2 失效与第二遍处理；effect 不存储原始 Key。此步骤与用量一起提交，响应丢失时按持久标记重放。
5. 事务外调用实际上游 BillingCache 的 InvalidateUserBalance 和 InvalidateAPIKeyRateLimit。失败后按固定错误码退避，最多 60 秒；租约 reclaim 保留本地完成标记。缓存删除可重复，不使用非幂等增减操作。第一遍成功后持久安排 30 秒后的第二遍删除，减小并发旧值回填窗口；第二遍成功才确认 effect。固定上游另有异步缓存写队列，本增量不证明普通供应商路径的全局强一致缓存；第二遍删除也不是后续永无旧写入的证明。Provider 自身每次准入继续使用权威数据库检查，不能依据缓存放行资金或额度。

数据库步骤最多 10 秒；每次缓存阶段最多 5 秒。后台只保留一个当前 effect，不在内存排队；无工作及错误后等待固定轮询间隔。停止会取消并等待循环，不清理数据库租约，不丢掉 effect，不释放资金。宿主注入实际上游缓存，缺少依赖拒绝启用；禁用 Provider 时不要求该依赖。组件测试可注入有界协议替身，不能据此声称真实 Redis 已验证。
