# 94 · 队列等待估算与运行样本

2026-10-26。关联待办 06/09/25/48、JOB-03、DEV-07/08/13/22/25/26/29/32。此增量先实现可核查的等待估算，不签收真实 GPU、生产 Workflow 或容量。

## 范围和使用

Admin 任务详情提供独立的“估算等待”操作。GET /admin/api/v1/jobs/{identifier}/wait-estimate 使用 jobs:read 和独立管理会话；业务 Key、Worker、网关身份不能调用。不存在的任务返回 404，数据库故障仍沿用既有脱敏错误。读取不领取任务，不修改配额、公平历史、占用或账本。

预计区间表示从快照时刻到任务可分配生成槽位的等待，不含领取后的准备、生成和上传。实际已等待时间继续单独展示。结果包含快照、15 秒有效期、样本数量和时间范围；不提供精确队列位置或完成承诺。已经分配、结束或不在 queued/retry_wait 的任务返回 not_waiting。

## 样本依据

新领取的非验证、非 test_only 任务，在既有 attempt.channel_snapshot 中追加 wait_basis 摘要。摘要绑定不可变发布摘要、生成规格摘要、物理 GPU、渠道及其已应用配置 revision、运行批准和相符画像；不保存额外提示词、素材、地址或秘密。旧 attempt 缺少该摘要时不回填猜测。配置、批准、规格或发布变化后，旧样本不混用。

样本只来自同依据的成功任务，跨度为 attempt.created_at 到 generation_released_at，覆盖准备、加载和生成槽位实际持有时间，不使用任务总耗时或上传耗时。要求已收集输出、已释放槽位、时间顺序有效，且属于最近 24 小时。每张物理 GPU 只扫描最新 200 个 fence，使用已有 (gpu_id,fence) 唯一索引；每组至少 10 个样本，最多 200 个。验证任务、测试目录、失败任务和无依据记录不成为生产耗时样本。

## 估算模型与不确定性

只读一致快照最多包含 500 个未完成任务、64 张物理 GPU、50,000 个绑定/渠道观测和 12,800 条历史尝试投影。只读取生成规格、样本摘要及必要字段，不读取完整图、提示词、渠道凭证或产物内容；不逐任务查询数据库。四个场景合计计算预算为 750 毫秒，超出返回 capacity_limit，不延长控制 API 的排队预算。读事务继续使用现有 5 秒语句与 1 秒锁等待限制。

使用当前已应用并验证的渠道、批准绑定、设备容量和音频特性，排除排空、维护、规格隔离及 OOM 已失败 GPU。按真实物理 GPU 去重，同 GPU 多渠道共享一个时间线。占用不明、租约/启动过期、ComfyUI 观测过期或外部队列干扰不能按空闲处理。

模拟复用 tenant-service-aging-v1 排序和原来的派单成本，推进租户公平历史、优先级老化、当前租户/项目/Key 并发计数、重试可用时间和 deadline。占用在预计释放时才减少并发；上传中的任务已释放 GPU，不继续阻塞生成。运行中的剩余时间按相同依据的耗时分位减去已持有时长；超过 P95 仍未释放则不猜零等待。

分别使用历史 P50/P95 槽位耗时和两个稳定 GPU 仲裁顺序执行四个场景，返回场景等待的最小/最大值。它是条件估计区间，不是统计置信区间；条件为当前设备继续可用、没有新增任务/配置变化/失败，实际 Worker 轮询与网络会带来额外延迟。样本不足、前序未知运行、无法判断配额释放或超过窗口/扫描边界时返回 unknown 和固定原因，不套用图片/视频/音频调度基准冒充实测。

## 契约和验证

响应冻结于 [admin-wait-estimate.schema.json](contracts/admin-wait-estimate.schema.json)，同步 DTO、运行契约、端点目录、OpenAPI 和前端类型。首次接入和历史记录应正常显示未知；六类能力使用相同的规格及样本规则。业务 API 和 Worker 0.4.0 envelope 不增加必需字段，无数据库迁移或重写历史。

验证应覆盖单/多 GPU、同 GPU 多渠道、四种场景、租户公平与老化、并发配额、retry_wait/deadline、未知/过期占用、P95 超时、样本漂移与不足、六类规格、读权限、数据库只读和有界查询，以及页面取消请求/过期/移动端/键盘行为。原生 PostgreSQL 和合成样本仅证明实现，不能代替真实 Workflow/设备画像/排队质量验收。界面沿用 04·青柠原始资源，浏览器和本轮辅助服务必须清理。
## 返回状态和原因

| 状态 / 原因 | 处理逻辑 |
| --- | --- |
| estimated | 当前四种条件场景均可计算，返回区间及已使用的样本依据；不是统计置信区间 |
| not_waiting / not_queued | 已分配、终态或取消中，不返回数字 |
| unknown / validation_task | 验证任务不使用生产估算 |
| unknown / insufficient_samples | 参与时间线的至少一组缺少 10 条近期同依据成功样本 |
| unknown / stale_observation | 设备容量或任一相关渠道观测不新鲜 |
| unknown / uncertain_execution | 占用、fence、boot、租约、外部队列或超 P95 运行需要核对 |
| unknown / no_ready_route | 当前无满足配置、批准及能力条件的路线 |
| unknown / quota_blocked | 不能根据已知释放事件推算并发配额恢复 |
| unknown / deadline | 在目标截止前不能计算可分配时间 |
| unknown / capacity_limit | 扫描上限、模型事件边界或 750 毫秒计算预算触达 |
| unknown / execution_unavailable | 执行/并发快照不满足可推演的计数约束 |

任何 unknown 都不返回零或兜底调度成本。读取不会取消、延期、释放、重试或重排真实任务。客户端关闭详情、切换任务、隐藏页面或退出会话时取消请求并清除快照；过期数字不继续展示。

## 本机复现和演示

已有工程原生 Python 环境、PostgreSQL 与 Edge 后，在 app 中运行。浏览器测试只创建本次所属的临时数据库和 HTTPS API，不启动 Worker、真实 ComfyUI 或推理。

```powershell
.\.venv\Scripts\python.exe -m pytest tests/unit/test_wait_estimates.py tests/integration/test_queue_wait_estimates.py tests/integration/test_dispatch_transactions.py -q
.\.venv\Scripts\python.exe -m venv .local/browser-venv
.\.local\browser-venv\Scripts\python.exe -m pip install playwright==1.56.0
.\.venv\Scripts\python.exe -X utf8 scripts/capture-wait-estimates.py --run-id wait-estimate-local-20261026-c01 --browser-python .local/browser-venv/Scripts/python.exe
```

run-id 必须唯一，已有证据不覆盖。源输入首先单独保存，正常结束再核对前后摘要并写完整结果；私有登录信息只存在 app/.local 下且结束删除。当前机器的系统 Git 预检出现过超时，本轮使用桌面依赖包的原生 Git，并仅在子进程关闭 fsmonitor/untrackedCache；没有修改全局 Git 配置或提高门禁预算。

本轮 [浏览器证据](evidence/2026-10-26/wait-estimate-94-bounded/summary.json) 包含 3 份实际区间响应、6 张截图、10 项检查和 3 个 context 的关闭记录；[媒体索引](media/README.md) 提供原速 MP4/GIF 和摘要。截图沿用原始青柠，已检查 1440/768/390px、键盘焦点及 reduced-motion。

首轮重放断言不应比较动态 server_time，已按稳定字段修正。浏览器时钟安装顺序、回调参数和联合收集时同名测试模块的失败均保留。旧隔离测试库在 DELETE api_keys 夹具清理处超时，功能断言尚未执行；[原库保存记录](evidence/2026-10-26/queue-wait-test-database-preservation-94.json) 保留原数据库对象和数据，另建空测试库继续专项。这不宣称历史清理或全量 CI 超时已定位/修复，亦不签收真实设备与生产。
