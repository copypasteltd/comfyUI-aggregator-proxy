# 118 · 双 GPU 真实 ComfyUI 接入

用户于 2026-10-27 明确授权启动 remote-3080 / remote-4090 的既有 ComfyUI，并将两台设备及现有 Workflow 配置到已部署服务。本轮接入沿用原生 Windows、ZeroTier 私网、生产 PostgreSQL / 私有对象存储和原有图形 Admin。关联 DEV-01～05、07～22、25～32。

先核对设备身份、既有部署记录、启动器、队列和物理 GPU，再复用或后台启动既有 ComfyUI，监听 `0.0.0.0:8188`；不重装模型、节点或 ComfyUI 依赖。登记独立 Worker 身份与物理 GPU，通过私网内部入口回传心跳、配置、Workflow 和产物。公开 HTTP 39443 与任意来源 CORS 沿用现状。

逐项读取现有 Workflow 与 API 图，建立可追溯发布包、模型别名、输入标量/素材绑定、依赖指纹、输出规则和运行画像。原画布及用户输出保持；未知结构或缺少输入的条目应明确标记，不能以 UI JSON 已导入冒充可执行图或真实运行通过。接入后分别验证服务器到 ComfyUI、Worker 登记与同步、验证任务及内容交付；未通过的能力不标为已批准运行。

操作范围已获授权；若适配工作涉及实现修改，先记录兼容行为与验证。客户端当前强制控制源 HTTPS，需按用户已确认的普通 HTTP 私网部署要求增加显式、默认关闭的兼容配置，不能伪造 TLS 验证或修改全局网络策略。真实凭据、私有 Workflow、模型和完整拓扑只保存在受限交接目录；公开证据记录摘要、状态和验证边界。

实际接入、清理、验证结果与剩余限制在执行后追加。

原生 Worker 服务使用受限 PATH，两台机器也没有系统 Git。增加可选 `git_executable`，仅接受现有本地 `git.exe` 文件；默认仍使用 PATH 查找。依赖核验显式选择该程序，并只对当前本地仓库临时设置 `safe.directory`，不修改系统 PATH 或全局 Git 配置。原生 Python、Git 和 Worker 使用独立目录，不复用 ComfyUI 的依赖环境。

用户随后要求同步接入第三个 ComfyUI 地址；本机与服务器侧的两次独立连接均超时，已请求其在线状态与 Windows 管理方式。此目标保留待接入，不会用虚构 GPU 或代用另一台设备的身份登记。

读取真实 ComfyUI 0.42.1 history 后发现输出 subfolder 使用 Windows 反斜杠。Worker 仅将此相对目录的分隔符规范为 /，再执行既有相对路径和实际目录包含校验；文件名不做宽松转换，绝对路径、盘符及父目录越界仍拒绝。图像、视频、音频均须经服务实际产物回传检查后记录验证状态。
