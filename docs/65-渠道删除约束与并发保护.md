# 65 · 渠道删除约束与并发保护

2026-10-24，第 65 增量。先冻结契约和事务边界，再同步实现和验证；完整首版、五类图像/视频及 ComfyUI Workflow 音频范围不变。

## 问题与行为

文档 07 要求有活动任务、待完成核对或有效公开模型绑定时拒绝删除。原实现只查询未结束任务的候选引用，未完整保护公开模型、未关闭 attempt、在途管理指令及物理 GPU 事实。本轮修复真实管理出口，不通过隐藏按钮代替后端裁决。

新增 GET /admin/api/v1/channels/{id}/deletion-check，要求管理会话及 channels:write；读取无需 CSRF，不扩大只读角色权限。业务 Key、Worker、网关身份不能调用。不存在或格式无效的资源 ID 沿既有规则返回 not_found/404。返回 contracts/admin-channel-deletion.schema.json 定义的 channel_id/node_id/gpu_id、revision、snapshot_at、deleted、can_delete 及 blockers。它只是观测，不能作为随后删除的许可或缓存凭据。

blockers 为固定六类，依次检查：active_jobs（未结束 Job 的候选渠道引用）、open_attempts（本渠道 closed_at 仍为空的尝试，即使父任务已终态）、pending_commands（本渠道除 succeeded/failed 外的一切管理指令，包括租约过期和未知状态）、published_models（published=true 且引用该渠道的模型）、gpu_occupancy（同物理 GPU 的占用，包括其他实例及 uncertain）、gpu_management_hold（同 GPU 未解除的管理保留）。分别只返回 job/job/op/mdl/job/gpu 公开 ID，不返回提示词、素材、凭证、命令正文或现场路径。每类按 ID 排序读取最多 11 个不同 ID，展示前 10 个，has_more 表示截断，不把样本数当总数；最多六类、六十个 ID。已删除登记返回 deleted=true/can_delete=false、空 blockers，不读取现场或改变历史。

## 事务与竞争

预检在有界只读可重复读事务执行；5 秒语句、1 秒锁预算。DELETE 仍要求独立管理权限、CSRF、If-Match 和请求 revision 一致。写事务按 Node 共享锁 → GPU 写锁 → Channel 写锁取得当前登记，锁后重查身份及 revision，再执行同一六类检查；不写锁 Job、模型、Command 或 Operation，避免反向锁序。发布模型和任务准入既有 Channel 共享锁与删除互斥；所有管理指令准入必须先锁定当前 Channel，探测/扫描/诊断的原无锁读取改为 Node 共享锁及 Channel 写锁。DELETE 不跨网络等 Worker。

只要任一冲突仍在，返回既有 channel_in_use/409；与 GPU/渠道竞争的锁或语句超时返回脱敏 channel_busy/409，其他数据库失败返回固定 503。不得因为租约过期、任务终态或页面刷新就释放 unknown 占用、管理保留或未关闭的尝试。成功仅设置 enabled=false、draining=true、deleted_at 并递增 revision，登记删除和审计/outbox 原子提交；保留 Node/GPU、fence、占用、模型/Workflow、任务/尝试、配置历史和文件。已删除的重复请求沿旧行为返回登记，不新增删除审计。本轮不新增 DDL，数据库 head 保持 0a7d9b4e2136。

## 图形出口

渠道删除使用独立预检对话框，显示登记、观测时间、修订及各类阻断 ID，提供任务、操作中心、模型管理和 Windows 节点处理入口。内容在有界滚动区展示，窄屏操作按钮保留在视窗内。模型/操作入口进入既有列表，不声称新增尚未实现的详情直达。加载/失败/有阻断/已删除均禁用确认；显式刷新重新观测。允许时用户仍需明确确认，DELETE 在服务端重新裁决。失败不自动重发删除；409 后重取检查供用户再次审阅。读取 10 秒预算，隐藏、关闭、切换、注销和离页取消旧读取，迟到响应不得覆盖目标；已发出的删除有 10 秒预算，取消或超时不等于回滚，恢复后以读取登记为准，不自动重试。
