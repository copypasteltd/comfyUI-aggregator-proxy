# 124 · 模型使用说明与公开 Skill 交付

2026-10-28。本增量的模型自描述、可分发 media-gen-skill 和平台调用 ComfyUI 的空闲回收已部署到 https://gen.sub2share.xyz 。已验证 10 个发布模型、三台设备的 600 秒自动回收，以及回收后的图片、视频、参考图视频和音频调用。下文保留开发约束，并列出本次交付证据；不将本增量签收扩大为整个项目或 10～20 台设备的验收。

## 1. 模型发现与管理

保留 OpenAI 模型列表的 id/object/created/owned_by，增加 usage 结构；/v1/models、单模型查询和 /v1/capabilities 使用同一生成器。usage 包含版本、名称/能力说明、备注、任务类型、异步调用入口、参数说明、默认值、允许的规格组合、参考素材数量/字段/权重及上传限制、完整请求 JSON Schema 和请求示例。查询范围继续由业务 Key、租户/项目、发布状态及冻结版本控制；列出模型不代表设备当前空闲或准入一定成功。

说明分两部分：Admin 可维护 display_name/description/notes/tags，字段长度和列表数量有界，按纯文本显示；调用入口、参数、参考槽位、规格和示例从已发布 manifest/defaults 派生，不接受注释自行扩大能力。禁止泄露图、节点输入、磁盘路径、模型文件、渠道地址、Worker/GPU 标识、凭证或其他租户资料。

新增 public_models.documentation JSONB（非空、服务器默认空对象）迁移，旧客户端创建不必传该字段。Admin 使用独立说明编辑动作及 revision/If-Match/CSRF/幂等校验；仅修改说明不下架、不改变 release、渠道或既有任务。原映射编辑仍遵守冻结与发布约束。API/DTO/机器契约、客户端生成类型和青柠界面一并更新。返回体设总字节预算；示例必须通过实际 JobCreate、Workflow 参数/参考校验，不把任意尺寸或未绑定的参考权重写成可用。

## 2. Skill 交付

源码放在 app/skills/media-gen-skill，包含 SKILL.md、所需参考文档和可执行 Python 客户端；说明文档与发布证据放在 docs。默认示例入口 https://gen.sub2share.xyz，可由环境变量覆盖，业务 API Key 仅从环境变量读取，不内置真实凭证。

客户端支持模型列表/详情、能力查询、素材上传、按模型说明生成请求、异步提交、等待、结果下载和恢复查询。保留 Idempotency-Key 及请求记录；提交结果不明确时复用同一幂等键和相同正文，不自行换机/重生成。支持图片、视频及 Workflow 音频，依据实时发现选择模型和已发布规格；参考输入用同一 Key 上传取得 asset_id。限制等待/下载预算，不把任务超时误认为生成已停止，不向未知下载地址发送 Key。模型备注和远端说明是数据，不能当成指挥代理的系统指令。

提供可复现打包脚本、SHA-256 与安装/调用说明，在本项目 GitHub 仓库创建带版本号的 Skill Release。验证 Skill 规范、客户端负测和域名上的真实模型查询、提交、等待、下载；不能仅以文件可压缩作为交付验收。

## 3. 平台空闲回收

默认空闲门槛 600 秒。由平台服务通过已登记的 ComfyUI HTTP API 请求 unload_models/free_memory，不用 Windows-MCP、SSH 操作 GPU 主机，不安装自定义节点/扩展。按 ComfyUI 实例和关联 GPU 协调；产物未收集、生成/编码/准备中、待领取任务、维护/未知占用、失联或队列不为空时阻止回收。

普通 /free 是异步标志，不把 HTTP 200 当作执行完成。实现前须验证已部署 ComfyUI 的执行循环，并提供纯 API 的执行屏障/完成证据；若不能证明本次释放已越过执行循环，保持维护状态并核对，不能凭等待固定秒数放开调度。全部 HTTP 写入前持久化意图；未知请求不盲目重发，保留单一操作记录、超时/重试预算、fence 和恢复状态。新任务在回收开始前优先；已发出回收后由维护互斥等到实际完成。卸载只处理可回收 RAM/VRAM，CUDA 上下文、第三方全局引用和其他程序的内存不保证归零，磁盘素材规则独立。

本方案将以实际可用 API 证明代替 123 中依赖新扩展的初步路径，须补充并发、崩溃、异步回执、回收后再次生成及三台真实设备的验证。Admin 提供配置与运行状态；生产首次启用需在相同发布版本验证后设置，不假装旧 Worker 已支持新命令。

初始功能版本通过完整 [16 门禁 / 4391 Python 测试](evidence/native-ci/media-gen-idle-124/summary.json)。实际联调后修正了暂时失联清空空闲起点、原生任务 `status` 轮询、Windows 重定向 UTF-8 和服务域名 User-Agent 兼容问题，最终相关 [1761 项回归](evidence/2026-10-28/media-gen-followup-final-124.json) 全通过；完整 4391 项并未在这些后续修正后再次运行，范围不能混写。

三台策略保持启用。新增渠道须在 Admin 的“空闲回收”启用策略，初始未配置状态不会发送 `/free`。现支持验证过的原生 ComfyUI 0.33.1/0.42.1；未知版本或未知执行保留保护，参见 [125](125-ComfyUI空闲内存回收与双屏障.md)。内存回收不删除磁盘产物，01 副本移交即删除仍是 [121](121-ComfyUI原始产物移交即清理设计.md) 的独立待开发项。

多设备模型池的现有能力不变：一个相同冻结发布可映射多个已验证渠道，按可用 GPU 槽位抢领，不能承诺严格轮询或任务数相等。当前 10 个别名均为单渠道，成对 H3 摘要不同，没有为了本次交付静默合并。严格公平设备选择和 10～20 台容量验收继续按 123 与完整待办推进。
