# 第 47 增量：队列筛选、等待时长与实时负载

日期：2026-10-23。对应 ADMIN-07/08/10/12、QC14/15、WP-08/09/13。实施与验收结果在文末登记，未完成项不得写成已通过。

## 1. 冻结接口与计数口径

`GET /admin/api/v1/queues/snapshot` 与 `GET /admin/api/v1/queues/jobs` 接受同一份 [查询契约](./contracts/admin-queue-query.schema.json)：租户、项目、历史模型别名、Workflow、不可变发布版本、渠道、逻辑 Key、状态、创建时间范围和分页。各条件取交集；模型为完整匹配，不跟随当前模型路由改写历史任务。Workflow 按任务冻结的发布记录关联。时间为 UTC Unix 秒，`created_from` 包含、`created_before` 不包含，均限 0～4102444800；同时指定时前者必须小于后者。ID 前缀、状态、长度、未知字段和分页均验证；不认识的字段不得静默忽略。每页 50 条，页码 1～10000。

渠道筛选同时包含当前尝试已分配该渠道的任务，以及 `queued` 且尚未领取、允许该渠道领取的候选任务；已结束且当前尝试属于其他渠道的任务不因旧候选列表被包含。多渠道候选可能重复，禁止累加为全局任务数。快照的状态、未完成、未领取及渠道任务计数按同一条件过滤。渠道列表另按租户、项目、指定渠道过滤并分页；其他条件不隐藏零任务渠道。响应回显有效筛选条件和服务端采样时间。全局物理 GPU 占用、每渠道的真实 GPU 占用/人工保护和 ComfyUI 队列是实际资源事实，不被任务筛选缩减；页面必须明确这一差别。

`GET /admin/api/v1/queues/filter-options` 使用独立 Admin 会话及 `queues:read`；`kind` 为 tenant/project/model/workflow/release/channel，支持可选父租户/项目/Workflow、名称查询 `q`（最多 128 字符）、50 条分页。只返回 value/label、page/has_more；禁止携带 Workflow 图、地址、凭证、提示词或素材。模型选项含历史任务别名；归档 Workflow 仍可检索历史任务。任务列表保持 `jobs:read`，快照保持 `queues:read`；业务 Key、Worker 和网关身份均不能访问。

## 2. 实际等待时长

任务视图补充 `release_id`、`accepted_at`、`first_assigned_at`、`queue_wait_seconds`。等待从准入确认到第一次创建尝试；尚未分配的未完成任务采样到当前快照时间，尚未分配的终态任务截止终态时间。首次分配后固定，不将执行、上传或重试等待当作首次排队。未准入、缺少/逆序/未来时间证据返回 null，不伪造为 0；合法不足一秒为 0。此值是已发生时间，不是预测完成时间。详情和列表使用同一算法；一页任务的首次尝试时间批量聚合。

## 3. 一致性与前端行为

队列查询使用 PostgreSQL 只读可重复读事务，以批量聚合替代每渠道单独查任务和 GPU 的方式；渠道从 1 增至 50 时 SQL 条数不得随渠道线性增长。SQL 使用有界执行/锁等待时限，查询失败返回错误，不能伪造空队列。

筛选表单支持按名称检索租户、项目、模型、Workflow/发布与渠道；明确应用后才改变实时查询。旧请求不能覆盖新筛选结果，切页或筛选清理不匹配的数据；同条件刷新失败保留上次成功快照并显示错误。页面隐藏、退出或卸载时关闭本页 SSE、轮询、在途列表/选项请求；恢复可见须重新校验会话。SSE 为失效通知，数据由同源受鉴权快照查询得到；5 秒轮询作为兜底。

## 4. 验收边界

必须覆盖筛选交集、时间边界、历史路由、候选和已分配渠道语义、多个渠道共享 GPU、未知/过期 ComfyUI 观测、分页、等待时钟、四身份隔离、批量查询数量与浏览器旧响应/清理行为。

QC15 负载采用 20 个鉴权 HTTP 协议 Worker、500 个未完成任务、3 个 Admin 会话，测量从可见任务状态提交到页面/会话快照反映变化的延迟，P95 不超过 10 秒；同步记录 HTTP 耗时、实际资源计数及清理情况。协议 Worker、合成队列与浏览器测试不等于 20 台 Windows 实机或真实 GPU。真实设备、真实五类 Workflow、私有对象存储与公网代理仍待用户提供资源后验收。禁止 Docker/WSL 等虚拟化；测试只关闭自身进程、临时数据库与浏览器。
