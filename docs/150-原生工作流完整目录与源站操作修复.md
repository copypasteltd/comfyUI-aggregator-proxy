# 150 · 原生工作流完整目录与源站操作修复

用户要求系统修复原生面板与源站 Workflows 不一致。旧实现拦截全部 userdata 并只返回 Key 私有数据，遗漏源站目录；不能把“已加载原生前端”称作完整转发。2026-11-16 实测 RTX4090 源站有 386 个文件（306 个 JSON），平台测试 Key 目录为空，196 个节点模板一致。

## 修复契约

- 原生授权设备的 `workflows/` 采用真实源站目录及原有层级，兼容 userdata/v2 userdata、递归、split、full_info、Unicode 名称、文件夹导航、读取与下载。新文件随源站刷新可见，不按平台发布模型或可执行性筛选，不复制整个目录到云端私有配额。
- 已取得设备独占的可信原生操作者可保存、另存、重命名、删除源站 Workflow 文件；修改真实设备上的共享文件，源站直连和其他获准操作者能看到变更。修改沿用 Key/设备授权、CSRF、固定源与路径限制；不能指定外部地址或修改 workflows 之外的源文件。
- 原先云端保存的 Key 私有文件继续保留，映射至 `workflows/@personal/`，在 Workflows 中显示独立个人目录。Key 间隔离不变；原生工作区、自动保存和设置仍私有。`@personal`、`@source` 如与源机真实文件夹重名，源机同名部分经 `@source/` 逃逸显示，不能静默隐藏原文件。
- 源站修改使用持久幂等记录与审计：HTTP 前保存意图，已确认回执可重放；未知写响应先按文件摘要/改名前后状态核对，禁止盲目重投。利用现有 PostgreSQL Idempotency/AuditEvent，不改变数据库结构。HTTP 不跨数据库事务持锁。跨共享/个人目录的文件移动提示使用另存为，避免把两次文件变更伪装成原子移动。
- 元数据最多 10000 个文件、响应最多 4 MiB，单个 UTF-8 工作流文本最多 4 MiB；越界或源不可达明确报错，不伪装空目录。模型/节点缺失可由原生界面正常提示，不在目录层隐藏对应流程。源文件内容、原始凭据不进入公开日志或证据。
- Skill 中个人保存命令继续写私有目录；新增显式源站操作参数，说明共享影响，版本递增并按既有不可变发布流程同步。业务生成 API、任务/文件归属、日额度不限、开放 CORS、高位端口和用户域名反代规则继续适用。

## 首次面板加载的资源修正

上线浏览器冷启动发现扩展脚本与子工作流集中加载时出现连接超时，不能用单文件成功代替面板验证。资源转发改用生命周期内复用的 HTTP 连接池，每台设备最多同时读取 8 个资源，响应读完或取消后才归还槽位；禁收源站 Cookie，避免共享连接池携带另一个 Key 的上游会话。静态模块相对导入先按源站根目录解析，再挂载设备前缀，修正插件越过前缀请求 `/origin/scripts/` 的问题。

[84 项专项验证](evidence/2026-11-16/origin-workflows-150-transport-local.json) 已通过，新增并发响应生命周期、连接失败/取消释放、源 Cookie 隔离和相对模块导入检查；原 81 项结果保留。该结果属于本地组件验证，实际部署与浏览器结果另附，不表示未知扩展私有接口已全部兼容。

浏览器复查进一步发现高位 HTTP 入口 `worker_connections 128` 耗尽：同一轮 API 日志无 5xx，而入口出现 375 条连接槽不足记录，外层返回 502。固定原生容量工具仅把入口改为 2048 槽、Worker 文件描述符 4096、API 并发 512；摘要守卫、私有备份、配置校验与失败回退保留现有路由/CORS/私有监听，不修改用户域名代理或 TLS。新安装模板同步，单独记录运维工具来源，不替换应用运行载荷。[5 项容量和入口回归](evidence/2026-11-16/origin-workflows-150-capacity-local.json) 通过。

## 使用逻辑与剩余边界

1. Admin 为 Key 单独启用原生访问并选择设备；在 `/origin/` 登录后查看实时设备和源队列。
2. 查看 `Workflows` 即读取源目录；新文件随刷新出现。要修改共享流程或运行图，先取得该设备操作权。保存到原路径会修改源设备文件，个人另存选择 `@personal`。
3. 自定义执行仍用设备已安装节点/模型；运行结果留设备。归还前等待自己的任务结束；关闭标签或退出不会自动解除不确定执行占用。
4. Skill 用户参照[可复制命令](examples/origin-workflows-150/README.md)和[原生参考](../app/skills/media-gen-skill/references/comfy-origin.md)。共享操作须显式 `--shared` 与私有操作文件；改名使用 `move-workflow`，未知响应用原文件 `resume-workflow`，不换幂等身份重投。

这是受控原生入口：源 Workflow 共享，但历史、任务、下载及个人状态仍按 Key 管理。实际浏览器另观察到 43 个 403 和 7 个 404，主要是尚未适配的 rgthree 公共脚本/扩展私有接口、主题及缺失可选个人文件；这些未被伪装成成功。**不宣称所有第三方扩展、Manager 或主机接口均可用，也不把目录可见当作全部 Workflow 可执行。** 本轮核心目录/打开、共享文件操作与上线验证完成，全量候选生成、10–20 台容量及完整产品验收仍按原待办分别推进。

收尾复核：最终浏览器时段服务日志的 API 5xx 和入口槽耗尽均为 0，新入口 Worker 文件描述符为 4096。确认没有服务进程引用后，仅移除本轮中间发行 `150.1`，回收约 163 MiB，保留当前 `150.2`、原 `146.6` 回退和全部数据库备份；未删除客户内容或源文件。[清理及运行证明](evidence/2026-11-16/origin-workflows-150-housekeeping.json)。本次原生测试 PostgreSQL 已停止，自动化浏览器资源均关闭。双语 README、调用示例、媒体和更新日志随最终提交同步。
