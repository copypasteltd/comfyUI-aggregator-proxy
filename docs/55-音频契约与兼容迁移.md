# 55 · 音频契约与兼容迁移

日期：2026-10-24。状态：本地实现、合成协议与 Windows 候选验证通过；真实 Workflow、设备及生产仍未验收。承接 [54](./54-ComfyUI音频产物范围与开发约束.md)；本次冻结音频扩展的接口行为，实际 Workflow、模型和设备仍待用户后续提供。

## 1. 能力与规格

新增 `text_to_audio`，输入为 `prompt`，可由冻结 Workflow 声明 `negative_prompt`；不限定语音、音乐或其他声音。首批输入不接受客户任意节点参数、图、文件路径或音频文件。统一 `POST /v1/jobs` 异步提交、查询、取消与下载；这一扩展不等同于 OpenAI `/v1/audio/speech` 的同步二进制协议。

音频 Workflow 使用 `format_version=1.1`、`audio-files-v1`、`history_field=audio`，仅从已声明最终节点取得一个 `type=output` 文件。原五类继续使用 1.0，保持旧字段与精确视频时长语义。ComfyUI 官方 [SavedAudios](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_api/latest/_ui.py) 的 `audio` 列表包含 filename/subfolder/type；其他节点结构须另行验证适配，不隐式猜测。

音频预设由 `quality`、`seconds` 唯一选择，额外固定 `audio_format`、`sample_rate`、`channels`。音频没有 size/width/height/fps/strength。`seconds` 是输出时长上限，支持毫秒精度，最大 600 秒；短于上限的有效产物允许交付，按实际解码时长结算。长于上限的产物失败，不追加消耗。模型默认值必须匹配唯一预设；客户不能临时覆盖编码、采样率、声道或输出路径。

首批格式为 WAV（PCM s16le/s24le）、FLAC、MP3、Ogg Opus，规范 MIME 分别为 `audio/wav`、`audio/flac`、`audio/mpeg`、`audio/ogg`。采样率 8,000～96,000 Hz，声道 1 或 2，单文件上限 256 MiB；Opus 按实际解码的 48,000 Hz 发布。每个预设声明实际输出格式、采样率与声道，发布时检查其 MIME 与适配器一致。未通过样例验证的配置不得运行批准。

云端以原生 ffprobe 检查容器/codec/采样率/声道，并用 ffmpeg 完整解码核对非空采样和实际时长；探测、解码均使用固定参数、受控本地路径、仅 file 协议、超时与输出上限。文件大小、SHA-256、不可变存储版本沿用原有校验。扩展名只用于 Worker 的规范 MIME 映射，不构成媒体验证证据。

Windows 候选固定携带经 SHA-256 核验的 Gyan FFmpeg/ffprobe 8.1 原生二进制、GPL 许可证和构建 README，来源为本机既有 WinGet 安装，未把未知来源下载写成官方验证。构建来源见 [Gyan Builds](https://www.gyan.dev/ffmpeg/builds/)。四个文件以 `config/media-tools.lock.json` 锁定并纳入发布清单；0.5 候选缺少或篡改任一文件即拒绝安装/启动，入口优先使用包内工具，不依赖操作系统已安装 ffmpeg。旧 0.4 候选保持旧校验。Linux 原生二进制另行锁定与验收。

## 2. 权限、额度与结算

新增显式 `audio:create`，与 `jobs:create`、模型/Workflow/渠道授权同时检查。旧 Key 不增加 scope。新增 `spec_limits.audio_max_milliseconds` 与 `limits.daily_audio_milliseconds`；旧请求和旧记录缺省均解释为 0，Admin 必须明确配置后才能生成音频。Tenant/Project 的缺省音频日额度也为 0，不能用图片或视频额度替代。

受理按冻结上限预留 Tenant/Project/Key 三层音频毫秒，成功时从已验证产物取得实际毫秒，事务内返还差额；失败、取消、过期返还全部音频预留。每日任务受理次数保留。`usage_ledger.audio_milliseconds` 仅记录实际成功产物，终态唯一、幂等不重复；跨日释放回受理日桶。未知执行不放锁、不新开任务、不释放日额度。网关最终事件必须独立携带音频用量，不能冒报图片或视频。

数据库增加音频桶与账本非负字段，旧行默认 0；不改旧计量。迁移前验证原生备份和归档清单，恢复演练后记录证据。回退先排空音频任务并保留账本，禁止删除已有音频用量后降级。

固定 Sub2API 补丁沿用原 intent、余额/套餐预留、终态去重和持久副作用，不建立第二套货币账本。音频通过 `/v1/jobs`，内部操作标识 `audio.create`；价格显式配置为每开始一秒的单价，上限预留与实际结算分别向上取整到秒，控制面资源额度仍按整数毫秒。音频采用用户/分组通用倍率，不借用图片或视频专用倍率。升级新增独立 `audio_milliseconds`，用量日志新增 `audio_count` 与 `audio_duration_milliseconds`，旧值均为 0；`billing_mode=audio`，图片/视频计数保持 0。零值音频事件字段在 Go 重新编码时省略，保持旧终态事件摘要可重放。数据库和代码同时拒绝跨媒体用量、失败带用量及超预留扣费。迁移 256 只向前扩展，旧 Provider 写进程必须先停止。

## 3. Worker 与渐进兼容

保留 Worker 协议 0.4.0 的既有消息；注册 inventory 增加可选 `features`，旧 Worker 缺省为空。新版 Worker 明确声明 `audio-output-v1`；控制面仅向当前 boot 已声明该能力的 Worker 派音频，旧 Worker 可继续五类任务。注册资料由 Worker 身份持久化，业务请求不能伪造。能力变更不解除已占用 GPU、不把未知提交变为可重试。

机器契约以音频扩展 0.5.0 登记。公开发现、内容集合、Admin 筛选增加音频枚举；旧图片/视频响应不添加空音频规格。Key 与父级限额的新字段可缺省以兼容旧客户端，服务端新写入规范化为显式 0；任何省略均不获得音频权限。

音频也参与租户等份额与等待老化调度。无已批准运行画像时采用独立 `audio_baseline_milliseconds=300000`，只作保守调度估计，不作计费或性能承诺；有已批准画像时使用其 P95。旧队列策略响应可缺省该字段。发布包的必达任务清单增加音频，仍不将合成协议验证记作真实 Workflow 批准。

## 6. 配置和调用顺序

1. Admin「租户与项目」明确配置音频日额度；缺省 0 表示禁止受理音频。
2. 在「Workflow 管理」导入 1.1 音频发布包并冻结，绑定支持该模型/依赖的 Windows/ComfyUI 渠道。同步、验证样本和运行批准沿用既有流程，不能用冻结成功替代设备验证。
3. 「模型与路由」配置公开别名，选择质量和最长秒数；音频不填写分辨率。采样率、声道和文件格式由冻结预设控制。
4. 「API Key」明确授予 `audio:create`、`jobs:create`，设置音频最长毫秒与日额度，以及模型/Workflow/渠道选择；查询、内容读取和下载另需对应 scope。业务 Key 不能进入后台。
5. 提交后保存任务 ID，查询至成功后从任务产物取得内容 ID，通过授权内容接口下载。Admin「内容管理」选择文件类型「音频」，可查看 codec、采样率、声道和实际毫秒，主动点击后播放；关闭预览、切页或隐藏页面会释放媒体。

以下为已发布模型的请求形状示例，别名需替换成实际经过验证和批准的音频模型：

```http
POST /v1/jobs
Authorization: Bearer <业务 API Key>
Idempotency-Key: <同一次提交保持不变的唯一值>
Content-Type: application/json

{
  "model": "my-comfy-audio",
  "task_type": "text_to_audio",
  "input": {"prompt": "需要 Workflow 生成的声音描述"},
  "parameters": {"quality": "standard", "seconds": 2}
}
```

`GET /v1/jobs/{id}` 查看任务；成功后的 `artifacts` 给出内容 ID。`GET /v1/content/{id}` 查看已验证元数据，`GET /v1/content/{id}/download` 获取音频，支持 HEAD/Range。固定 Sub2API Provider 使用同一 `/v1/jobs` 形状及其公开任务 ID；音频不套用图片/视频兼容查询，也不声明 `/v1/audio/speech` 已实现。
