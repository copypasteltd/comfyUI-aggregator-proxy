# 40 · Sub2API 倍率与套餐计费

2026-10-23。接续 [29](./29-Sub2API持久意图与账本事务约定.md)、[33](./33-Sub2API服务托管与生命周期.md) 和 [39](./39-Sub2API用量与缓存持久消费.md)。涉及 DEV-07、11～17、23～27、29～32。先冻结本次计量、鉴权、迁移及验证约束；未附源码匹配的运行证据前，不表示功能已经完成。

## 计价与冻结

固定上游为 Wei-Shaw/sub2api 的 7da09cab4e875463baa79fc150adde700c5438df。本 Provider 仍使用受信模型配置中的版本化基础单价，不把通用供应商的模型名猜测、分辨率价卡或 token 价格套到自定义 Workflow。基础单价大于零；单位沿用图片张数、视频毫秒向上取整到秒。基础总价及倍率后单笔金额均不得超过 1,000,000 美元。

准入事务从上游数据库读取分组与用户专属倍率：默认使用用户覆盖值，NULL 时使用分组倍率；开启图片或视频独立倍率时，分别使用该媒体倍率，覆盖前述倍率。文字 token 的高峰倍率不叠加到媒体。倍率采用 4 位定点，金额采用 8 位定点；先算基础单价 × 实际单位数 × 倍率，最后一次按 half-away-from-zero 舍入到 8 位，禁止先舍入每单位价格或使用二进制浮点。零倍率和舍入为零的成功请求合法，不能人为收取最小金额；负值、非有限数及溢出拒绝。

新增向前迁移 255，保留 247～254 原摘要。意图冻结倍率、来源、余额/订阅计费类型及原订阅 ID。历史意图默认倍率 1、余额类型，保持旧金额；不猜测历史订阅。基础单价、最大单位数、价格版本与新计价字段禁止修改。重放使用原意图，后续模型价格、用户倍率、分组或套餐变化不能重报价或换计费主体。

## 套餐及事务

standard 分组使用上游 users.balance/frozen_balance。subscription 分组必须有当前用户和分组对应、未删除、已开始、未到期且 active 的 user_subscriptions；无有效套餐明确拒绝，不回落余额。复用上游 daily/weekly/monthly_usage_usd 记录已结算消费，不创建第二份客户余额。

锁顺序为用户 → Key → 当前分组共享锁（新准入）→ 原订阅行（如有）→ 意图。所有 Provider 实例与同一用户的不同 Key 在数据库中串行检查；日、周、月限额使用 NUMERIC 原值，加上该订阅全部未终态意图的倍率后预留金额。限额 NULL 或非正沿用上游无限额语义；旧窗口产生的未完成预留同样计入当前窗口。Key 总额度及 5h/1d/7d 窗口继续叠加所有未完成预留。窗口推进、额度检查、意图、预留和 effect 同事务提交，拒绝或故障必须整体回滚。

窗口计划复用固定上游的原有私有时间规则，通过新增 service 文件导出纯计算入口：日窗口按配置时区零点，短于或等于一天的一次性套餐不按日再发额度；周为 7 × 24 小时，月为 30 × 24 小时，保留旧零点锚点修正与到期边界。首次激活使用当前日零点与当前时间。SQL 锁住订阅后再应用计划，不能复制一个简化的“自然月”实现。

成功终态按冻结倍率与经验证计量结算；失败、取消、到期与未派发释放金额为零。订阅只增加原订阅用量，不改余额或冻结余额；余额类型维持原退款与结算。Key 计数、去重、意图终态、ledger_ref、effect 同事务。Key 改组、订阅暂停/软删除/到期不能免除已受理任务的原归属记账；外键阻止原订阅被硬删除。仍有效的原套餐在结算时推进窗口，实际费用记入结算时的当前窗口；已失效套餐不再激活或发放新窗口额度，仍增加原行用量。人工重置/续期遵从上游现有窗口，未完成预留继续占用当前准入额度。

相对文档 29 的旧行为，本次明确收紧 Provider 终态计数：已软删除 Key 仍增加其原 Key 的 quota/window 计数，保证余额或套餐、Key 计数与新用量可对账；保留 deleted_at 与当前禁用状态，不赋予新访问权。只修改本 Provider 的事务辅助函数，不改变普通供应商计费实现，不追补已经终态的旧历史计数。原回归用例保留名称并改为检验本条新约束。

本增量保证 Provider 自身的持久预留与结算；普通供应商路径仍使用其原有准入/在途机制，未改造为读取 Provider 预留的统一串行账本。不得把这写成所有供应商共享额度都已严格预留，混合路径的完整并发验收仍待跨服务验证。

## 鉴权、用量与缓存

固定上游认证仍核验 Key、用户、分组、IP 和资源权限。Provider 路由在服务端 Gin 上下文设置不可由请求头构造的标记，仅对其固定 POST 生成/素材入口，将预估余额/套餐检查交给本 Provider 的权威数据库事务；普通上游路由不获得该例外。这使零余额用户可以使用免费倍率或有效套餐，同时不能绕过撤销、过期、Key 限额或模型权限。资源读取沿用原有逐资源授权。缺套餐返回 403，套餐额度不足返回 429；错误消息不含订阅内部信息。

usage_logs 的 total_cost 保存基础实际金额，actual_cost 保存倍率后实际金额，rate_multiplier、billing_type 与 subscription_id 使用冻结值；失败计量为零。消费仍不再次扣费。订阅 effect 每遍同时清理余额、Key 窗口、原用户/分组的订阅 Redis 缓存与本实例 L1，并发布上游订阅失效通知；失败退避和第二遍继续持久化。原生组合根必须注入实际缓存和 SubscriptionService；不得用仅删除 Redis 的测试实现冒充生产 L1/pubsub 接线。两遍失效不证明上游异步旧写入永不回填，准入不能依赖这些缓存保证资金正确。
