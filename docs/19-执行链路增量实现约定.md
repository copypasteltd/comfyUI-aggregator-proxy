# 19 · 执行链路增量实现约定

2026-10-22。关联 DEV-08～11、18、20～23、26、32；补充文档 11/12 的原生实现细节，不改变任务状态和四类身份。

1. Worker 输出先申请任务限定的上传记录，云端生成对象键；首个实现使用鉴权流式代理上传，避免向 Worker 发桶级凭证。单图最多 32 MiB、视频最多 2 GiB，上传记录固定 position/bytes/SHA-256/media_type。重复申请须完全一致；网络和存储读写均不持有数据库事务锁。
2. 上传到私有不可变版本后，云端重新读取该版本并核对摘要、字节数和媒体信息；图片使用 Pillow，视频使用原生 ffprobe 的固定参数与超时。缺少媒体探测器拒绝交付，不把扩展名当作验证。临时文件仅在 app/.local，结束立即清除。
3. complete 仅引用同一 attempt 的已验证上传记录，校验稳定产物清单摘要、实际规格和当前结果租约，再在同一事务发布 Artifact、manifest、终态、资源结算、审计和 outbox。重复完成返回同一 manifest；不能影响已经复用 GPU 的另一个任务。
4. 节点 boot 共享锁在业务配额锁之前取得；注册新 boot 使用排他锁。管理命令改变运行配置前取得物理 GPU 管理占用，生成领取同时检查该占用。管理超时保留占用，不能按时间释放。读探测不改变运行环境。
5. Workflow 的结构冻结和设备批准分开。发布包不可编辑；应用后验证节点、依赖文件摘要和环境，再由管理员绑定有证据的设备画像。设备批准存于绑定的 runtime_approval，引用已成功交付的验证任务产物；不能让冻结包内自报 approved/evidence_id 自动批准设备。验证任务由独立内部逻辑主体创建，不给客户开放未批准模型。未提供真实 Workflow 和硬件前，不创建虚假的已批准生产能力。

新增表和字段通过 Alembic 独立迁移；已有 attempt 的渠道配置不可反推，旧数据须进入核对。协议字段同时进入实际 OpenAPI 和生成的 Admin 类型；机器契约中既定状态及事件不增删。模拟链路验证不替代真实 ComfyUI、私有 S3 或 Sub2API 运行验收。

模型管理沿用设计目录的 `/admin/api/v1/public-models`。增量提供 `/{id}/validation-jobs`，验证请求只接受规范生成参数与目标渠道，服务端使用不签发客户凭证的内部逻辑 Key；不能拿客户头指定内部身份。同步图片端点至多等待 60 秒，超时返回明确错误和原任务 ID，不在原同步入口返回异步成功形状。异步图片与原生 jobs 统一规范请求及幂等范围；multipart 临时上传 ID 不进入语义摘要，素材内容、角色和顺序参与摘要。

Worker 每 5 秒进行只读 ComfyUI 队列观测，最多 4 路并发，每次 3 秒、2 MiB 上限；心跳与探测独立。观测携带渠道配置 revision 和单调时钟测得的年龄，服务端仅接受当前已应用版本、年龄小于 15 秒的数据；队列时间独立于管理回执和清单扫描时间。失败、缺字段、过期、配置变化或新 boot 都显示 unknown/null，不能显示为零或释放 GPU。心跳返回仅该 Worker 的已应用渠道配置；Authorization 不进入 journal、管理读模型或日志。
