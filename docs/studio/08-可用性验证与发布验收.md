## 4. 证据格式和发布规则

每条真实生成证据至少关联：前端版本、服务契约版本、模型/发布摘要、任务类型、合法 preset、job/content ID、请求/响应状态、真实 MIME/尺寸或时长、字节/hash、到期时间、桌面/手机结果。提示词与参考图属于用户内容，证据公开前须去除业务 Key、管理会话、个人素材和其他敏感信息。

每条故障证据记录注入点、原意图和幂等键的不可逆摘要、重放次数、服务任务数量、最终状态和本机保存状态。任务数量从服务记录或可审查的测试数据库确认；截图上只有一张结果不能证明没有重复 GPU 调用。

上线前固定源提交、依赖锁、适配版本、静态包摘要及回滚包；同一包执行通过的证据应可追溯。发布后端或前端再改动相关链路，需要重验受影响门禁，而非一遍遍重复所有已通过且无变化的测试。

**发布条件：** G-01～27 的全部适用项有对应实现与通过证据，且没有未解决的 P0；范围减少需明确记录，不能通过删除验收项“通过”。当前只有评估和部分基线/离线证据，因此不能标记 `release_ready=true`。
