# 10 · 技术栈与工程结构

本文冻结首版的实现方向。应用已在 `app/` 建立；实际可执行命令和验证边界见文档 17。目标结构中的模块存在不表示对应首版出口已验收。

## 1. 技术栈基线

| 层 | 首版选择 | 边界 |
| --- | --- | --- |
| 云端与 Windows Worker | Python 3.13；独立虚拟环境，uv 管理与锁定 | Python venv 是包隔离，不是虚拟机；不共用 ComfyUI 的 Python/torch |
| 云端 HTTP | FastAPI、Pydantic 2、Uvicorn | 分 public/admin/internal/gateway 路由与认证依赖；不以 BackgroundTasks 承载持久任务 |
| 数据层 | PostgreSQL 18、SQLAlchemy 2.0、psycopg 3、Alembic | 2.0 为明确选用的成熟分支，不声称是最新；升级 2.1 另做兼容验证 |
| HTTP/存储 | httpx；S3 兼容 SDK 封装在对象端口后 | 所有调用有超时；同步 SDK 用有界线程执行，不阻塞异步事件循环 |
| Worker journal | Python 标准库 sqlite3，单 Writer，WAL，synchronous=FULL | SQLite 仅用于单机 journal，不能替代云端 PostgreSQL 队列测试 |
| 音视频校验 | 原生 ffprobe/ffmpeg 的固定版本；图片用受限解码器 | 音频完整解码并核对实际时长/采样率/声道；Windows 工具及许可证以 app/config/media-tools.lock.json 锁定，0.5 候选携带；以参数数组启动、禁止 shell=True，不接受任意滤镜/命令 |
| 管理前端 | Vue 3、TypeScript、Vite、Element Plus 2、Vue Router、Pinia | 中文界面；API 类型由冻结 OpenAPI 生成；不手写另一份领域契约 |
| 前端构建 | Node.js 24 LTS、npm、package-lock.json | npm ci 安装；精确补丁版在工程初始化时记录 |
| 验证 | pytest、Ruff、mypy；vue-tsc、Vitest、Playwright | 原生启动和本次浏览器资源清理；真实数据库单独测试实例 |
| 网关 | 固定 Sub2API commit + 狭窄 ComfyUI Provider 改动 | Go 版本以固定上游 go.mod/toolchain 和本机验证为准；不复制其账本 |
| 原生运维 | 云端 Linux 原生进程/systemd、Windows 服务封装 | 服务封装精确版本在部署前登记；本地不使用 Docker/WSL |

以上是项目选择，不是已经验证的一揽子兼容组合。WP-00 必须锁定精确版本、Python/Node 原生安装来源与哈希，生成 uv.lock/package-lock.json，并在原生 Windows 验证安装、导入、类型检查和最小构建。先 `uv lock --check` 核对元数据，再用 `uv sync --frozen` 安装；单用 --frozen 不检查锁文件与元数据是否仍一致。若特定包不能原生运行，先给出证据与替代方案，不私自切换虚拟化。ComfyUI 既有版本独立盘点，不随服务 Python 版本升级。[uv 锁定与同步](https://docs.astral.sh/uv/concepts/projects/sync/)。

选择依据与官方链接见 [06](./06-调研依据与兼容性核对.md)。Vite 构建不替代 TypeScript 类型检查，必须独立执行 vue-tsc；数据库 Session/AsyncSession 每个请求/任务独立，不能共享给并发协程。[Vue TypeScript 指南](https://vuejs.org/guide/typescript/overview.html)、[SQLAlchemy Session](https://docs.sqlalchemy.org/en/20/orm/session_basics.html)。

## 3. 模块边界

domain 不依赖 FastAPI、SQLAlchemy、S3、httpx 或 Vue；application 只调用 domain 与显式 Port。infrastructure 实现 Port，control_api/control_runner 为组合根。Worker 引用契约和纯值对象，不引用云端 ORM、数据库仓库或管理权限实现。前端只调用管理 API；浏览器不能直连 ComfyUI、Worker、数据库和对象存储管理面。

一个用例有一个清楚的数据库事务边界。路由负责身份输入、DTO 和状态码；领域拒绝非法状态；仓库负责锁和条件更新；审计由事务统一写入。不能让路由先改状态、Runner 再补配额，或页面通过调用两个不原子的接口实现发布。

control_runner 可多副本，但每项工作使用数据库行锁/租约；单进程假设不得作为正确性基础。首次版本不引入 Celery、Kubernetes、独立消息 Broker 或任务调度微服务。后续确需增加组件须有瓶颈数据和迁移方案。

## 4. 工程约定

- Python 全新代码使用类型标注，显式异常类型，UTC aware datetime；I/O 边界使用 DTO，禁止把 ORM 对象直接序列化给客户。
- Python/TypeScript 文件 UTF-8；Python/配置推荐 LF，PowerShell 按原生工具兼容；中文文件名只用于 docs，业务模块与 API 字段使用英文 snake_case。
- 客户 ID 视作不透明字符串；内部 UUID、公共前缀、时间、字节和 hash 规则见文档 12。禁止用浮点数累计钱或视频秒数额度，时长内部用整数毫秒。
- 配置启动时强校验；缺少数据库、密钥、存储或信任来源配置直接失败。开发明确开启的 fake adapter 只能绑定回环地址并在页面/响应标记模拟环境。
- HTTP 读取、连接、写入、连接池等待分别设限；重试仅用于有明确幂等语义的操作。不能为所有 POST 加统一自动重试。
- 日志采用结构化 event、request_id、job_id、attempt_id、operation_id；敏感正文默认不写。测试使用合成小文件和虚构凭证标记，不使用生产素材。
- 数据库迁移、接口契约、业务修复和纯重构分别说明目的，避免顺带批量格式化掩盖核心差异。

## 5. 原生开发入口要求

下表为脚本职责；已实现入口与实际执行结果在文档 17 区分记录。脚本输出 PID、绑定地址、日志路径和退出码，不能隐式安装系统服务或打开防火墙。

| 目标命令（工程初始化后提供） | 要求 |
| --- | --- |
| `scripts/bootstrap.ps1` | 检查原生 Python/Node/PG 工具，按 uv.lock 和 npm ci 安装；缺少系统依赖给明确错误 |
| `scripts/dev-start.ps1` | 仅启动任务 API、Runner、Admin 开发服务器和可选合成 Worker；默认 127.0.0.1；登记 PID |
| `scripts/dev-stop.ps1` | 只清理上述登记且身份匹配的子进程，不按泛化进程名结束用户程序 |
| `scripts/check.ps1 -Suite ...` | 统一调用文档、静态、契约和对应测试；失败返回非零；不自动略过真实 PG |
| `scripts/db-migrate.ps1 -Target ...` | 校验目标环境、备份策略和版本；与 API 启动解耦，不静默修改生产库 |

上述原生启动、停止、迁移和检查脚本已在 app/scripts 实现，本机实际验证结果及仍未通过的发布出口见 [开发记录](./17-开发记录与运行说明.md)。文档检查也可在项目根独立运行 `python -X utf8 docs/tools/verify_docs.py`，该入口不安装依赖、不启动数据库、浏览器或 GPU。脚本存在不表示完整生产部署与恢复已经验收。


第 49 增量的实际发布入口见 [49](./49-原生发布包与离线安装验证.md)：七项目构建后端固定 Hatchling 1.27.0，单独 release-build 依赖组与运行依赖由 uv.lock 锁定（75 个解析包）。Windows amd64 CPython 3.13 候选使用普通 wheel、离线 wheelhouse、Admin 静态资源和独立脚本，不依赖源码 checkout/editable 安装；运行状态在安装外。Linux/系统服务部署仍待后续原生验收。


第 50 增量以 domain/retries.py 固定首批分类和 5/15 秒退避，infrastructure/retries.py 做有界 PG 到期提升；新 RetryInfo 和 job-retry.schema.json 同步 API/OpenAPI 与 Admin，保持版本 0.4.0 的可选扩展。迁移 c5719fa03028 增加来源/次数/计划约束。测试隔离先核验准确数据库身份，保留真实约束并按依赖删除合成数据，避免逐例 TRUNCATE 带来的表文件替换与大量检查点同步。详见 [50](./50-有证据内部重试与计量保全.md)。

## 音频范围的工程约束

音频沿用现有 apps/packages 和四类身份边界，作为 ComfyUI Workflow 产物加入已有链路。新增音频契约/媒体探测/Worker 适配与 Admin 能力放入相应现有模块，依赖锁定并原生打包；不因新增媒体类型另建独立调度或绕过存储授权。运行契约 0.5 已支持音频本地实现，冻结行为与分层证据见 [55](./55-音频契约与兼容迁移.md)，真实资源验收边界见 [54](./54-ComfyUI音频产物范围与开发约束.md)。
