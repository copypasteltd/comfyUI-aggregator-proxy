# 112 · 输入素材发布未决事务与清理保护

2026-10-26（Asia/Taipei）。关联稳定待办 37/41/43/51/55/61/62、DEV-08/11/18/23/25/29/31。110 已保护输出发布确认不确定时的精确版本清理；继续检查输入素材时发现 ContentRepository._discard_unpublished 使用普通新快照查询。发布事务仍未结束时，暂时看不到 ObjectRecord 不足以证明对象未发布。本专题记录固定规则、真实 PostgreSQL 在途发布复现和当前源码完整验证。

## 固定规则

1. 输入发布事务已有的 ApiKey 行锁是本次清理的同步依据。清理使用可信上传身份的 key_id，在新的短事务等待同一 ApiKey 行锁，再用新语句查询精确 object_key/version_id；READ COMMITTED 与既有发布锁序保持。
2. 不改变发布流程的权限复查、幂等、配额或锁序，不增加全局锁或额外发布锁。同步使用已存在的 API Key 行；未找到该行或查询失败时保留对象，不能推断可以删除。
3. 成功查明精确版本没有 ObjectRecord 引用后，先结束数据库事务，再执行精确版本删除。存储 I/O 不持有数据库连接，清理不删除其他版本。
4. 清理错误不覆盖原上传错误，也不使有效的重复上传响应失败。日志只含固定 asset_cleanup_deferred_pending_publication_verification 标记，不含对象路径、SQL、身份或异常正文。
5. 用实际输入上传在 before_commit 暂停，记录独立清理连接的 PostgreSQL 锁等待。恢复后核对数据库引用、实际授权下载字节、幂等重放和唯一 Asset/ObjectRecord；该测试是受控提交窗口，不冒充实际网络断线或真实 S3 故障。
6. 真回滚、查询不可用、删除失败和重复上传另列验证。现有上传存储阶段不持有数据库锁、撤销后不发布、提交后确认丢失保护继续适用。

本次仅处理输入素材发布/清理的本地边界。六类生产 Workflow、物理 Windows、真实 Redis/S3、历史鉴权/审计/CI 根因、69 项完整待办和生产签收保持开放。不得提高既有超时或重试预算来获得通过；原失败报告保留。
