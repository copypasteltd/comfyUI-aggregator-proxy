# 46 · 生成失败归因与规格隔离

本增量落实 NODE-06、ADMIN-09/11、FAIL-13 与 DEV-07/08/10/17/20/25，推进 WP-05/06/07/08/13。先冻结以下约束，再同步契约、迁移、Worker、派单、Admin 与测试。真实 OOM、真实工作流及硬件容量仍需独立验收。

## 1. 归因与资源事实

新增固定失败码 comfy_oom、comfy_output_invalid。OOM 只读取已关联 prompt 的 ComfyUI execution_error 事件中的受控异常类型；不匹配任意错误文字，不上传 exception_message、traceback、current_inputs 或提示词。类型与事件形状参考 [ComfyUI 官方执行器](https://github.com/comfyanonymous/ComfyUI/blob/master/execution.py)，具体版本仍待真实联调。旧版 generic comfy_execution_failed 继续兼容，不猜测为 OOM。

只有当前 prompt 的失败历史或已完成的成功历史及受控输出拒绝，才按既有协议声明执行停止；超时、连接失败、队列仍包含该 prompt、输出仍在变化或事实不明确时保留 journal/占用，进入核对，不计为安全停止。输出归因包括数量、受控路径、体积及云端明确的媒体/规格拒绝；网络/存储 5xx、探测工具不可用、摘要传输不一致不冒充模型产物错误。所有终态与资源计量继续经既有事务，不能绕过 GPU/结果租约。

## 2. 隔离粒度、计数和派单

隔离键为物理 gpu_id + 不可变 release_id + generation-spec-v1 摘要。规格来自云端已冻结的执行：任务类型、公开参数（除 seed）、输入角色是否存在与参考数量；不保存 prompt、负向词、素材 ID/哈希或权重正文。相同规格在同 GPU 的多个 ComfyUI 渠道共享隔离；其他规格、其他 GPU 或新发布版本独立处理，仍遵守原授权/画像条件。参数保留规范化语义，数值等价表示产生相同摘要。

迁移新增 spec_isolations 表，保存规范规格、递增 revision、失败计数、最近失败/已验证成功的服务端生成停止时间、最近失败任务、隔离起点与原因、恢复验证任务及更新时间。唯一约束覆盖 GPU/发布/规格；租户/项目归属由来源任务决定并设置复合外键。所有新领取、计数、手工动作在同物理 GPU 行锁下串行裁决。

同规格在最近 10 分钟内、没有更新的已验证成功产物的两次独立安全终态失败触发持久隔离。只计 comfy_oom/comfy_output_invalid，Worker inbox/终态保证同一尝试不重复计数。传输后到的较旧失败不能覆盖更新的验证成功；较旧成功不能清除较新失败。计数与资源终态原子提交；已隔离后不因时间、重启或一次成功自动恢复。活动隔离永不按 TTL 清除；非活动记录超过 30 天可每轮有界清理。

只拒绝新的客户生成领取；既有领取重放、续约、核对、上传和完成继续。显式管理验证任务可以测试被隔离规格，客户不能伪造 is_validation。隔离不取消任务、不降分辨率/参考数、不更改候选授权，也不释放 GPU 占用或 management_hold。领取扫描使用与全局未完成硬上限相同的有界队列窗口，避免队首大量隔离任务遮蔽后续健康规格。

## 3. 管理接口与恢复证明

新增管理端点，均使用独立管理会话，业务 Key 无权访问。

| 接口 | 权限与写入约束 | 行为 |
| --- | --- | --- |
| GET /admin/api/v1/spec-isolations | channels:read；每页 50 条 | 按状态/GPU/发布筛选，返回安全规格、失败计数、原因、关联任务和 revision |
| POST /admin/api/v1/spec-isolations | channels:write、CSRF、幂等、If-Match | 输入已发生执行的 job_id、expected_revision 和受控 evidence_id；从服务端当前尝试定位 GPU/发布/规格，手工隔离，不接受浏览器指定租户/GPU/规格 |
| POST /admin/api/v1/spec-isolations/{id}/actions | channels:write、CSRF、幂等、If-Match | isolate 必须提供 evidence_id；resume 必须提供 validation_job_id；均校验隔离 revision |

恢复必须引用同租户/项目、同物理 GPU/发布/规格的显式验证任务：在最近隔离/失败之后创建，已通过云端产物验证并成功终结，证据不超过 24 小时，来源 boot 和渠道应用/验证 revision 仍匹配。不能用普通客户任务、他人规格、失败/在途任务或自由填写“已修复”文字代替。恢复只解除规格拦截，现行渠道/画像/容量/GPU 占用检查继续生效；未知占用不会被清除。

锁顺序遵守 Node 共享锁、任务需要的锁、GPU、规格状态；动作不在 GPU 锁后再写锁验证任务/渠道。恢复读取不可变终态证明，并由之后的新领取复查渠道配置与资源条件，不能借恢复批准环境或更改执行版本。原子写审计、outbox 和幂等结果；展示时不返回私有 Workflow 图/输入正文。

## 4. 图形流程与验证要求

Admin 增加“规格隔离”页面，支持状态筛选、分页、失败详情与任务编号、手工再次隔离和填写验证任务编号恢复；任务详情可从当前执行一键发起隔离。隔离以独立告警显示，并可进入处置页面。只读角色无写按钮；刷新失败保留明确的最后成功快照，隐藏/离页取消轮询，写入失败重试沿用幂等键，成功后的新意图使用新键。

至少验证异常类型/敏感文字不用于归因、当前队列仍运行时不确认停止、不同种子同规格、不同规格/GPU隔离、重复/迟到事件、传输后到的结果顺序、并发派单与人工隔离、200 条以上被隔离队首后仍领取健康规格、验证专用绕行、假验证/旧 boot/旧配置/过期证明拒绝、恢复与新失败竞争、保留未知占用、HTTP 四类身份/角色/CSRF/版本/幂等、浏览器处置及资源清理。新增 DDL 先备份/归档验证，并执行升级后恢复演练；具体执行结果后续登记。

## 6. 保留的开发服务与升级边界

第 82 增量补充：已确认的来源 OOM 即使进入 retry_wait，仍在原物理 GPU/发布/规格记录失败，不能用后续成功掩盖。其他 GPU 的成功不解除原 GPU 隔离；旧 OOM GPU 在本任务的后续准备重试中仍被排除。受控重试条件、证据与共享预算见 [82](./82-确认失败重试分类与跨GPU约束.md)，真实故障验收保持独立。

保留本项目原生 PostgreSQL、HTTPS API、Runner 和独立 GC，便于继续开发；只重启按 PID/路径/启动时间登记的本项目进程。所有原生回归进程根、临时数据库、媒体/凭据及本轮浏览器已清理。失败记录保留真实的迁移外键修正、测试收集/fixture 纠正、停止脚本竞态与浏览器选择器修正，不把重跑结果覆盖成从未失败。没有使用 Docker、WSL、虚拟机或子代理。
