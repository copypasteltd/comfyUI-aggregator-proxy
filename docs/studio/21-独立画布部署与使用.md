# 21 · 独立画布部署与使用

当前交付 `canvas-20261030.138.1` 是独立静态画布，公网入口为 **http://43.165.167.179:39445/studio/**。原 API 仍为 **http://43.165.167.179:39443**，管理入口仍为该 API 的 `/admin/`。画布只直接请求原有业务 API，未修改原 API/Worker/数据库/调度/转发配置。

## 使用流程

1. 打开画布，进入连接页。API 地址填写 `http://43.165.167.179:39443`，不是画布的 39445 端口；使用原 Admin 提供的业务 API Key。默认不勾选记住 Key，按需自行选择；不要将 Key 放进 URL、截图、导出或源码。
2. 连接后读取模型目录与实时用法。选择当前 Key 有权限且已发布的模型；尺寸、时长、参考槽位和输出格式按原 API 的 Schema/preset 显示，不按名称猜测。
3. 新建画布并点击新建创作，填写参数及参考素材。首帧视频、多参考视频是不同能力；音频是 ComfyUI Workflow 的产物；GLB 提供原件与静态交互预览。
4. 提交前先完成本机原请求日志事务；收到任务 ID 后只查询该 ID。响应丢失先核对原提交，不换 Key、模型、参考图或幂等键盲目重提。API 未声明核对能力时保留未知状态。
5. 可以离开后恢复原任务。停止本页等待只停止查询；远程取消须单独请求，并以服务端终态为准。不要把关闭浏览器当作停止 GPU 计算。
6. 成功后核对内容类型、长度和 SHA-256，再载入本机素材与画布。预览失败仍可保存原件；损坏下载不能标作已保存。
7. 云端产物沿用原系统的完成后八小时到期规则。本机副本独立管理，浏览器清理和配额可能影响保留，请另存原件或导出作品 ZIP。任务清单 JSON 备份原请求和编号，不包含媒体原件或连接 Key。
8. 管理 Windows 渠道、Workflow、模型、业务 Key 和队列时，在独立窗口打开原 Admin。画布不提供管理接口，不接管调度，不直连 ComfyUI，也不发送删除原件或释放显存命令。

新端口/域名属于新浏览器源站，**不会自动继承旧画布的 IndexedDB 或 Key**。迁移前从旧入口导出作品 ZIP、必要原件和任务清单，再到新入口导入并重新连接原 API。作品 ZIP 中任务转为说明，不重提生成；任务清单导入后需显式查询原 ID。确认新副本可用前保留旧数据。当前数据库为 v4，静态回退不能降级或清空它。

## 原生构建

源码位于独立仓库 `infinite-canvas/`，应用位于 `web/`。已验证的原生工具链为 Node 22.14.0/npm 10.9.2。以下为 PowerShell 示例，不依赖 Docker、WSL 或原 API 工程：

```powershell
Set-Location infinite-canvas/web
npm ci
$env:VITE_BASE='/studio/'
$env:VITE_STUDIO_MODE='managed'
$env:VITE_AGGREGATOR_ORIGIN='http://43.165.167.179:39443'
npm run typecheck
npm run build
```

部署 `web/dist/`，提供 `/studio/` 子路径、正确 MIME 和 SPA 深链回退。API 地址是公开默认值，Key 不得进入构建环境。未配置默认 API 时连接页留空。**保留 `managed` 模式**；上游名为 `standalone` 的模式包含可选脚本/Agent，不代表本次要求的独立部署。

## 当前服务器布局

| 项目 | 当前值 |
| --- | --- |
| 公网端口 | 39445；独立原生 Nginx 静态服务 |
| 发布目录 | `/opt/infinite-canvas/releases/canvas-20261030.138.1/` |
| 画布指针 | `/opt/infinite-canvas/current` |
| 配置 | `/etc/infinite-canvas/nginx.conf` |
| systemd 单元 | `infinite-canvas-static.service` |
| 运行目录 | `/var/lib/infinite-canvas/`，由 www-data 使用 |
| 原 API 指针 | `/opt/comfyui-aggregator/releases/linux-20261030.137.1`，保持原样 |

静态服务没有 `/v1/`、`/admin/`、`/internal/` 或 Agent 代理路由；对应探测均返回 404。业务请求从浏览器直达 39443，使用 Bearer 且 `credentials: omit`。原 API 已允许任意 Origin，本轮只验证、未改写 CORS。

当前独立配置样本：[Nginx](deployment/nginx.conf)、[systemd单元](deployment/infinite-canvas-static.service)。它们仅适用于上述新画布目录；不要覆盖原API或全局Nginx配置。

主文档和 Schema Worker 分别设置 CSP；Worker 仅为本机参数校验所需的策略。主文档不因此开放任意脚本。服务器现有 Nginx 为 BT 发行版，需要读取其已安装的 resty Lua 路径；该路径只写入本画布的独立配置。

首次部署遇到 PID 文件属主及 BT Lua 搜索路径两项故障，失败记录保留，修复仅限新画布服务。当前已启动并完成 HTTP 就绪检查；原 API、Runner、HTTP Worker、Edge 的 PID、指针及配置摘要前后相同。没有重启原服务。

后续发布应建立新的独立静态目录，核验摘要再切换画布自身 `current`；回滚同样只操作画布。不得切换 API 指针、升级 Worker 或执行 API 数据迁移。原 39443 `/studio/` 旧入口保留用于用户迁移；不自动清空本机库。当前 HTTP 部署供用户后续自行反代，不增加 HTTPS 验收条件。
