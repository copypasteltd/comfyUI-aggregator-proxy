# 120 · 参考能力发布与精确尺寸验证

2026-10-27。本轮落实用户要求：继续发布、真实验证参考生图、多参考生视频，并覆盖前述 `720x1080` 参数输出要求。涉及 DEV-04/08/09/15/17/18/20/21/25/29/30/31；执行前状态为 241 草稿、3 已发布模型，参考三类的冻结、绑定、验证任务、批准和模型均为零。

## 实施与验收约定

1. 复用两台已接入 Windows/ComfyUI 和原生 Worker，不安装节点、不下载模型，不调用 Docker/WSL/虚拟化或子代理。只通过现有 Admin、业务和 Worker 协议维护生产状态，不直接修改生产业务表。
2. 为单图生图、双图参考生图、单首帧视频、原生双图参考视频选择已有候选。最后一类必须由两张输入实际连接到 H3 的两个参考条件，不能用首尾帧或批量视频替代。
3. 图片与视频增加受控 `720x1080` 规格。H3 内部按 32 网格生成，再通过固定输出裁切得到精确 720×1080；说明内部尺寸、裁切位置及默认时长，不能将内部尺寸直接冒充下载尺寸。既有公开文字生图/视频规格同时保留。
4. 每个发布版本先完成依赖同步和成功真实验证，使用同渠道/版本/运行配置的产物批准，再发布别名。业务 Key 另行验证发现、图片上传、异步提交、幂等重放、任务查询、鉴权下载及真实媒体尺寸；输入的顺序和用途写清楚。
5. 验证素材由本项目自制/既有自制样本构成，不使用设备上客户原图、声音或原画布中的业务提示词。私有原图、API Key、完整图、内部地址与日志不入库。公开证据保留元数据、摘要、成功/失败边界，媒体副本移除内嵌生成元数据。
6. 视频文件混合参考候选须单独核对。当前图片素材契约不能宣称接收视频参考文件；不得将此类草稿直接发布。自动分类遗漏作为独立问题保留，不以图片参考发布掩盖视频文件输入缺口。
7. 同步时维护渠道排空与恢复。已受理任务继续沿冻结快照；未知提交只核对原任务，不盲目重试。已有业务 Key 不擅自扩权；新版本需要对应授权。
8. 完成后更新中英 README、CHANGELOG、调用示例、真实截图/录屏/GIF、分层证据和待办，执行文档及需求证据门禁后提交推送。

## 调用流程

Admin 中依次完成渠道登记与探测、Workflow 草稿整理、冻结版本、同步环境、真实验证、运行配置批准和模型发布。模型别名、发布版本、渠道、质量、参考数量和配额都需要落在业务 Key 的允许范围内；新增版本不会自动扩大原 Key 的权限。调用方从 `GET /v1/models` 发现自身获准且当前可用的模型。

参考图片先通过 `POST /v1/assets` 上传，得到 `asset_id`，再提交生成任务。图片素材当前接收 PNG/JPEG/WebP；不接收本地 Windows 路径、任意远程 URL 或视频文件。输入顺序由冻结图的绑定决定；本轮多参考模型固定使用两张图片，不能据此宣称每个模型都支持任意 2～4 张参考。

下列 JSON 使用项目的 OpenAI 样式异步扩展。每个新的生成意图使用独立 `Idempotency-Key`；超时后用原正文、原 Key 重放，再按原任务 ID 查询。相同幂等请求不会新建任务；明确终态过期后再次生成属于新请求，须记录原任务并另取幂等键。

```bash
curl -H "Authorization: Bearer $COMFY_AGGREGATOR_API_KEY" \
  -H "Idempotency-Key: my-reference-upload-01" \
  -F "file=@reference-0.png" "$BASE_URL/v1/assets"
```

单图生图：

```json
{
  "model": "comfy-3080-image-edit-wai",
  "prompt": "A green lime beside a white ceramic cup, soft daylight.",
  "source_image": {"asset_id": "asset_REPLACE_WITH_UPLOAD_ID"},
  "size": "720x1080",
  "quality": "standard",
  "n": 1,
  "response_format": "url"
}
```

将正文发往 `POST /v1/images/edits/async`。两图参考生图使用同一入口，模型改为 `comfy-3080-image-refs-wai`，移除 `source_image` 并增加：

```json
{
  "references": [
    {"asset_id": "asset_FIRST_UPLOAD_ID", "role": "subject"},
    {"asset_id": "asset_SECOND_UPLOAD_ID", "role": "style"}
  ]
}
```

`subject`、`style` 表达输入顺序与用途。本轮 WAI 图将两张图片组成 ImageBatch 后共同送入 IPAdapter；未提供各图独立权重，也未验收多人物身份一致性。单图编辑采用原图重绘参数，不能保证主体或局部像素严格不变。

单首帧视频发往 `POST /v1/videos`：

```json
{
  "model": "comfy-4090-video-h3-i2v",
  "prompt": "A fixed camera, a lime and a white cup, very subtle movement.",
  "input_reference": {"asset_id": "asset_FIRST_UPLOAD_ID"},
  "size": "720x1080",
  "quality": "standard"
}
```

多参考视频使用同一入口，模型改为 `comfy-4090-video-h3-refs`，移除 `input_reference`，增加上述两项 `references`。H3 参考视频图分别连接两个参考图条件；它不是首尾帧任务。单首帧形式也可用一项 `references`，但其角色必须为 `first_frame`，不能写成 `style`。

成功受理返回任务 ID。通过 `GET /v1/jobs/{id}` 轮询，成功后读取 `artifacts` 中的内容 ID，用同一业务 Key 调用 `GET /v1/content/{id}` 和 `/v1/content/{id}/download`；下载支持 HEAD 和 Range。云端正式产物在成功完成后八小时到期，按 `expires_at` 及时保存；下载到客户端的文件不受云端 GC 管理。相关规则见 [119](119-云端产物八小时保留.md)。

## 原生验证工具

[verify_reference_api.py](../app/scripts/verify_reference_api.py) 可用于上述六种模式，实际执行上传、异步提交、原幂等请求重放、任务查询、鉴权下载、摘要、HEAD、Range 和发布尺寸检查。输出目录保存私有请求状态、验证 JSON 和下载文件，重试时必须保留该目录以及 `--request-id`；目录中会包含调用提示词和业务 ID，不应提交到公开仓库。

```powershell
$env:COMFY_AGGREGATOR_API_KEY = 'YOUR_BUSINESS_API_KEY'
python app/scripts/verify_reference_api.py `
  --base-url http://YOUR_SERVER:39443 `
  --model comfy-4090-video-h3-refs --mode video-refs `
  --prompt 'A fixed camera shows a lime and a white cup in soft daylight.' `
  --reference C:/inputs/reference-0.png --reference C:/inputs/reference-1.png `
  --request-id example-video-refs-001 `
  --size 720x1080 --quality standard `
  --output app/.local/reference-check/example-video-refs-001
```

`image-edit`/`video-first-frame` 要求一项 `--reference`，`image-refs`/`video-refs` 要求两项，`text-image`/`text-video` 不接受参考图。通过 `--seconds` 只能选择该版本中已有的时长；本轮参考视频使用默认约 5.167 秒。请求的尺寸和质量必须匹配冻结预设，任意长宽不是通用支持承诺。

## 精确尺寸与兼容范围

WAI 图像路径使用八像素网格，可直接输出 720×1080。既有 Krea2 文生图及 H3 视频路径先生成 736×1088，再固定从 `(x=8,y=4)` 裁出 720×1080；这是边缘裁切，构图应保留余量。没有将低分辨率放大冒充该规格。既有文生图默认 1024×1024、文生视频默认 864×480 保持；V2 新增受控的 `720x1080`，实际已验证规格以本轮结果表为准。

视频文件参考、混合图片/视频参考、任意参考数量/尺寸/时长、全部候选 Workflow、10～20 台实机容量、完整 Sub2API 运行接入和完整首版签收仍需独立验收。候选分类中视频输入节点的遗漏保留为待修复项，未将这些图发布为可调用能力。

实际后台拍摄另发现静态包回归：119 部署带入不含既有 HTTP UUID 兼容入口的旧 Admin bundle，普通 HTTP 登录报 `crypto.randomUUID is not a function`。逐字节核对 116.2 中的 45 个已验证 Admin 文件后，将其作为独立静态发布 `admin-20261028.120.1` 恢复，配置备份后仅重启 API。两个现有 UUID 测试复验通过，浏览器以真实普通 HTTP、`isSecureContext=false` 验证登录；未使用 HTTPS、浏览器安全豁免或页面内临时补丁。后端仍为 `linux-20261027.119.1`，Worker 仍为 `rc-20261027.118.3`；后续打包须保留该静态版本及其源摘要，避免再次带入旧资产。

最终后台有 7 个公开别名，两个渠道启用且未排空，测试无未完成任务、GPU 占用或管理保留；两个临时业务 Key 均禁用。已关闭本轮浏览器上下文和浏览器，保留正式 ComfyUI、Worker、云端 API/Runner/GC 服务供正常使用。
