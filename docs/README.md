## 已确认的目标

- 将现有 Windows + ComfyUI 的生图、生视频及音频 Workflow 产物作为对外服务。
- 架构至少支持接入 10～20 台 Windows 设备；调度资源进一步细化到 GPU 与 ComfyUI 实例。
- 完整范围包含文生图、文生视频、图生图、多参考图与文本生图、多参考图与文本生视频。
- 最终正式范围同时包含 ComfyUI Workflow 音频产物，复用同一调度、Key、Admin 和内容体系；音频本地实现与协议验证已通过，实际 Workflow 与设备待验收，范围和冻结契约见文档 54、55。
- 优先对接 Sub2API，尽可能沿用 OpenAI 请求与响应格式；客户端接受异步任务。
- 云端接收请求、保存任务、调度设备并管理交付文件；设备经加密私网与云端互通。
- 首版必须交付可视化 Web Admin，可管理渠道地址、Windows/ComfyUI 接入、Workflow 与模型，并实时查看全局及各渠道队列；管理 API 不能替代图形界面。
- 首版 Admin 可创建和管理多个对外业务 API Key，分别限制操作、模型/Workflow/渠道、内容范围和调用额度；用户已确认用途是对外生成与内容 API，后台管理采用独立账号/会话。
- 项目文件位于 `E:/dev/sandbox/生图生视API封装/`；所有项目文档放在本 `docs/` 目录。
- 本地开发和验证禁止使用 Docker、WSL 等虚拟化环境；使用浏览器后关闭不再需要的标签页。

## 建议结论

采用 **Sub2API 接入层 + 可视化 Admin + 云端持久化任务服务 + Windows Worker + 规范化 ComfyUI Workflow + 云端对象存储**。

10～20 台设备适合先用单个云端控制服务和关系数据库管理。Windows Worker 主动连接云端领取任务，ComfyUI 只在本机监听。私网用于控制通信和运维，生成文件由 Worker 上传至云端管理的对象存储，再交付客户。

OpenAI 格式兼容必须拆成三项验收：图片生成/编辑协议、异步任务扩展、视频协议约定。图片异步后缀、多参考图角色、工作流参数并不是统一的 OpenAI 标准。所查 Sub2API 版本还存在图片模型名校验和视频供应商路由限制，因此完整目标需要一个明确的 ComfyUI Provider 适配边界。[源码依据见调研记录](./06-调研依据与兼容性核对.md)。

## 关键边界

1. 云端数据库保存权威任务状态；ComfyUI 的运行队列只承载近期执行任务。
2. 外部调用者只能选择公开能力和受控参数，不能上传任意工作流 JSON、节点代码或模型路径。
3. 单 GPU 默认只执行一个生成任务；20 台设备不代表 20 台设备支持同一个视频模型。
4. 任务成功必须同时满足生成完成、产物有效、云端文件可访问；上传失败优先续传。
5. 分布式通信按可能重复交付设计，通过幂等、租约、执行记录和结算唯一约束避免重复交付与重复扣费。
6. 图片同步等待仅作为兼容入口；视频和长排队任务使用异步方式。
7. 所有分阶段工作最终都必须覆盖原五类及音频共六类 Workflow 能力和 10～20 节点调度，不能用两台机器出一张图代替完整验收。
8. 首版必须通过实际浏览器操作验收 Admin；共享候选任务按全局去重，不把各渠道候选数直接相加。
9. 对外生成、任务和内容 API 必须鉴权；独立 Key 默认隔离，显式共享仍受租户边界约束。Key 不可用于登录 Admin 或调用后台管理接口。

## 执行文档校验

在项目根使用原生 Python 执行 `python -X utf8 docs/tools/verify_docs.py`；需要重写记录时加 `--write-report`。工具不运行文档里的 shell 示例，不启动数据库、GPU、浏览器或任何虚拟化环境。检查失败返回非零，报告包含文件 SHA-256 与实际检查范围。

实现采用 Python/FastAPI + PostgreSQL + 原生 Windows Worker，Admin 为 Vue/TypeScript；精确依赖以 `app/uv.lock`、`app/apps/admin_web/package-lock.json` 和 `app/config/native-toolchains.lock.json` 为准。数据库队列、journal、GPU 与结果权分离、四类身份和资源配额仍为强约束。各项初值不能作为现有设备能力或上线性能承诺。
