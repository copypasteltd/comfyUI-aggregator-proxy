# 21 · 内容保留与回收实现约定

2026-10-22，DEV-11、15、18、23、26、27；补充文档 08、11、12、15。真实 S3 与容量门禁仍待验证。

1. job 准入在同一事务建立输入 asset 引用，包含 admission_pending。新准入锁定并重新确认素材未删除、对象已验证且未到期；与删除/回收竞争时只有一个路径成功。Worker 使用当前租约及冻结引用读取输入，不能扩大到同项目其他素材。
2. 未结束 job 的输入引用和当前 attempt 的待交付上传均保护底层对象，不因普通保留时间到达而物理删除。输入保留至少延长至引用任务终态后 24 小时；成功输出保留从最终发布起算 7 天。未知执行仍算活动引用。
3. 业务删除只允许本逻辑 Key 创建的素材/产物，显式共享只赋予按策略读取的范围，不赋予删除他人原件。Admin 删除需要 content:delete，原始输入下载另需 content:sensitive。活动引用返回 409，不先隐藏再强行删除。逻辑删除立即阻止后续读取，返回 202；任务历史和计量不删除。
4. ObjectRecord 保留明确删除申请、回收 claim/fence 和物理删除完成时间。回收器先在短 PG 事务复查全部活动引用、到期/剩余可见引用并领取对象，随后在事务外删除私有对象的精确版本；成功后仅凭同一 claim 回写 deleted_at。网络失败或回执丢失可重试同一版本，不能删桶、目录、其他版本或更改任务结果。
5. 回收器以独立原生 Runner 进程运行，有界批量与退避，避免对象存储故障阻塞任务租约扫描；多副本使用 SKIP LOCKED 和持久 claim。启动仍检查 S3 私有性与版本控制。备份元数据、对象版本和加密主密钥须协调恢复，不能只恢复 PG 后立刻重新派单。

Admin 内容页分别查看产物和输入元数据，显示创建 Key、任务、规格、到期与删除状态；不把内网存储路径、桶凭证或完整提示词混入普通列表。用户选择下载或删除时才读取对应接口，避免自动加载大量媒体。长期元数据清理、对象存储实际容量和供应商兼容性仍是独立验收项。
