# 01 · 需求规格与约束

状态：开发设计基线 v0.4；已纳入 10～20 台设备、Sub2API 优先、异步、首版可视化 Admin，以及由 Admin 管理的多业务 API Key 与独立访问限制。开发强制规则、工程契约和任务出口见 [09](./09-开发总纲与强制约束.md)～[16](./16-开发任务分解与交付清单.md)。

## 1. 服务定义

本项目把一组不同硬件配置的 Windows ComfyUI 设备组织成可交付图片、视频、音频的生成服务。客户提交标准化的文本、素材与生成参数，获得任务标识，查询进度，并从云端下载最终产物。音频同样来自 ComfyUI Workflow，已纳入正式交付范围；共享既有调度、Admin、Key 和内容体系，实施约束见 [54](./54-ComfyUI音频产物范围与开发约束.md)。

云端负责身份、任务、调度、资产、计量、交付和可视化 Admin；Windows 负责受控工作流的本地执行。模型推理在 Windows GPU 上完成，云端控制服务器无需 GPU。

“设备兼容”表示节点可以登记、探测、执行适配能力、回报状态和维护退出；不表示所有节点都能执行所有模型。CPU 卸载、低显存量化和高显存原版工作流应作为不同运行配置测试，不能按显卡名称推断性能相同。

## 2. 角色与主要路径

| 角色 | 操作 |
| --- | --- |
| API 客户 | 查看可用模型、上传素材、提交任务、查询/取消、下载/删除产物、查看用量 |
| 管理员 | 登录 Admin，管理账号、多业务 API Key、内容授权、渠道地址/凭证、配置与审计，执行受控管理操作 |
| 运营人员 | 在 Admin 查看全局/渠道队列、任务与失败原因；停发能力；处理异常任务与费用调整 |
| 工作流维护者 | 在 Admin 导入/编辑草稿、同步工作流和模型清单、冻结版本/参数/样本、发布与回滚 |
| 节点维护者 | 在 Admin 管理渠道接入、注册/探测、维护/排空、受控升级 Worker，定位 ComfyUI 故障 |
| 只读观察者 | 按授权查看总览、渠道、能力、队列和脱敏任务详情，不可修改配置或操作任务 |
| Sub2API | 外部身份和账户入口，执行已约定的路由、配额、价格与账单逻辑 |

客户路径：发现能力 → 上传素材 → 校验与报价 → 提交并获得 ID → 排队 → 生成 → 上传验证 → 下载。生成结束但文件未交付时仍属于处理中。

维护路径：暂停节点接新任务 → 等待执行结束或明确取消 → 更新依赖 → 探测与基准生成 → 恢复调度。

## 3. 能力范围

| 编号 | 能力 | 输入 | 必须输出 | 主要限制 |
| --- | --- | --- | --- | --- |
| CAP-01 | 文生图 `text_to_image` | 文本、尺寸、质量档 | 单张有效图片及实际尺寸 | 尺寸/质量只能使用已测试档位 |
| CAP-02 | 图生图 `image_to_image` | 文本、1 张原图、可选受控强度 | 单张有效图片 | 区分重绘与局部蒙版编辑；蒙版需单独声明支持 |
| CAP-03 | 多参考图与文本生图 `references_to_image` | 文本、2～R 张参考图及有序角色 | 单张有效图片 | 保留所有参考图顺序与角色；不能悄悄只用首图 |
| CAP-04 | 文生视频 `text_to_video` | 文本、尺寸档、时长档 | 可播放视频、预览图、媒体元数据 | 帧率、时长、是否有音频均应明确 |
| CAP-05 | 多参考图与文本生视频 `references_to_video` | 文本、2～R 张参考图及有序角色 | 可播放视频及元数据 | 必须实际支持多参考语义；首尾帧能力单独标注 |
| CAP-06 | ComfyUI Workflow 音频生成 | 已发布 Workflow 声明的文本/素材/受控参数 | 可播放音频、时长/格式/采样率/声道及授权下载 | 任务标识、输入和格式随音频契约冻结；同样需要版本验证、配额和真实产物验收 |

`R` 为每个已发布模型的能力上限，不预设所有模型相同。建议产品首版以支持 2～4 张参考图为选型目标，实际支持数通过清单公布。若没有可用工作流支持其中某项，该项应标记未就绪并继续选型，不能宣称已交付完整范围。

单图生视频、首尾帧视频可在 CAP-05 的模型中作为额外输入模式发布，但不能用它们替代多参考图视频。视频配音、口型同步、连续长片、在线训练、用户上传 LoRA、任意工作流执行作为后续独立扩展评估。

首版建议每个任务产出 1 张图、1 条视频或 1 条音频；批量请求需独立设计子任务、部分失败和计费，未发布时 `n > 1` 明确拒绝。

## 4. 功能要求

### 4.1 接入与能力发现

| 编号 | 要求 |
| --- | --- |
| API-01 | Bearer Key 鉴权，明确客户、租户、API Key 及其权限范围 |
| API-02 | 提供模型列表和项目扩展能力详情，公布输入模式、参考图数、尺寸/时长、输出格式和可用状态 |
| API-03 | 图片生成/编辑尽可能使用 OpenAI 的端点、字段和错误外形；异步扩展单独标注 |
| API-04 | 长任务立即返回任务 ID；查询、取消、产物获取均不依赖原始连接 |
| API-05 | 优先完成 Sub2API 适配；New API 保留独立适配接口，不作为首阶段前置依赖 |
| API-06 | 参数错误、权限错误、能力不支持在消耗 GPU 前拒绝，并返回具体字段和原因 |
| API-07 | 标识全链路请求 ID；同一幂等键的重试关联同一业务任务 |

能力发现需区分“存在但暂停”“版本已下线”“目前无节点可执行”“队列暂满”。不能把暂时离线直接解释为模型不存在。

### 4.2 任务与队列

| 编号 | 要求 |
| --- | --- |
| JOB-01 | 在返回接收成功前，持久化规范请求、调用者、工作流/价格版本及任务状态 |
| JOB-02 | 按能力、模型、资源画像匹配节点；支持 10～20 台设备登记、心跳和调度 |
| JOB-03 | 支持租户公平排队、优先级权限、队列上限和最大排队时长 |
| JOB-04 | 区分排队等待、素材准备、执行、产物收集、上传验证；分阶段设超时 |
| JOB-05 | 通过数据库状态和 Worker 执行日志恢复；不把 ComfyUI WebSocket 当作唯一记录 |
| JOB-06 | 明确重试分类、最大次数、退避和跨设备重试限制 |
| JOB-07 | 取消是可查询的状态变化；收到取消请求不等于 GPU 已停止 |
| JOB-08 | 客户端断开不自动取消已接收任务；Worker 失联不立即判定原执行已停止 |
| JOB-09 | 只有一个执行尝试能提交最终交付与成功结算；旧租约结果隔离 |
| JOB-10 | 服务重启、网络分区、回传失败、重复上报均有可验证的处理流程 |

客户只看到预计等待区间。异构 GPU、维护、模型加载和视频长任务都会改变排队顺序，不承诺严格全局位置或精确完成时间。

### 4.3 节点管理

| 编号 | 要求 |
| --- | --- |
| NODE-01 | 登记 `node_id`、物理 GPU 标识、实例端点、硬件、内存、磁盘、版本与允许执行的能力 |
| NODE-02 | 首次接入、重启或依赖变更后进行探测；未通过探测不得接生产任务 |
| NODE-03 | 心跳回报 Worker、ComfyUI、GPU、运行任务、输出积压和版本摘要 |
| NODE-04 | 单 GPU 默认 1 个生成槽位；共享同一 GPU 的多个 ComfyUI 实例共享资源锁 |
| NODE-05 | 支持 ready、busy、suspect、offline、draining、quarantined、disabled 等状态 |
| NODE-06 | 支持排空、维护、禁用、恢复；连续 OOM 或产物错误触发隔离而不是无限重启 |
| NODE-07 | Worker 独立原生运行并有本地持久日志；不改变现有 ComfyUI 环境以解决业务依赖 |
| NODE-08 | 禁止生产实例被人工混用提交任务；人工操作需排空或使用隔离 GPU 资源 |
| NODE-09 | 通过 Admin 管理节点下的 ComfyUI 渠道、地址、认证引用与配置版本；同 GPU 多渠道共享资源锁，Worker 确认配置并探测通过后才生效 |

“在线”只说明通信可达。“可调度”还要满足模型、节点版本、显存画像、磁盘空间、运行时健康和租约一致。

### 4.4 数据与交付

| 编号 | 要求 |
| --- | --- |
| DATA-01 | 输入素材先登记为租户资产，完成类型、大小、解码与归属校验，再进入执行队列 |
| DATA-02 | Worker 仅获得当前任务所需素材和上传授权，不持有整个存储桶的管理密钥 |
| DATA-03 | 保存输出大小、SHA-256、MIME、图片尺寸或视频时长/帧率/编码与音轨信息 |
| DATA-04 | 上传成功且验证通过后，原子提交产物清单和任务成功状态 |
| DATA-05 | 默认私有对象存储；按 Key 策略提供需鉴权的云端代理下载，或显式允许的短时签名 URL；签名过期可鉴权刷新，撤销不能追回已签发 URL |
| DATA-06 | 视频下载支持 HEAD、Range 和断点续传；检查代理或重定向后的行为 |
| DATA-07 | 上传中断、回执丢失时可恢复上传或核查已有对象，不默认重新生成 |
| DATA-08 | 明确保留期、客户删除、失败残留、本地缓存与云端孤儿对象的清理规则 |
| DATA-09 | 删除和过期不回写历史任务为生成失败；资产生命周期与任务终态分别记录 |
| DATA-10 | 结果在云端管理存储交付；不向客户返回内网地址或 Windows 文件路径 |

“回到云端”建议解释为上传到云端对象存储，由云端统一鉴权和管理。若强制所有文件经过控制服务器本地磁盘，需要额外验收磁盘、带宽、备份和服务可用性。

### 4.5 计量与结算

| 编号 | 要求 |
| --- | --- |
| BILL-01 | 冻结价格版本和规格；区分平台资源成本与客户应付金额 |
| BILL-02 | 接收时预留额度；成功交付时结算；失败、取消、到期按明文策略释放或退款 |
| BILL-03 | 重复回调、重试、重复查询、文件再次下载不能重复扣生成费 |
| BILL-04 | 结算依据为图片数量、像素/质量档、视频输出秒数/分辨率档等真实单位 |
| BILL-05 | 不伪造 OpenAI token 用量；缺少原生 token 统计时省略并提供项目计量明细 |
| BILL-06 | Sub2API 与任务服务只允许一个客户余额账本；内部算力计量不重复扣客户款 |
| BILL-07 | 客户停止轮询也必须完成或释放结算；后台负责对账 |

建议默认业务规则：首版单产物任务仅在可交付成功时收费；生成失败、无法回传、取消成功均不收生成费，平台记录实际资源成本。下载链接自然过期可以刷新，不退款；客户主动删除已交付成果不触发自动退款。后续改变规则需版本化。

### 4.6 运维与可观测性

首版必须提供可登录、可实际操作的中文 Web Admin，以及配套管理 API 和结构化日志。界面必须覆盖任务检索、租户配额、全局/各渠道队列与等待时间、节点能力、GPU 占用、模型加载/执行/上传耗时、失败分类、存储容量和结算异常。不得以仅有 API、静态页面或人工编辑配置替代可视化后台交付。

日志关联 `request_id → public_task_id → job_id → attempt_id → node_id → prompt_id → artifact_id`。密钥、完整签名链接、客户原图和完整提示词默认不进入日志；排障采样需限定访问和保留期。

### 4.7 首版可视化 Admin

下列项目全部属于首版必需范围，页面、对象关系、队列口径与交互详见 [Admin 专项设计](./07-Admin可视化管理后台.md)。

| 编号 | 要求 |
| --- | --- |
| ADMIN-01 | 提供中文 Web Admin 的登录/退出、管理员/维护者/只读权限；客户 Key、Worker 凭证和管理会话隔离 |
| ADMIN-02 | 在界面新增、编辑、禁用、排空、恢复、删除 Windows/ComfyUI 渠道登记；管理名称、地址/端口、节点/GPU、认证引用和运行策略 |
| ADMIN-03 | 从绑定 Worker 视角测试连接与探测环境，显示在线、可调度、维护、失联及配置待生效状态；有活动执行时受控应用新地址/凭证 |
| ADMIN-04 | 导入 API-format Workflow/发布包、编辑草稿和参数绑定、创建版本、验证、发布、停用和回滚；已有任务固定原版本 |
| ADMIN-05 | 支持从授权渠道目录/清单导入 Workflow、向目标渠道同步冻结版本、查看差异及逐渠道结果；依赖缺失/冲突不得自动显示为可执行 |
| ADMIN-06 | 管理底层模型文件登记和渠道安装清单，显示哈希/版本/依赖/缺失状态；管理对外模型别名、规格与 Workflow/渠道绑定及 Sub2API 映射 |
| ADMIN-07 | 实时展示全局排队、退避等待、已分配、生成、回传、核对/取消中任务；支持模型/Workflow/租户/状态/时间筛选、分页和等待时长 |
| ADMIN-08 | 展示每渠道的共享候选、已分配待执行、当前执行、回传/核对，以及实际 ComfyUI pending/running；共享候选不能相加充当全局排队数 |
| ADMIN-09 | 任务详情显示冻结版本、执行尝试、渠道/GPU、真实阶段、错误、产物和结算；提供受权限约束的取消、终态重试及待分配优先级调整 |
| ADMIN-10 | 页面自动更新并显示采样/更新时间，断线重连并恢复快照；过期观测标未知，无法估计的进度/等待不伪造数值 |
| ADMIN-11 | 写操作具备权限、幂等、配置版本冲突检查和审计；删除保留历史引用，批量操作显示影响范围与逐项结果 |
| ADMIN-12 | 配置和操作状态持久化，服务重启后可恢复；20 Worker/渠道、500 个未完成任务下验收实时界面、分页与受控资源使用 |

这里的“渠道”是本项目登记的 ComfyUI 执行接入实例；一个 Windows 节点可有多个渠道。模型文件、Workflow 发布版本和客户选择的公开模型是不同管理对象。后台由本项目交付，Sub2API 继续承担客户账户与账本职责。

### 4.8 首版多 API Key 与内容访问控制

用户确认：Key 用于对外生成及内容 API，Admin 通过独立管理会话创建和管理 Key。以下均是首版必需项，细则见 [API Key 专项设计](./08-APIKey鉴权与访问控制.md)。

| 编号 | 要求 |
| --- | --- |
| KEY-01 | Admin 可创建多个独立业务 Key，命名/标用途、编辑、停用/恢复、撤销、轮换和归档；秘密值仅创建/轮换成功时显示一次 |
| KEY-02 | 对外生成、任务、素材及内容 API 使用 Bearer Key 鉴权；业务 Key、Admin 会话、网关与 Worker 身份隔离，业务 Key 无管理权限 |
| KEY-03 | 每 Key 配置操作 scopes、公开模型、Workflow/版本、允许渠道及尺寸/时长等规格上限；所有兼容/原生入口统一检查，路由限制传入调度 |
| KEY-04 | 记录租户、项目与逻辑 owner_key_id；独立 Key 默认只能访问自身内容，支持管理员显式授权同租户项目共享或指定 Key 内容范围 |
| KEY-05 | 分别配置请求频率/突发、每日新任务、未完成任务、生成并发、图片/视频资源额度；准入原子预留，幂等/内部重试不重复占用 |
| KEY-06 | 支持有效期、IP/CIDR 白名单和最新策略检查；权限收紧/停用/撤销后不继续使用旧缓存放行；无凭证不匿名降级 |
| KEY-07 | 轮换凭证保留稳定 key_id、内容归属、幂等范围和用量；停用可恢复、撤销不可恢复，不因轮换重置额度 |
| KEY-08 | 提供按项目/创建 Key/模型/Workflow/标签/时间筛选的内容目录与调用/用量记录；列表、计数、详情、敏感字段与审计均执行权限过滤 |
| KEY-09 | 提供 authenticated_proxy 与显式 signed_url 下载策略；GET/HEAD/Range、预览、Base64 返回和签名刷新执行对应内容权限，清楚展示撤销边界 |
| KEY-10 | Sub2API Key 由网关验证，项目保留 issuer/外部引用与可信本地主体映射；不按共享网关 Key 混合客户归属，不另建第二客户余额账本 |
| KEY-11 | Key 停用/到期默认不取消已接收任务；Admin 可显式阻止待执行或按状态机取消，任务回传/核对/结算能继续收尾 |
| KEY-12 | Key、摘要凭证、策略版本、额度和审计持久化；并发修改/重复操作受版本与幂等约束，服务恢复不丢用量或意外放开权限 |

首版内容管理对象是任务、输入素材和生成产物。标签用于检索，不作为授权依据；新增 Key 不默认继承其他 Key 的历史内容。内容发布站点等独立 CMS 功能后续单独扩展。

## 5. 权限与输入约束

- 客户可访问的任务和资产必须同时满足租户与 Key/项目授权范围；猜测 ID 不获得存在性信息。
- Sub2API 转发的租户身份必须来自可信服务身份或签名声明，剥离客户自行提交的同名头。
- 网络互通不能替代 Worker 身份认证；一个节点只可更新自身有效租约中的执行记录。
- 管理员登录、配置/任务操作和实时订阅都要做服务端鉴权；地址与凭证可在授权范围管理，密钥不明文回填，不向普通客户开放管理 API。
- 业务 Key 只保存不可还原的校验摘要；其创建、轮换、授权和使用记录均可审计。租户/项目/Key 归属来自服务端认证，不能信任客户自行声明的 owner 或身份头。
- 首版只接受文件上传、已归属资产或已验证数据；外部 URL 导入若开放，应阻断私网/元数据地址、重定向绕过和 DNS 重绑定，并限制解码尺寸和总流量。
- 只允许白名单工作流、模型、LoRA 和输出格式；API 不接受可执行脚本、任意磁盘路径、节点安装或模型下载指令。
- 保留模型、权重、插件、字体等发布依赖的用途许可记录，作为对外发布包的一项资料。

## 6. 建议默认值

下表是开发起点，不代表用户已确认这些数值，也不代表当前硬件已实测达标。能力清单可收紧通用上限。

| 配置 | 建议初值 | 约束说明 |
| --- | --- | --- |
| 设备规模 | 设计/协议至少 20 节点 | 实际 GPU 数和能力分布待盘点 |
| 单 GPU 生成并发 | 1 | 经专项测量后才能放宽 |
| 每租户未完成任务 | 20 | 包括排队、执行、重试、回传；不是 20 个 GPU 并发 |
| 全局未完成任务上限 | 500 | 还需按预计 GPU 秒数限流，防止长视频挤满队列 |
| 租户执行额度 | 默认最多 2 个生成槽位 | 内部可配；视频权重另计，需保留公平性 |
| 心跳 / 可疑阈值 / 租约 | 5 秒 / 15 秒 / 60 秒 | 租约过期不等于可以安全重跑 |
| Admin 实时更新 / 降级轮询 | SSE 失效通知后刷新一致快照 / 5 秒轮询 | 正常联网且 Worker 正常时，状态变化至页面更新目标 P95 不超过 10 秒；不在前端累加状态 delta |
| Admin 观测过期阈值 | 15 秒 | 标记最后观测过期/未知，不能把失联队列显示为零 |
| Admin 任务列表分页 | 默认 50、最多 100 条 | 后台过滤和游标分页，历史事件有长度上限 |
| 新建 Key 权限/额度 | 最小权限，显式选资源并显示继承的项目上限 | 空权限不解释为全开；每 Key 可收紧，显式不限额仍受平台/租户上限约束 |
| Key 内容下载模式 | authenticated_proxy | signed_url 需管理员显式允许；SDK 下载能力按真实客户端验收 |
| Key 轮换 / 每日任务账期 | 默认立即失效旧凭证 / Asia/Taipei 自然日 | 可显式配置短重叠窗口，逻辑归属和用量不重置 |
| 图片 / 视频排队到期 | 15 分钟 / 60 分钟 | 队列总预算和对外承诺需基准测试调整 |
| 执行尝试 | 最多 2 次 | 仅适用于证明确认可重试的失败 |
| 失联对账观察窗 | 初值 5 分钟 | 到期进入人工/隔离处置，不能据此假定旧 GPU 已停 |
| 提示词 | 1～8,000 Unicode 字符 | 不静默截断；与具体工作流限制取更小值 |
| 图片素材 | 单张最多 20 MiB、解码最多 25 MP | 文件字节和解码尺寸都检查 |
| 素材格式 | PNG、JPEG、WebP 静态图 | 首版拒绝 SVG、动画与无法安全解码文件 |
| 多参考图 | 选型目标 2～4 张 | 实际按能力声明；有序且逐张赋角色 |
| 图片单任务 / 视频单任务 | `n=1` / 1 条 | 其余批量规则未发布时拒绝 |
| 任务 JSON 大小 | 1 MiB | 上传素材走独立资产接口；含 data URL 的兼容入口另设 128 MiB 总体上限 |
| 生成图片编码大小 | 最多 32 MiB | 若使用原版 Sub2API 异步转存，需核对其下载大小配置 |
| multipart 编辑请求总大小 | 128 MiB | 图数上限、单图与解码限制仍分别生效 |
| 单条视频产物上限 | 2 GiB | 准入前依据规格估算；超限列为规格/编码异常 |
| 下载签名有效期 | 15 分钟 | 长下载按对象存储行为测试；可以重新签发 |
| 输入保留期 | 最后关联任务终态后 24 小时 | 仍被其他活动任务引用时不得清理 |
| 输出保留期 | 任务成功完成后 8 小时 | 用户已确定；图片/视频/音频统一，向客户返回真实 expires_at，到期由 GC 回收 |
| 任务元数据保留期 | 终态后 30 天 | 成果过期后仍可查询状态；账单保留期另定 |
| 幂等记录保留期 | 至少 7 天且覆盖全部活动任务 | 请求哈希、主任务标识一起保留 |
| Worker 本地产物保留 | 云端确认后至少 1 小时 | 云端未确认时保留，按配额暂停接单并告警 |

执行超时必须按工作流和硬件档位设定，建议从实测 P99 加余量确定，不统一设“视频最多 30 分钟”。未配置最大执行预算的能力不得公开接单。

## 7. 非功能目标与待测边界

- 元数据类提交/查询：目标 P95 小于 1 秒；只对已上传就绪素材、无 GPU 等待、无大文件传输的 API 操作统计。
- 调度：有空闲匹配节点时，目标 P95 在 5 秒内发出租约；不包含下载/模型加载时间。
- 节点规模：协议和故障测试覆盖 20 个 Worker；真实机器验收与模拟验收分开出证据。
- 可视化管理：首版通过浏览器完成渠道、Workflow、模型、实时队列和任务操作；20 Worker/渠道、500 个未完成任务、3 个查看会话作为初始管理面验收负载。
- 持久性：数据库进程/服务重启不丢已确认任务；云端整机灾难的 RPO/RTO 由备份策略单独约定。
- 可用性：单台云主机是已知单点；若要合同化 99.9% 等指标，必须增加冗余并重新评估部署范围。
- 吞吐量：按具体能力、硬件、热/冷启动和上行带宽测量；目前不能承诺每分钟出图或视频时长。
