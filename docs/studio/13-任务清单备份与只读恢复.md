# 13 · 任务清单备份与恢复

对应F-15、F-17、F-33、F-34。作品ZIP保存画布和文件；任务清单单独保存原提交的正文、幂等键、发布摘要、身份摘要及最后确认的任务编号。两者用途不同，需要分别备份。任务清单不包含图片、视频、音频、GLB原件、上传缓存或连接配置，也不延长云端八小时有效期。

## 冻结格式

JSON封装使用`format=comfy-studio-task-journal`、独立格式版本、原始payload字符串及其SHA-256。普通清单仍为`version=1`，含批次关联时为`version=2`；新版本读取两者，v1拒绝批次字段，旧客户端应拒绝v2文件。批次关联是不可变提交的一部分，详细约束见[批次方案](15-批量创作与部分失败恢复.md)。payload包含导出时间、单个原服务/Key指纹和全部该身份的任务记录。记录保留原始body字符串，不重新序列化请求，不修改client_request_id、幂等键、发布摘要和原project/node编号。身份只含profile ID、源站和Key指纹，不读取业务Key或管理Cookie。

SHA用于检查意外损坏，不是签名或授权依据。提示词按原文保留，可能含用户主动输入的私人信息；备份应由用户妥善保管，不公开上传。模型参数是历史快照，查询产物仍由原服务鉴权，不能相信备份自报权限。

## 导出与导入

1. 任务页允许导出当前连接的清单；已保存连接的身份信息足以离线导出，不需要读取保存的Key。跨身份记录不混入同一文件。
2. 导入须连接原服务及原Key。先读取文件、校验封装/payload/hash、全部结构与版本、原身份、原请求关联、编号唯一性、任务状态和产物编号，再展示全部记录及有/无job ID的数量。未知版本、损坏、重复或凭证字段拒绝导入。
3. 用户确认后，在同一个严格IndexedDB事务中检查现有记录、原幂等键及活动节点冲突，只新增不存在的记录；同ID的原提交完全一致时保留本机版本，不覆盖较新的状态。任一冲突、并发冲突或写入失败使整批中止。提交完成才提示成功。
4. 恢复记录明确标记来自备份，并暂停自动查询；不恢复画布节点/连线、上传操作或调度计时。备份中的状态和updated_revision不构成服务端证明，UI统一显示待核对。用户主动查询已知job ID后才使用服务端状态；首次真实查询可覆盖备份中虚高的版本号，随后恢复原来的单调版本/终态保护。确认前禁止取消和读取产物。任务清单不会覆盖现有画布，作品ZIP仍按离线副本方式导入。
5. 尚无job ID的备份保留原证据，但禁止通过它补发生成。使用原服务历史核对；仅凭旧幂等键或“历史没查到”不能证明从未执行。不自动改Key、换模型、补传素材或构造新任务。该限制不改变原浏览器已有意图的恢复行为。
6. 导入后不自动发起任何业务请求；同页面及其他页面只收到本机记录更新通知。身份切换、已有记录变化和空间不足在最终事务中再次防护。文件解析与错误提示不执行脚本或打开备份中的URL。

此方案不新增文件大小、重试、超时或并发限额，不改变任务、上传或产物TTL。备份读取在浏览器内存中完成；浏览器无法读取或写入时保留原文件和现有数据库。WebDAV、未知提交的服务端只读精确查证以及完整灾难恢复仍分别验收。

数据库升至版本3，保留版本1/2的仓库、文档、文件及索引。升级用于阻止旧版页面忽略新增的“备份恢复”标记后补发生成：旧版本客户端会收到VersionError，必须载入新界面。恢复标记纳入不可变提交快照，后续状态更新不能移除该保护。不能静态回退后清空数据库规避版本保护。
