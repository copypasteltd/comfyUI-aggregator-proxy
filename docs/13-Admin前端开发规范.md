# 13 · Admin 前端开发规范

当前网关目录界面实现与验证见 [81](./81-Admin网关目录映射与发布核对.md)。模型维护者/观察者从模型页选择仅含 id/name/enabled 的网关选项，不因只读目录取得凭证管理权限；十进制 ID、定点价格、编辑基线与未知写请求保护沿用强约束。

首版是中文可操作的 Web Admin，需求与数据口径见 [07](./07-Admin可视化管理后台.md)，API Key 行为见 [08](./08-APIKey鉴权与访问控制.md)。本文规定前端工程、交互状态和服务端约束；当前实现与未完成出口见 [17](./17-开发记录与运行说明.md)，不能将下表的必交范围当成全部已验收。

## 1. 页面与路由

| 路由 | 必交内容 | 服务端能力 |
| --- | --- | --- |
| `/admin/login` | 独立账号登录、错误/限流、会话过期恢复 | session 创建；无注册/默认万能密码 |
| `/admin/overview` | 全局互斥状态、可调度 GPU、未知占用、告警、数据新鲜度 | 一致队列快照；只显示授权范围 |
| `/admin/channels`、`/admin/channels/:id` | 新增/编辑地址、凭证引用、GPU/实例、探测、配置版本、排空与逻辑删除 | channels、probe、actions、inventory、operations |
| `/admin/workflows`、`/admin/workflows/:id` | API JSON 导入、参数/输出映射、草稿/冻结版本、依赖、双向同步与验证 | workflows、releases、syncs、validation |
| `/admin/models` | 文件清单/哈希、渠道依赖差异、公开别名/规格、网关同步状态 | model-artifacts、public-models、gateway binding |
| `/admin/queues`、`/admin/channels/:id/queue` | 全局去重排队、渠道共享候选/唯一分配、本机观测、阶段/年龄/筛选 | snapshot、jobs、channel queue；unknown 不显示 0 |
| `/admin/jobs/:id` | 脱敏详情、attempt 时间线、产物状态、核对/取消、关联重试、优先级 | 管理 jobs；敏感内容单独权限 |
| `/admin/operations` | 探测/应用/同步/验证逐项结果、重启恢复、部分失败 | operations、alerts；按目标分页 |
| `/admin/keys`、`/admin/keys/:id/access` | 创建/编辑策略、限额/有效期/IP、一次显示、轮换/撤销、用量/拒绝事件；当前策略用抽屉，访问记录为独立页 | api-keys、usage、access-events；记录归属、保留与页面取消见文档 28 |
| `/admin/content`、`/admin/content/:id` | 按项目/创建 Key/标签检索、预览/下载/删除、保留期 | 管理内容端点，沿源授权 |
| `/admin/audit`、`/admin/users` | 审计、管理账号、角色与授权上限 | audit-events、admin-users |

只读角色通过直达 URL 也不能编辑；服务端仍复核。没有权限的导航隐藏，缺省页显示授权错误，不获取完整数据后在浏览器过滤。

## 2. 前端分层与数据流

建议 `src/{app,router,api,features,components,stores,composables}`；features 按 channels/workflows/queues/jobs/apiKeys/content 等组织。api/generated 为 OpenAPI 类型和客户端，api/http 处理 CSRF、错误、请求 ID、超时和取消；组件不得直接拼接未约束 fetch 或保存重复领域状态。

Pinia 保存当前管理身份、权限摘要、全局筛选和实时连接状态。列表/详情缓存以用户/租户/筛选/revision 为键，默认最多 10 个页面、每页最多 100 条；退出清空。日志尾部最多保留 500 条，超过后分页查询；前端不无限追加任务/事件/预览。页面卸载通过 AbortController 取消请求，过期响应不能覆盖较新的筛选或 revision。

一致快照只覆盖同次读取的统计和首屏；后续游标页按稳定排序取当前可见数据，不承诺跨多次HTTP请求维持数据库事务。实时筛选列表变化时显示新数据提示并重置分页；不在翻页期间保持长事务或将不同snapshot_id拼成一个精确历史快照。

表单以服务端 DTO/JSON Schema 的可编辑子集为基础，输入校验不是鉴权。提交成功后重新查询权威详情；pending 状态仅表示请求在途，不能提前把 desired 显示成 applied。关键业务 mutation 不做乐观成功提示。重复提交复用同一次 Idempotency-Key；用户明确开启新动作才换键。

## 3. 会话与秘密值

身份由 `GET /session` 读取，Cookie 由浏览器管理，业务 Key 和管理 session 不写 localStorage/sessionStorage/URL。CSRF token 仅内存保存并随会话更新；登录 POST 同样校验允许的 Origin，登出撤销服务端会话并关闭所有订阅/清空缓存。401 统一回登录并保留已解析的站内目标路径，重新登录清除查询串和 hash，不读取外部 redirect 参数；403 显示操作权限错误，不能在页面内无限重试。

API Key 创建/轮换的 secret 只保存在当前弹窗内存，显示一次、复制按钮由用户触发；不写 URL、历史、分析埋点、错误上报、全局状态持久层或截图附件。幂等重放若只有 key_id 没有 secret，显示“原秘密值不可再次读取，可重新轮换”，不能伪造第二份 Key。关闭弹窗即移除前端引用；页面不承诺能清除用户剪贴板。

渠道凭证表单区分“保留原值/替换/清除”，不能把 `******` 提交为真实新密码。详情只显示引用/指纹。业务 Key 策略保存需显示 inherited/selected/deny 的实际交集；空范围和显式 unlimited 分开，不能用空输入代表不限。修改多个字段一次原子保存，不用多个 PATCH 拼成不一致策略。

## 4. 配置、同步与危险动作

编辑携带最初读取的 ETag，409 冲突展示当前 revision 和差异，要求用户重新合并，不自动覆盖。渠道详情并列展示 desired/applied、最后探测、verified 环境摘要、draining 和阻塞任务。地址校验说明连接由绑定 Worker 视角执行，不把云端 127.0.0.1 当成 Windows 本机。

同步页面先选择 pull 来源或 push 的冻结发布包，再列目标渠道/依赖差异/模型缺失/是否需排空；操作 ID 可持久恢复。扫描成功、文件同步成功、验证通过、能力启用和公开发布必须显示为不同步骤，不能统一绿色“已同步可用”。模型文件不自动下载，缺失时列出人工准备需求。

删除渠道、覆盖绑定、公开下架、撤销 Key、批量取消等按文档 07 二次确认，列具体资源 ID/数量/作用范围和原因。该确认是产品交互，不要求开发协作者对每次可逆文档编辑另行审批。批量操作冻结用户选中的具体 ID，禁止翻页后误把“当前筛选”当成原选择；每项结果独立展示。

取消返回 202 后显示 cancel_requested，确认 GPU 已停才显示 cancelled。终态重试跳转新 job，保留 retry_of；reconciling 不提供强制重试按钮。Key 禁用说明默认不取消旧任务，另提供筛选关联队列并按状态取消的动作。signed_url 策略显示已签发 URL 的失效时点，不能宣称撤销后所有文件立即不可访问。

## 5. 实时刷新协议

每个可见浏览器标签最多一个 SSE 管理连接，由 composable 共享；使用 Cookie 的 EventSource，不在 URL 带 token。连接 open 后请求一致快照，在请求期间收到失效通知设置 dirty，响应落地后最多补拉一次。刷新有 300ms 合并与 1 秒最短间隔；繁忙时以最新快照覆盖，不累计前端状态 delta。

SSE 正常时每 5 秒做安全检查/刷新，故障退回 5 秒轮询；同一页面不并发运行两套轮询器。网络失败指数退避 1/2/4/8/15 秒并加抖动，达到上限后保持提示；503 与429遵守服务端适用的 Retry-After。游标断层、过期、权限变更和恢复可见都重取快照。隐藏页关闭连接、定时器和未完成读取，恢复后先查当前 session。

每张卡显示服务端快照时间；节点观测还显示其 received_at/age/stale。15 秒观测过期显示“未知（最后一次…）”，不展示为实时零。全局 queued 与渠道 shared_candidates 分列并解释可重叠，不绘制相加后的虚假总量。进度 null 用阶段文本，整体 100% 只用于 succeeded。

## 6. 可用性与验收

桌面首要覆盖 1366×768 及以上，窄屏可横向表格滚动；关键操作可键盘访问，状态不只靠颜色。空状态、加载、401/403、409、429、断线、部分失败和历史对象归档都有明确反馈。界面面向运维决策展示渠道/任务事实，不暴露内部 SQL、堆栈或秘密。

浏览器 E2E 必须从界面创建渠道、配置 Key、发布/同步 Workflow、观察队列并完成授权业务 HTTP 调用，不能靠测试预先手改数据库伪装可操作。截图/trace 使用合成素材并脱敏；资源清理由 finally 关闭本次 page/context/browser。完整门禁见 [14](./14-测试策略与质量门禁.md) 与原 ADMIN/KEY 测试集。

## 队列筛选与刷新约束增量

[47](./47-队列筛选与实时负载验收.md) 冻结公共筛选栏和刷新行为：草稿表单只有显式应用才改变轮询；租户/项目变更清理不兼容子条件，按名称分页拉取的选项只含安全 value/label。最多缓存两页选项；隐藏、卸载时中止选项请求。切筛选/分页中止旧列表请求并清除不匹配快照；同条件读取失败保留最后成功数据并提示错误。

总览使用 SSE 失效通知和 5 秒轮询，任务页 5 秒轮询。共用刷新模块处理合并、取消和旧结果防覆盖；隐藏页关闭 SSE、定时器与在途读取，恢复先校验会话，退出清理。后端时间为 UTC 秒，日期组件按本地时区输入转换；界面明确结束时间不含，不展示预测 ETA。桌面和 390px 页面检查通过。

## 内容目录与媒体释放增量

[48](./48-内容检索标签与受控预览.md) 使用独立内容筛选栏：父范围变化清空不兼容子条件，选项按名称/50 条分页、最多缓存两页；草稿显式应用才改变目录，切条件/分页中止旧读取，页隐藏或卸载中止列表、详情和选项，恢复先验证会话。显示服务端生命周期与查询时间，不把本地时钟推断作为可用证明。

标签表单最多 16 项，规范化为 NFC 并检查长度、控制字符和重复；保存携带当前版本及固定请求体对应的幂等键。提交已成功而响应丢失时复用同键重试，409 保留草稿并要求显式重新加载/核对；不自动覆盖另一个管理员的版本。

只在主动预览后设置固定同源 src；图片不预下载，视频 controls/preload=none/不自动播放，不使用内存 Blob 保存媒体。关闭、切换条目、隐藏、退出及 before-unmount 暂停视频、移除 src、调用 load 释放；图片节点同步卸载。恢复可见不自动重新加载媒体。权限不足隐藏对应标签保存和敏感输入预览/下载控件；后端每次独立校验。390px 允许表格自身滚动，页面不横向溢出。

## 音频范围的工程约束

音频必须进入现有 Workflow/模型/渠道、队列、任务、内容与 Key 页面。内容提供受控音频预览/播放、元数据和下载；切页、抽屉关闭或卸载时停止播放、撤销对象 URL、取消无用请求。音频新增交互需桌面/手机真实浏览器验证，所有测试 page/context/browser 仍必须 finally 关闭。当前音频本地实现已通过 12 组桌面/手机业务与 Admin 检查，实际 Workflow/设备仍待验收；分层证据见 [55](./55-音频契约与兼容迁移.md)，完整出口见 [54](./54-ComfyUI音频产物范围与开发约束.md)。

## 第 62 增量：管理会话空闲与交互

第 62 增量统一由根组件管理会话交互和截止。仅可信 pointerdown/keydown/wheel 可续期，30 秒合并且单请求；不读取输入内容。隐藏/注销/卸载取消请求及计时器，恢复和到期只读复核。过期或无法确认有效性时关闭敏感界面；旧请求不能恢复已退出会话。实现与时序验收见 [62](./62-管理会话空闲超时与交互续期.md)。

## 第 63 增量：管理审计保留

审计页并发读取列表和保留状态，各自更新成功/失败结果，不等待另一个结果才渲染；共享一次刷新取消边界和 10 秒总预算，不新增自动轮询。隐藏/离页/退出取消请求及定时器，旧响应不能覆盖恢复后的策略，状态失败标记上次成功时间。见 [63](./63-管理审计保留与有界清理.md)。


## 第 64 增量：渠道检索与详情直达

渠道检索草稿显式应用，条件/分页切换中止旧读取，详情使用仅含公开 ID 的站内路由。列表与选项及现场观测独立读取，10 秒预算、隐藏/注销/返回和旧响应隔离纳入浏览器验证；见 [64](./64-渠道检索与详情直达.md)。


## 第 65 增量：渠道删除保护

删除前查询有界阻断观测，DELETE 仍在 Node/GPU/Channel 锁内检查当前任务、未关闭尝试、在途命令、已发布模型和物理 GPU 占用/管理保留。图形入口列出公开 ID 和处理入口，失败不自动重试或释放资源。冻结契约与验证边界见 [65](./65-渠道删除约束与并发保护.md)。


## 第 66 增量：管理指令核对

完成结果与未知执行分开处理，过期/旧 boot 的已完成指令只关闭旧操作并要求重验证，未知不释放占用、不重跑；Admin 显示状态并允许明确重应用当前渠道配置。事务、兼容、预算与验证边界见 [66](./66-管理指令持久结果与恢复核对.md)。


## 第 70 增量补充

模型目录每页 50，搜索/项目/能力/发布状态明确应用交集筛选。新选择器按需读取、250ms 防抖、十秒总预算、每页 50、最多 100 个映射渠道；已选项按每批 50 精确核对，父资源变化清理下级，隐藏/注销/离页停止请求。已有映射的当前规格可以保留，换版本必须重新选择。未知写入原键原正文核对，不能自动新建请求或提升 revision。详见 [70](./70-模型目录分页与冻结规格选择.md)。


## 第 71 增量补充

Key 生成资源目录每页 50、最多 1000 个已选项；250ms 搜索防抖、十秒读取/写入预算，项目切换清理指定值，未知或跨项目项须明确处理。精确解析结果覆盖缓存标签；所选失效项保留移除入口。暂停时卸载选择器并取消请求，恢复先核对会话；保留原请求核对不自动提高 revision 或重复轮换。 详见 [71](./71-Key生成资源授权选择与请求核对.md)。


## 第 72 增量补充

Workflow 目录每页 50、最多 100 个同步渠道分两批精确核对；列表/草稿/目录/写入及文件读取均十秒本地预算。未知写入保留原请求，不自动提高 CAS revision。 详见 [72](./72-Workflow检索与分页同步选择.md)。


## 第 73 增量补充

历史与差异各每页 50；只读权限统一，十秒预算与取消/迟到隔离、上次成功结果标记、草稿 revision 变更重置第一页、会话核对及 Blob URL 释放已验证。 详见 [73](./73-Workflow发布历史与版本差异.md)。


## 第 74 增量补充

Workflow 元数据表单与完整 JSON 分开暂存，未应用修改/过期表单不自动覆盖；观察者只读但可分页。表单、导入、请求重放和导出使用精确数值 JSON；禁用普通 JSON.stringify 序列化工作流数字包装值。10 MiB/100000 值/64 层、原型键隔离及确认框随页面释放已验证。 详见 [74](./74-Workflow参数与元数据表单.md)。


## 第 75 增量补充

恢复确认面板显示冻结版本 → 草稿 revision；选择阶段不写服务器。确认时冻结正文、键及 If-Match。响应丢失保留原请求供明确核对，不能自动更新 revision、换键或盲目重试。未知结果期间可只读查看当前草稿并浏览历史；禁用第二次恢复。成功提示“原恢复事务已确认”，当前内容须重新读取。关闭/隐藏/离页/注销清理未确认面板，恢复可见后先核对 session；同一请求只渲染一个核对区域。 详见 [75](./75-Workflow历史版本恢复草稿.md)。


## 第 76 增量补充

状态确认只保存本地选择，确认后冻结原正文/键/revision。归档行只读并禁用新增变更；未知响应提供原请求核对及只读查看，不自动换键或 revision。成功提示仅指原事务，当前状态从目录刷新；新提交清除上次成功提示，409 不保留旧成功投影。关闭/隐藏/离页/注销清理未确认状态框，恢复可见先核对 session；业务 Key 不进入管理通道。 详见 [76](./76-Workflow归档与恢复管理.md)。
