# 122 · RTX 5070 纯 HTTP 接入与调用验证

2026-10-28（Asia/Taipei）。用户授权将指定 5070 ComfyUI 加入线上平台、适配模型/Workflow 并完成真实业务调用；随后明确该设备没有 Windows-MCP，要求不做主机核验，直接根据 ComfyUI 信息构建。遵循此指令，新增明确 opt-in 的 HTTP Worker 模式，不要求在该 Windows 上安装程序或取得 shell。

## 变更设计与约束

1. 独立原生 HTTP Worker 部署到现有 Linux 服务器，持有自己的节点身份、journal、spool、进程锁及 systemd 服务。ComfyUI 仍在远端 Windows；不用 Docker、WSL、虚拟机、远程 shell、节点安装或模型下载。
2. 复用 PostgreSQL 调度、单 GPU 槽、配额、提交前 journal、未知执行核对、fencing、异步任务及内容上传协议。HTTP Worker 通过 /prompt 提交、/history 和 /queue 核对、/view 下载原文件；提交不确定时不盲目重提，不将失联视为 GPU 空闲。
3. LocalChannel 明确 connection_mode=remote_http，必须没有 comfy_root，并启用 allow_api_only。原 local 模式仍要求本地根及原 Git/文件哈希核验；禁止自动降级。HTTP 模式只使用固定本地配置的 ComfyUI origin，不跟随重定向或系统代理。
4. 新依赖声明 mode=comfy-api-only-v1，只记录实际 API 观察到的 ComfyUI 版本、节点类和所用模型选项。它不含伪造的 ComfyUI commit、模型 SHA-256、文件大小或自定义节点提交。原本地依赖声明不变；新旧声明不能互相代用。
5. 依赖同步回执分别表示 environment_verified=false、api_profile_verified=true 和 API 声明摘要；控制面只对同一 API 模式声明接受这种回执，原本地环境继续要求 environment_verified=true。API 结构同步、实际生成批准和主机文件核验是不同证据。
6. HTTP Worker 的容量只代表服务器 spool/内存，明确标记 scope=worker_spool；远端磁盘余量未观测，不伪称健康。GPU 名称/显存来自 system_stats，资源键由固定配置登记，不冒称 NVIDIA 硬件 UUID；同一物理 GPU 的多个 HTTP 入口须人工绑定同一资源键。
7. 生成成功且 prompt 已停止后，下载完整最终文件。严格限制 type、相对 subfolder/filename、固定 /view、数量、字节及时间；已有部分副本只有逐字节匹配当前源前缀才续写，绝不截断或覆盖未知副本。下载 flush/fsync、重新读取 SHA-256 后才保存包并上传，媒体规格仍由云端核验。
8. 01 ComfyUI 原文件仍保留；[121](121-ComfyUI原始产物移交即清理设计.md) 尚是设计，不随本接入偷偷启用删除。02 在本模式位于云服务器 HTTP Worker spool，仍在 complete 确认后至少保留一小时；03 正式对象仍在任务成功后八小时到期。
9. 工作流按实际图和可用模型整理，清除测试图中的原业务提示与私有参考文件。仅发布完成真实生成和独立业务 API 调用的受控规格；未支持的图像模型、缺失节点/权重、视频文件输入、结构化长片等保留待办，不以导出成功当成可调用。
10. 变更涉及 DEV-05/07～11/14/18～21/23/25～27/29～32。先验证原本地模式回归、HTTP 下载安全/恢复和本地/HTTP 依赖隔离，再构建不可变发行与原生部署。保持当前 HTTP 高位入口、任意来源 CORS 和已修复的 Admin 静态版本；不做 HTTPS 验证。

## 接入预检

从控制机与云服务器均可访问目标 ComfyUI；实际 system_stats 为 ComfyUI 0.33.1、PyTorch 2.13.0+cu130、RTX 5070、约 12 GB 显存，预检队列为空。读取 78 个 UI Workflow，经实际前端只读转换得到 75 个 API 图，3 个未能解析；只读转换阻止非 GET/HEAD/OPTIONS 请求，浏览器在 finally 中关闭。

当前 API 的 checkpoint 选项为空；UNet 有 3 个 H3 选项，CLIP 有 2 个、LoRA 有 4 个，VAE 包含视频/音频模型。此处是 API 目录观察，不是模型文件完整性或全部 Workflow 的运行证明。下方单独记录三个精选包的实际生成和业务调用结果。

## 工作流筛选边界

78 份源文件中，75 份能经前端转换为 API 图，3 份解析失败。按最终 SaveVideo 反向追踪、节点/必填输入及模型枚举初筛，37 份进入结构候选；38 份导出图被排除。排除原因可重叠：缺模型 15、没有本次支持的最终保存链路 22、依赖外部音视频文件 11、枚举不匹配 5。ComfyMathExpression 的动态 values.a 输入按实际展开方式识别，不误报缺少 values。

结构候选大量是相同 H3 载荷的长片/分镜变体。此次只整理文生视频、首帧生视频、双参考图生视频三个独立调用包；其他候选保持未导入、未发布。裁掉无关和未连接节点，清除源提示词/标题/私有参考路径，只绑定平台允许的提示词、seed、参考资产、尺寸及输出前缀。首轮冻结规格为 512×288、39 帧/24 fps（1.625 秒），用短任务验证完整交付链路，不能据此声称长片、高清或视觉质量已验收。

## 原生部署与接入步骤

1. 在 Admin 创建独立 Worker 身份，凭证只保存到 Linux 私密文件，业务 Key 不复用为 Worker 身份。
2. 使用 app/deploy/native-linux 的 http-worker.json.example、comfy-aggregator-http-worker.service 和 http-worker.nginx.conf.example。配置固定 ComfyUI origin、逻辑 GPU 资源键及 allow_api_only=true；原生 Python 3.13 运行 windows_worker.main。模板中的文档保留地址必须替换为实际地址。
3. loopback 39446 仅代理 /internal/ 到本机控制 API，Host 与 public_origin 一致。该端口不对外开放；公网业务继续使用原 HTTP 39443 和任意来源 CORS。Worker 服务不启用独立 PrivateTmp，以便同一服务账号共享进程锁；不同账号仍须严格隔离 Worker 凭证，不能把逻辑键宣称为硬件 UUID。
4. 注册 GPU 后在 Admin 创建该节点的渠道，应用配置、执行渠道探测，再同步选定发布包，核对 API-only 回执。需要时显式扫描节点目录；不凭空登记权重 SHA-256 或模型文件大小。
5. 每个候选创建少量验证任务，串行占用同一 GPU。只有平台收到并验证最终媒体、任务成功，才批准 runtime profile 和公开模型映射。独立业务调用再核对幂等、内容权限、SHA-256、HEAD、Range 与到期时间。
6. 服务账号为 comfy-http-worker，journal/spool 位于 /var/lib/comfyui-aggregator/http-worker；凭证和配置在 /etc/comfyui-aggregator，0600 且由该账号持有。代码位于不可变 Linux 发行，systemd 开机启动。原 Windows Worker 继续使用自己的本地依赖模式。
