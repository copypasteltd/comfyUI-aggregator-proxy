# 43 · Sub2API 原生跨进程联调

本增量推进 [16](./16-开发任务分解与交付清单.md) 中 WP-05/06/11/13 的完整协议链路。已有组件、账本和服务器编译证据不能代替服务器实际启动。本节先冻结测试边界和运行约束，最终结果以本节后续记录及可核验报告为准。

## 1. 运行范围

在 `app/` 构建并启动固定 Sub2API 实际 `cmd/server` 二进制、真实控制面 API、真实 Windows Worker，以及用于测试的 ComfyUI 协议服务。使用原生 Windows 进程与本项目 PostgreSQL，不调用 Docker、WSL 或虚拟机。

Redis 暂使用已锁定的 miniredis v2.38.0 原生进程，覆盖实际上游认证/缓存/pubsub 调用，但它是协议测试服务，不是生产 Redis 验收。ComfyUI 服务只按已冻结的合成 API 图生成预置媒体回执；它不运行 GPU 或证明工作流质量。对象服务使用受环境约束的回环本地私有存储，不算真实 S3。Sub2API 后端监听回环 HTTP，控制面及交付访问使用本项目证书验证的 HTTPS；公网反向代理及真实部署另行验收。

目标覆盖五类原生任务、图片同步/异步和编辑、素材/产物读取、视频任务、当前 Key 撤销与跨 Key 隔离、唯一预留/终态结算/用量与缓存消费、重启后的任务查询。实际通过的子项逐项记录，不能从一个成功样例推断五类能力或所有入口通过。

## 2. 隔离与迁移

- 每次创建独立控制面测试库和 `render_sub2api_test_<12位小写十六进制>` 上游测试库。拒绝 `render_control`、`render_control_test`、postgres 和其他非本次创建的数据库；同时核对服务器为 `127.0.0.1:55438`。
- 使用项目统一迁移 advisory lock。每个空库在任何 DDL 前执行原生 `pg_dump` 并验证 `pg_restore --list`，记录归档摘要；随后分别执行现有 Alembic 和固定上游迁移，重复核对版本/摘要。
- 合成租户、Key、分组、账号、Workflow、运行画像和对象仅写入本次随机测试库，控制面强制 `environment=test`。不向正在开发的客户目录发布合成模型，不改本地现有 ComfyUI。
- 每次凭证、加密密钥和缓存密码随机生成，保存在本次 app 私有目录；日志及报告不得包含原 Key、数据库密码、完整图或输入正文。依赖按现有锁和缓存使用，不启用 Go 在线自动下载。
- 测试辅助命令仅允许迁移、写入本次合成 fixture、启动有口令的回环 Redis 协议服务等固定动作；不接受任意 SQL/shell、任意监听地址或生产数据库。

## 3. 证据与清理

报告记录固定上游 commit/归档与维护源码摘要、实际二进制摘要、服务启动与 HTTP 结果、两边数据库的任务/账本/计数、已通过和未通过场景，以及协议服务边界。HTTP 成功不能替代数据库唯一记账或当前授权验证。

所有测试进程使用独立工作目录、固定可执行文件、禁止 shell 的参数数组、有界启动/请求/运行时间和本次拥有的进程组或 Windows Job Object。结束在 finally 中停止整个本次进程树，再删除本次随机数据库和暂存媒体；只保留脱敏证据与可恢复的源码/构建产物。不得结束已有 API/Runner/GC/PG 或用户进程。若使用浏览器，同样在 finally 关闭本次创建的上下文。

本轮不改公开 API、任务状态机或货币规则。若联调暴露真实缺陷，先补充约束与失败证据，再同步修正、匹配风险的回归及文档。完整首版仍需真实 Redis、ComfyUI、五类工作流样本、私有 S3、混合供应商额度与 10/20 台实机出口。

## 3. Windows 启动与清理约束

实际启动暴露固定 stock 二进制在本机缺少 IANA 时区数据库，加载默认 `Asia/Shanghai` 时退出。Provider 的现有包内加入 Go 标准库 `time/tzdata`，随同二进制携带时区数据；不要求安装系统包、不修改机器时区、不增加第三处上游源码补丁。重建后必须重新启动实际服务器验证，编译成功本身不作为修复完成。

Git 在 Windows 将对象文件标记为只读。合成协议目录的清理只能在核对本次创建的绝对路径后解除这些文件的只读属性并删除；媒体清理失败必须记录并返回失败，同时仍执行数据库释放和报告落盘。历史失败保留于 [失败记录](./evidence/2026-10-23/sub2api-native-failure-notes.json)，不能覆盖为成功记录。`inet_server_addr()::text` 包含地址掩码，数据库身份校验使用 `host(inet_server_addr())`，仍严格限制回环地址和 55438 端口。

## 4. 网关稳定身份与凭证轮换

实际跨进程测试发现：控制面的 `GatewayService.id` 与 `credential_identifier` 本就独立，Admin 轮换只更新后者；原 Go 客户端却从凭证前缀推导 `GatewayID()`，导致准入查询的服务身份不匹配，任务停在 `admission_pending`。这是本轮必须修复的协议实现缺陷。

Go 客户端的配置必须显式给出稳定 `GatewayID`，即 Admin 返回的 `gateway.id`，并独立验证其公开 ID 格式。托管 Provider 的 `gateways[].id` 传入该字段；服务目标、准入证明、账本与恢复记录始终绑定此 ID。凭证只用于认证，不从其前缀推导业务身份，也不要求两个 ID 相等。缺少稳定 ID 时初始化失败，不退回旧推导。现有 Provider JSON 格式和数据库结构不变。

回归必须覆盖服务 ID 与凭证 ID 不同、凭证轮换后新旧客户端仍绑定同一服务、响应中其他服务 ID 不能授权关闭/退款，以及实际控制面的完整准入和结算。合成身份应遵循与 Admin 相同的 `issuer=gateway:<服务 UUID>` 约束，不能修改生产鉴权来迎合测试夹具。
